---
title: host.files
description: Persist and reopen macOS file bookmarks with a scoped access lifetime.
---

`host.files` stores access to a user-selected file or folder across launches. It manages bookmarks and access handles; read and write file contents in server code while the handle remains open.

How-to: [Security-scoped file bookmarks](/ui/platform-services#security-scoped-file-bookmarks-macos).

## Methods

### `createBookmark(path)`

Create an opaque bookmark for a path the app can already access.

```ts
const { bookmark } = await host.files.createBookmark('/Users/me/Documents/Reports');
```

| Parameter | Type | Description |
| --- | --- | --- |
| `path` | `string` | Absolute file or directory path. macOS expands `~` before checking it. |

Resolves `{ bookmark: string }`, a base64-encoded bookmark suitable for persistent storage. Rejects with `invalid_args` for a non-absolute path, or `unavailable` if the bookmark cannot be created, on Linux because the file doesn't exist. Creating a bookmark cannot grant new sandbox access.

On Windows, a bookmark is the path and the file's NTFS id, read with `GetFileInformationByHandleEx`. A volume with no lasting ids, FAT for instance, gets one with the path alone.

### `openBookmark(bookmark)`

Resolve a saved bookmark and hold its file access until released.

```ts
const access = await host.files.openBookmark(bookmark);
try {
  // Complete the operation that needs access.path here.
} finally {
  await access.release();
}
```

| Parameter | Type | Description |
| --- | --- | --- |
| `bookmark` | `string` | Opaque string from `createBookmark()` or an open dialog with `securityScoped: true`. |

Resolves `BookmarkAccess`:

| Member | Type | Description |
| --- | --- | --- |
| `path` | `string` | Resolved current filesystem path. |
| `stale` | `boolean` | Recreate and persist the bookmark while this access remains open. |
| `release()` | `Promise<void>` | Release this handle. Repeated calls share the successful release; a failed release can be retried. |

Each open acquires an independent handle, even for the same bookmark. Release each one in `finally`. In a sandbox this balances native `startAccessingSecurityScopedResource` and `stopAccessingSecurityScopedResource` calls.

Rejects with `invalid_args` for empty or invalid base64 data, `unavailable` if bookmark resolution fails or does not yield a file URL, and `denied` if scoped access cannot start. Well-formed base64 containing an invalid bookmark may fail during resolution with `unavailable`.

macOS and Linux. See [Linux](#linux) for how far a bookmark follows a file there.

## Sandbox access

In an App Sandbox build, including Mac App Store apps, these APIs create and resolve security-scoped bookmarks. The app still needs the appropriate user-selected file entitlements. Bookmarks do not bypass them.

Start with [`host.dialog.showOpenDialog({ securityScoped: true })`](/host/windows/dialog). Its `bookmarks` array aligns with `paths`; cancellation returns empty arrays. Bookmark creation failures reject the dialog call instead of returning incomplete grants.

Outside the sandbox, the same API creates and resolves ordinary bookmarks. No extra file access is required, but each returned handle should still be released. Keep access open for the entire native or server operation, including work in another context that uses the resolved path.

## Linux

Linux has no sandbox to get through, so a bookmark is the path with the file's device and inode, and `release()` has nothing to do. It follows a file less far than on macOS:

| What happened to the file | `path` | `stale` |
| --- | --- | --- |
| Nothing, or edited in place | The same | `false` |
| Renamed in its folder | The new name | `true` |
| Replaced by another file at that path (many apps save this way) | The same | `true` |
| Moved to another folder, or deleted | Rejects with `unavailable` | |

macOS finds a file that moved to another folder. Linux has no index to ask.

Windows finds it too, anywhere on its volume, through `OpenFileById`: it resolves the new path with `stale: true`, for a file or a folder. A move to another volume is a copy, which is a new file: it rejects with `unavailable`, or resolves what's now at the old path with `stale: true`. Replaced by another file at that path is the same as elsewhere.

## Platform support

| Method | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `createBookmark`, `openBookmark` | ✓ | partial | ✓ (NTFS) |
| `BookmarkAccess.release` | ✓ | ✓ | ✓ |

## Example

The first time, ask the user for a folder and save its bookmark in [`host.store`](/host/data/store), refreshing it if it is stale. This runs in a page or in server code; the flush makes sure the bookmark is written to disk before the app quits.

```ts
const selection = await host.dialog.showOpenDialog({
  directories: true,
  files: false,
  securityScoped: true,
});
if (!selection.canceled && selection.bookmarks?.[0]) {
  let bookmark = selection.bookmarks[0];
  const access = await host.files.openBookmark(bookmark);
  try {
    if (access.stale) {
      ({ bookmark } = await host.files.createBookmark(access.path));
    }
    host.store.set('reports-folder', bookmark);
    await host.store.flush();
  } finally {
    await access.release();
  }
}
```

On a later launch, open the saved bookmark and use the folder while the handle is open. This one runs in server code (for example a `+server.ts` endpoint or `src/hooks.server.ts`), because it reads the folder with `node:fs`:

```ts
import { readdir } from 'node:fs/promises';

const saved = host.store.get<string>('reports-folder');
if (saved) {
  const access = await host.files.openBookmark(saved);
  try {
    if (access.stale) {
      const { bookmark } = await host.files.createBookmark(access.path);
      host.store.set('reports-folder', bookmark);
    }
    console.log(await readdir(access.path));
  } finally {
    await access.release();
  }
}
```
