---
title: host.clipboard
description: Read and write clipboard text, rich text, images, file paths and multiple representations.
---

`host.clipboard` combines a reactive snapshot with clipboard operations. Single-format reads and writes work on all three platforms; macOS also supports publishing several representations together and reading arbitrary native types as bytes.

How-to: [Clipboard](/ui/platform-services#clipboard).

## Reactive state

| Property | Type | Description |
| --- | --- | --- |
| `text` | `string \| null` | Last text snapshot, initially `null`. Updated by `refresh`, `writeText`, `write` and `clear`. |
| `html` | `string \| null` | Last HTML snapshot, initially `null`. Updated by `refresh`, `readHtml`, `writeHtml`, `write` and `clear`. |
| `rtf` | `string \| null` | Last RTF snapshot, initially `null`. Updated by `refresh`, `readRtf`, `writeRtf`, `write` and `clear`. |
| `formats` | `string[]` | Last format snapshot, initially empty. Updated by `refresh`, `writeText`, `write` and `clear`. |
| `hasText` | `boolean` | Whether `formats` includes `'text/plain'`. |
| `ready` | `boolean` | Whether initial refresh completed. |
| `error` | `Error \| null` | Initialization failure, if any. |

There is no clipboard change subscription. Copies made in other apps do not update these fields automatically. `readText`, `read`, `availableFormats`, `has`, image methods and path reads query the service without refreshing the store. `writeHtml` and `writeRtf` update only their corresponding field; `writeText` updates only `text` and `formats`. Call `refresh()` when you need all four fields to reflect the current clipboard after a change.

## Methods

### `init()` and `refresh()`

Read text, format names, HTML and RTF into the store.

```ts
await host.clipboard.refresh();
console.log(host.clipboard.text, host.clipboard.hasText);
```

Both resolve to the store. `init()` also sets `ready: true` after a successful refresh and runs automatically when the platform connects. `refresh()` reads the four values in parallel; it does not provide an atomic snapshot across calls. HTML and RTF read failures become `null` during refresh; text and format read failures reject the operation.

### `readText()`

Read plain text without updating the reactive snapshot.

```ts
const text = await host.clipboard.readText();
```

Resolves `string | null`, with `null` when no plain text is available.

### `writeText(text)`

Replace clipboard contents with plain text and update `text` and `formats`.

```ts
await host.clipboard.writeText('Hello');
```

| Parameter | Type | Description |
| --- | --- | --- |
| `text` | `string` | Text to copy, including an empty string. |

Resolves `void`. A non-string value rejects with `invalid_args`.

### `readHtml()` and `readRtf()`

Read rich text and update its corresponding reactive field.

```ts
const html = await host.clipboard.readHtml();
const rtf = await host.clipboard.readRtf();
```

Each resolves `string | null`; absent or empty rich text returns `null`.

### `writeHtml(html)` and `writeRtf(rtf)`

Replace clipboard contents with rich text and update its corresponding reactive field.

```ts
await host.clipboard.writeHtml('<strong>Hello</strong>');
await host.clipboard.writeRtf('{\\rtf1 Hello}');
```

| Parameter | Type | Description |
| --- | --- | --- |
| `html` | `string` | HTML markup for `writeHtml`. Native backends also derive a plain-text representation. |
| `rtf` | `string` | RTF markup for `writeRtf`. |

Each resolves `void`. Non-string arguments reject with `invalid_args`. These calls replace earlier clipboard contents; use `write` on macOS to publish several representations together. The store's other fields remain unchanged until refreshed.

### `availableFormats()`

Read the names of available clipboard representations.

```ts
const formats = await host.clipboard.availableFormats();
```

Resolves `string[]`. Standard names are `'text/plain'`, `'text/html'`, `'text/rtf'`, `'image/png'` and `'files'`. macOS also reports `'image/tiff'` and custom native pasteboard types. Linux and Windows enumerate the standard formats above. Does not update the store's `formats` field.

### `has(format)`

Test one format without reading its data.

```ts
const canPasteImage = await host.clipboard.has('image/png');
```

| Parameter | Type | Description |
| --- | --- | --- |
| `format` | `'text/plain' \| 'image/png' \| 'files' \| string` | Standard format name or platform-native type name. |

Resolves `boolean`. macOS passes unknown names through as pasteboard UTIs, Linux as target names, and Windows as registered clipboard format names. A missing format rejects with `invalid_args`.

### `readImage()`

Read an image as base64-encoded PNG bytes.

```ts
const image = await host.clipboard.readImage();
```

Resolves `{ bytes: string; format: string } | null`; `format` is `'png'` and `bytes` has no data-URL prefix. macOS converts TIFF when PNG is absent; Windows can convert a DIB image; Linux uses the GTK image reader. No readable image returns `null`.

### `writeImage(pngBase64)`

Replace clipboard contents with an image.

```ts
await host.clipboard.writeImage(pngBase64);
```

| Parameter | Type | Description |
| --- | --- | --- |
| `pngBase64` | `string` | PNG bytes encoded as base64, without a data-URL prefix. |

Resolves `null`. Invalid base64 or undecodable image data rejects with `invalid_args`. This method does not refresh the reactive fields.

### `readPaths()`

Read copied file paths.

```ts
const paths = await host.clipboard.readPaths();
```

Resolves `string[] | null`, with `null` when there are no copied file paths. To copy file paths on macOS, use `write({ files })`; the public `host.clipboard` API has no `writePaths` method.

### `clear()`

Clear native clipboard contents and set the store's text, HTML and RTF to `null` and `formats` to `[]`.

```ts
await host.clipboard.clear();
```

Resolves `void`.

### `write(data)`

Publish several representations in one native clipboard write, then refresh the store.

```ts
const result = await host.clipboard.write({
  text: 'Hello', html: '<strong>Hello</strong>',
  formats: { 'com.example.note': btoa('note-v1') },
});
```

`data` is `ClipboardData`:

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `text` | `string` | Omitted | Plain text, encoded as UTF-8. |
| `html` | `string` | Omitted | HTML markup, encoded as UTF-8. No plain text is derived automatically by this method. |
| `rtf` | `string` | Omitted | RTF markup, encoded as UTF-8. |
| `image` | `string` | Omitted | Base64-encoded PNG image bytes. |
| `files` | `string[]` | `[]` | Absolute file paths. |
| `formats` | `Record<string, string>` | Omitted | Native UTI or standard format name mapped to base64 bytes. |

Resolves `{ changeCount: number; previousChangeCount: number }`. `previousChangeCount` is the native pasteboard counter observed on entry to the write; `changeCount` is its value after publication. They are observations of a shared clipboard, not a lock against other applications.

macOS only. All representations are prepared before replacing the clipboard and published together. Text and other representations accompany the first file URL; remaining file URLs use separate pasteboard items. At least one representation is required and combined decoded data, including file URL bytes, must fit within 16 MiB.

Rejects with `invalid_args` for non-string text fields, invalid base64 or image bytes, relative file paths, duplicate representations, invalid pasteboard types or data exceeding the limit. For example, supplying both `text` and `formats['text/plain']` duplicates one representation. A rejected native publication returns `unavailable`. After a successful native write, this wrapper refreshes its fields: a refresh failure can reject the promise even though publication already succeeded.

### `read(options)`

Read selected representations as base64 bytes from one pasteboard ownership version.

```ts
const copy = await host.clipboard.read({
  formats: ['text/plain', 'text/html', 'com.example.note'],
  maxBytes: 1024 * 1024,
});
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `formats` | `string[]` | Required | Up to 128 nonempty standard format names or native UTIs. Duplicate names are read once. |
| `maxBytes` | `number` | `16777216` | Maximum combined decoded result bytes; integer from `1` through `16777216` (16 MiB). |

Resolves `ClipboardRead`: `{ changeCount: number; formats: Record<string, string | null> }`. Each requested name maps to base64 bytes, or `null` when absent. Recognized standard names are `'text/plain'`, `'text/html'`, `'text/rtf'`, `'image/png'`, `'image/tiff'` and `'files'`. Other names pass through unchanged as native types. `'files'` reads the first file URL as UTF-8 bytes; use `readPaths()` for every path.

macOS only. Invalid arguments or a result exceeding `maxBytes` reject with `invalid_args`. If pasteboard ownership changes during the read, it rejects with `unavailable`; the caller can retry. This method does not refresh the reactive snapshot.

On Windows, clipboard operations that acquire the native clipboard can reject with `unavailable` when another process holds it open.

## Platform support

| Method | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `init`, `refresh` | ✓ | ✓ | ✓ |
| `readText`, `writeText`, `clear` | ✓ | ✓ | ✓ |
| `readHtml`, `writeHtml`, `readRtf`, `writeRtf` | ✓ | ✓ | ✓ |
| `availableFormats`, `has` | ✓ | ✓ | ✓ |
| `readImage`, `writeImage`, `readPaths` | ✓ | ✓ | ✓ |
| `write`, `read` | ✓ | — | — |

## Example

This macOS component copies a note as plain text, HTML and an application-specific representation, then reads that custom representation back.

```svelte
<script lang="ts">
  let copied = $state(false);
  let error = $state<string | null>(null);

  async function copyNote() {
    try {
      copied = false;
      error = null;
      await host.clipboard.write({
        text: 'Hello',
        html: '<strong>Hello</strong>',
        formats: { 'com.example.note': btoa(JSON.stringify({ version: 1, text: 'Hello' })) },
      });
      const snapshot = await host.clipboard.read({ formats: ['com.example.note'] });
      copied = snapshot.formats['com.example.note'] !== null;
    } catch (cause) {
      error = String(cause);
    }
  }
</script>

<button onclick={copyNote}>Copy note</button>
<p>{host.clipboard.hasText ? 'Text is in the clipboard snapshot.' : 'No text in the snapshot.'}</p>
{#if copied}<p>Note representation copied.</p>{/if}
{#if error}<p role="alert">{error}</p>{/if}
```
