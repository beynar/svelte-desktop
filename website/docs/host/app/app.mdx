---
title: host.app
description: Read app identity, control application and Dock behavior, and participate in the quit lifecycle.
---

`host.app` combines reactive app state with identity, lifecycle and Dock operations. On macOS and Linux, `onQuitRequested()` lets every page and the server protect unsaved work before any window is destroyed.

How-to: [App and Dock](/ui/platform-services#app-and-dock).

## Reactive state

| Property | Type | Description |
| --- | --- | --- |
| `info` | `AppInfo \| null` | App information loaded during initialization. |
| `name` | `string \| null` | `info.name`. |
| `version` | `string \| null` | `info.version`. |
| `packaged` | `boolean \| null` | Whether the app is packaged, from `info`. |
| `platform` | `string \| null` | Platform from `info`: `'darwin'`, `'linux'` or `'win32'` (unlike `host.system.os`, which says `'windows'`). |
| `active` | `boolean` | Starts `true`; macOS activation events keep it current. |
| `reopenCount` | `number` | Reopen events received; initially `0`. |
| `lastReopenedAt` | `number \| null` | Local Unix milliseconds of the last reopen event. |
| `quitting` | `boolean` | Set to `true` on `willQuit`; a quit request alone does not set it. |
| `restarting` | `boolean` | Set to `true` on `willRestart`. |
| `loginItem` | `LoginItem \| null` | Launch at login. See [`getLoginItem()`](#getloginitem). |
| `activationPolicy` | `ActivationPolicy \| null` | Dock presence. |
| `dockBadge` | `string \| null` | The badge text. |
| `dockIcon` | `IconSource \| null` | What `setDockIcon()` set. |
| `dockProgress` | `DockProgress \| null` | The Dock's progress bar. |
| `secondInstanceCount` | `number` | Second-instance launch attempts received; initially `0`. |
| `lastSecondInstance` | `{ argv: string[]; cwd: string } \| null` | Most recent second-instance arguments and working directory. |
| `ready` | `boolean` | Whether initialization completed. |
| `error` | `Error \| null` | Initialization failure, if any. |

`AppInfo` has `name: string`, `version: string`, `identifier: string`, `appPath: string | null`, `packaged: boolean`, `platform: string` and `arch: string`. `appPath` is `null` for an unpackaged app. Setters do not reload `info`; call `init()` to reload that snapshot after changing identity. `quitting` and `restarting` only record that the event fired; they don't mean the process has exited.

## Methods

### `whenReady()`, `getInfo()`, `getName()` and `getVersion()`

| Method | Resolves | Description |
| --- | --- | --- |
| `whenReady()` | `true` | The native app is ready. |
| `getInfo()` | `AppInfo` | Fresh identity and packaging information; does not replace `info`. |
| `getName()` | `string` | Current native app name. |
| `getVersion()` | `string` | Current app version. |

### `getPath(name)`

Resolve an OS or app-specific path. Resolves `string`; does not create the directory.

| Parameter | Type | Description |
| --- | --- | --- |
| `name` | `AppPathName` | `'home'`, `'appPath'`, `'exe'`, `'temp'`, `'appData'`, `'userData'`, `'logs'`, `'caches'`, `'documents'`, `'downloads'`, `'desktop'`, `'music'`, `'pictures'` or `'videos'`. |

`userData`, `logs` and `caches` are scoped by app identifier. `appData` is the OS application-data root; `appPath` is the bundle or executable directory. Rejects with `invalid_args` for an unknown path name. Server code also has startup-created [`host.paths`](/host/data/server) directories.

### `setName(name)` and `setIdentity(identifier, name?)`

Override the runtime app name or identifier. Both resolve `null`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `name` in `setName` | `string` | Required | Nonempty app name. |
| `identifier` in `setIdentity` | `string` | Required | Nonempty app identifier. |
| `name` in `setIdentity` | `string` | Omitted | Also override the name when supplied. |

Rejects with `invalid_args` for an empty required name or identifier. This changes runtime values, not the packaged app's manifest.

### `quit()`

Request normal application termination. Resolves `null` when the request is accepted, before the quit decision finishes, on macOS and Linux. A guard can still cancel it. See [Cancellable quit](#cancellable-quit).

```ts
await host.app.quit();
```

### `relaunch()`

Schedule a fresh copy after this process exits, emit `willRestart` and request quit. Resolves `null`; rejects with `internal` when the relaunch process cannot start. On macOS and Linux the quit coordinator still runs, so a guard can delay or cancel termination.

### `exit(code = 0)`

Exit the process immediately, bypassing quit guards and cleanup. `code` is a `number`, default `0`. The declared result is `Promise<never>`; it does not resolve.

### `hide()`, `show()`, `hideOthers()` and `showAll()`

All resolve `null`. `hide()` hides this app; `show()` unhides and activates it. On Linux and Windows these operate on the app's native windows. `hideOthers()` hides other applications; `showAll()` unhides all applications. On Linux, `showAll()` shows the app's own windows again, without activating them.

`hideOthers()` is macOS only: on X11 and Wayland, other applications' windows are the window manager's. `showAll()` is macOS and Linux.

### `addRecentDocument(path)`

Add a file to the OS recent-document list. `path` is a required nonempty `string`; resolves `null`. Rejects with `invalid_args` when the path is empty; on Linux, also when it isn't absolute. Linux adds it to the user's `recently-used.xbel` through `GtkRecentManager`.

### `clearRecentDocuments()`

Clear the app's recent documents; resolves `null`. That list is the user's on Linux, shared by every app: this removes the entries only this app added, and leaves those another app has opened too.

### `setDockBadge(text)`

Set the Dock badge on macOS, or the taskbar overlay on Windows. `text` is `string | null`; `null` clears it. Resolves `boolean` and mirrors the argument into `dockBadge`. Windows uses a generic overlay icon with the text as its description, rather than drawing arbitrary badge text. Linux sends the Unity LauncherEntry signal (Ubuntu dock, KDE, Plank…), which carries a number: other text shows nothing, clears the number and resolves `false`. It's the badge [`host.notifications.setBadge()`](/host/os/notifications) sets too.

```ts
await host.app.setDockBadge('3');
await host.app.setDockBadge(null);
```

The store records the accepted argument, not an independently queried native badge state.

### `getDockBadge()`

Resolves the badge text, or `null`. The reactive `dockBadge` gives the same without `await`. No dock can be asked on Linux: this is what the app set.

### `setDockIcon(icon)`

Replace the macOS Dock icon, or the icon of the app's windows on Linux (`_NET_WM_ICON`). `icon` is `IconSource | null`; resolves `null`. `null` restores the default icon. `IconSource` accepts a native icon name, an image path, `{ native: NativeIconName }` or `{ path: string }`; see [native menu icons](/host/input/menu). Rejects with `invalid_args` when the icon cannot be resolved or loaded.

On Linux a name can be one of the icon theme's, `null` restores the packaged app's icon, and a dock showing the app's `.desktop` icon doesn't change. macOS and Linux.

### `getDockIcon()`

Resolves what `setDockIcon()` set, or `null` with the bundle's icon. macOS and Linux.

### `bounceDock(type)`

Request attention through the Dock on macOS, taskbar flashing on Windows or the urgency hint of the app's window on Linux. Resolves `boolean`; Windows returns `false` if there is no primary window, Linux if no window is visible. On Linux, with one of the app's windows in front it does nothing, and otherwise the hint stays until the user comes to that window, `'informational'` as `'critical'`.

| Parameter | Type | Description |
| --- | --- | --- |
| `type` | `DockBounceType` | `'critical'` or `'informational'`. Critical requests continue until activation; informational requests are brief. |

### `setDockProgress(progress)`

Set Dock or taskbar progress. Resolves `null`.

| `DockProgress` field | Type | Default | Description |
| --- | --- | --- | --- |
| `status` | `DockProgressStatus` | Required | `'none'`, `'normal'`, `'indeterminate'`, `'paused'` or `'error'`. Use `'none'` to clear. |
| `completed` | `number` | `0` | Completed amount. |
| `total` | `number` | `1` | Total amount; the displayed fraction is clamped between 0 and 1. |

```ts
await host.app.setDockProgress({ status: 'normal', completed: 25, total: 100 });
```

Windows rejects with `unavailable` when no taskbar button is available. Linux sends the Unity LauncherEntry signal, and rejects with `unavailable` without a session bus. It has a fraction and no colors: `'paused'` and `'error'` look like `'normal'`, and `'indeterminate'` is a full bar, as macOS draws it.

`getDockProgress()` resolves the same object, `{ status: 'none' }` without progress.

### `getLoginItem()`

Launch at login: whether it's on, and whether this launch came from it. Resolves `LoginItem`:

| Field | Type | Description |
| --- | --- | --- |
| `available` | `boolean` | Whether this build can set it. `false` in `vite dev` and on macOS 12, where the other fields are `false` too. |
| `enabled` | `boolean` | The app launches at login. Reflects the system's settings: it's `false` once the user turned it off there. |
| `requiresApproval` | `boolean` | The user turned it off in the system's settings, and only they can turn it on again: show a link to [`host.system.openSettings('loginItems')`](/host/app/system#opensettingspane). macOS and Windows. |
| `launchedAtLogin` | `boolean` | This launch came from the login item. On Linux and Windows, an entry written by an earlier version of the app isn't recognized until `setLoginItem(true)` writes it again. |

It never rejects because the app isn't packaged, so a settings page runs the same in dev. `host.app.loginItem` gives the same object without `await`, reactive. It's `null` for a moment after the first read, and it's read again when the app comes back to the front, in case the user changed it in the system's settings:

```svelte
<label>
  <input
    type="checkbox"
    disabled={!host.app.loginItem?.available}
    checked={host.app.loginItem?.enabled}
    onchange={(e) => host.app.setLoginItem(e.currentTarget.checked)}
  />
  Launch at login
</label>
{#if host.app.loginItem?.requiresApproval}
  <button onclick={() => host.system.openSettings('loginItems')}>Allow in Settings</button>
{/if}
```

To start out of the way at login, create the main window hidden (`window: { visible: false }` in `desktop.config.ts`) and show it for the other launches:

```ts
const { launchedAtLogin } = await host.app.getLoginItem();
if (!launchedAtLogin) await host.window.show();
```

### `setLoginItem(enabled)`

Turn launch at login on or off. `enabled` is a required `boolean`; resolves `LoginItem`, the state after the call. Where it's not available (`vite dev`, macOS 12), it does nothing and resolves `available: false`. Uses `SMAppService` on macOS, an XDG autostart entry on Linux and the per-user Run registry key on Windows. macOS shows a notification the first time. macOS and Windows can reject with `denied`; Linux file-write failures reject with `internal`.

When the user turned it off in the system's settings, `setLoginItem(true)` doesn't turn it back on on macOS and Windows: it resolves `requiresApproval: true`.

### `setActivationPolicy(policy)`

Set `ActivationPolicy`, one of `'regular'`, `'accessory'` or `'prohibited'`. Resolves `boolean`: `false` if macOS refused the change. `'accessory'` hides the Dock icon; `'prohibited'` prevents activation. An unknown policy rejects with `invalid_args`.

On Linux, `'accessory'` sets the skip-taskbar and skip-pager hints on the app's windows, the later ones too. A dock showing running apps by their `.desktop` file may still list it. `'prohibited'` has no Linux meaning, since nothing stops an app from having windows: it resolves `false` and changes nothing. macOS and Linux.

### `getActivationPolicy()`

Resolves the current `ActivationPolicy`. Always `'regular'` on Windows.

### `requestSingleInstanceLock()`

Acquire the app's single-instance lock. Resolves `{ acquired: boolean }`. A later instance forwards its arguments and working directory to the holder as `secondInstance`; it should quit when `acquired` is `false`. Calling again in the holder returns `true`. Lock-creation failures on macOS and Linux reject with `internal`; Windows reports `acquired: false` if it cannot acquire the mutex.

### `getBundleType()` and `defaultWindowIcon()`

`getBundleType()` resolves `{ type: BundleType }`, where `BundleType` is `'app' | 'binary'`. `defaultWindowIcon()` resolves `{ pngBase64: string } | null` with the default icon as base64 PNG, or `null` if there is no available packaged icon.

`defaultWindowIcon()` is supported on macOS and Linux only.

### `aboutPanel(options = {})`

Show the platform About UI. Resolves `null`.

| `AboutPanelOptions` field | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `string` | Native app name | Display name. |
| `version` | `string` | Native app version | Display version. |
| `copyright` | `string` | Native default / omitted | Copyright text. |
| `credits` | `string` | Native default / omitted | Credits text; Linux uses the About dialog comments. |

### `metrics()`

Memory and CPU of the app's processes. Resolves `AppMetrics`: `{ processes, memory: { footprint } }`, where `memory.footprint` is the total in bytes. Each entry of `processes` is a `ProcessMetrics`:

| Field | Type | Description |
| --- | --- | --- |
| `pid` | `number` | Process id. |
| `type` | `'main' \| 'webview' \| 'python' \| 'helper' \| 'child'` | `main`: the shell (UI thread and the server's Worker). `webview`: a WebKit content process (a window's page, a kept-alive tab, a popover). `python`: the [Python](/native/plugins/python) process. `helper`: the app's own executable again (a service, a job). `child`: another process it started (a sidecar…). |
| `name` | `string` | Process name. |
| `windowId` | `number` | For a `webview`: the window whose page it draws. macOS: WebKitGTK doesn't say which web view a process draws. |
| `memory` | `{ footprint: number; resident: number }` | Bytes. `footprint` is the memory macOS counts for the process (Activity Monitor's Memory); on Linux, its private pages and swap in `/proc`, which add up across processes. |
| `cpu` | `{ time: number; percent: number \| null }` | CPU seconds so far, and the share of one core since the previous call (`null` the first time a process is seen). |

```ts
await host.app.metrics();                      // a first sample for the CPU shares
setInterval(async () => {
  const { processes, memory } = await host.app.metrics();
  console.log((memory.footprint / 2 ** 20).toFixed(0), 'MB', processes.map((p) => `${p.type} ${p.cpu.percent?.toFixed(1)}%`));
}, 2000);
```

On macOS, WebKit's networking and GPU processes are shared with the system and not counted. On Linux they're the app's own: `WebKitNetworkProcess` is listed as a `child`. macOS and Linux.

### `init()` and `dispose()`

`init()` reloads the `info` snapshot and resolves the namespace. The store calls it at startup; call it again after `setName()` or `setIdentity()`. `dispose()` removes the store's internal listeners, not yours or your quit guards.

## Cancellable quit

Register a guard in a page or server module. Return `'cancel'` to keep the app and all its windows alive, or `'quit'` to allow the attempt (see the [example](#example)). Each phase has a 10-second timeout, so a stuck guard can't block quitting.

On Windows there is no quit guard. To protect unsaved work there, guard the window instead with [`host.window.onCloseRequested()`](/host/windows/window): it stops the user closing the window, but not a quit from elsewhere (`host.app.quit()`, a signal).

Cmd+Q, Quit in the app or Dock menu, `host.app.quit()`, a termination signal, the last window closing when `quitOnLastWindowClosed` is enabled, and macOS logout/shutdown all enter the same native coordinator. On Linux, logging out reaches it as whatever signal the session sends: the reasons `'logout'`, `'shutdown'` and `'system'` don't occur. Repeated requests during an attempt join the active attempt rather than starting another vote.

### `onQuitRequested(callback)`

Register `(request: QuitRequest) => QuitDecision | Promise<QuitDecision>`. Every registered page and server guard participates. Any `'cancel'`, invalid decision or thrown guard error cancels the attempt. With no guards it proceeds.

### `onBeforeQuit(callback)`

Register `(request: QuitRequest) => void | Promise<void>`. Runs after every guard allows quit, while windows and the server still exist. It is awaited, but cannot veto.

### `onWillQuit(callback)`

Register `(request: QuitRequest) => void | Promise<void>`. Runs the final awaited cleanup phase after `beforeQuit` completes. It cannot veto. Errors in either cleanup phase are logged and do not cancel quit.

All three methods synchronously return an unsubscribe function. Explicit unsubscription removes any pending vote. A page that navigates or closes loses its subscriptions; if it disappears while its vote is pending, the attempt is cancelled instead of consenting to data loss. During cleanup, a disappearing participant no longer holds up the phase.

`QuitRequest` has these fields:

| Field | Type | Description |
| --- | --- | --- |
| `requestId` | `number` | Identity shared by all phases of this attempt. |
| `reason` | `QuitReason` | Why termination was requested; see below. |
| `deadline` | `number` | Unix milliseconds of this phase's native deadline. |

`QuitDecision` is `'quit' | 'cancel'`. `QuitReason` is:

| Reason | Source |
| --- | --- |
| `'api'` | API quit request, including the native shell quit entry point. |
| `'menu'` | App or Dock menu termination request. |
| `'lastWindowClosed'` | Last-window policy requests quit. |
| `'logout'` | macOS logout. |
| `'shutdown'` | macOS shutdown or restart. |
| `'system'` | Another external application-termination request. |
| `'signal'` | Termination signal handled by the native shell. |

The phases run in order: `quitRequested` → `beforeQuit` → `willQuit` → affirmative AppKit termination reply, or the end of the run loop on Linux. When a phase's 10-second deadline expires, unanswered participants are allowed to continue and `quitTimedOut` reports the phase. A stuck page or server cannot block quitting indefinitely. Force quit and `host.app.exit(code)` bypass these hooks.

Modal windows created with [`host.windows.create()`](/host/windows/windows) are hidden while the decision is made and restored if it is cancelled.

The separate server-only [`host.onBeforeQuit(fn)`](/host/data/server) remains a cleanup hook. On macOS it runs in the final `willQuit` phase, before AppKit's affirmative reply, including menu and system quits. Use `host.app.onQuitRequested()` for decisions and `host.app.onBeforeQuit()` for work requiring live windows.

Windows doesn't register the cancellable protocol (see above). Subscription registration errors are logged by these helpers rather than returned as rejected promises. Existing parameterless `onWillQuit()` listeners retain observational behavior there; their asynchronous work is not an awaited native phase.

## Events

| Event | Payload | Typed helper | Platforms |
| --- | --- | --- | --- |
| `reopened` | `{ hasVisibleWindows: boolean }` | `onReopen(fn)` | macOS |
| `openUrls` | `{ urls: string[] }` | `onOpenUrls(fn)` | All; also see [deep links](/host/app/deep-link). |
| `willRestart` | `{}` | `onWillRestart(fn)` | All |
| `secondInstance` | `{ argv: string[]; cwd: string }` | `onSecondInstance(fn)` | All |
| `appActivated` | `{}` | `onActivated(fn)` | macOS |
| `appDeactivated` | `{}` | `onDeactivated(fn)` | macOS |
| `quitRequested` | `QuitRequest` | `onQuitRequested(fn)` | macOS, Linux |
| `beforeQuit` | `QuitRequest` | `onBeforeQuit(fn)` | macOS, Linux |
| `willQuit` | `QuitRequest` on macOS and Linux; `{}` on Windows | `onWillQuit(fn)` | All; awaited on macOS and Linux. |
| `quitCancelled` | `{ requestId: number; reason: QuitReason }` | Use `host.on()` | macOS, Linux |
| `quitTimedOut` | `{ requestId: number; phase: 'quitRequested' \| 'beforeQuit' \| 'willQuit'; reason: QuitReason }` | Use `host.on()` | macOS, Linux |

Helpers on `host.app` return unsubscribe functions. `host.app.on(event, fn)` and `once(event, fn)` accept `reopened`, `willQuit`, `willRestart`, `secondInstance`, `appActivated` and `appDeactivated`; `once()` removes the listener after delivery. `host.on(event, fn)` observes any native event and also returns an unsubscribe function. Raw event listeners do not register quit votes or awaited cleanup; use the lifecycle helpers for those guarantees.

## Example

```svelte
<script lang="ts">
  let draft = $state('');
  let saved = $state('');

  $effect(() => {
    if (host.app.platform !== 'darwin') return;
    return host.app.onQuitRequested(async () => {
      if (draft === saved) return 'quit';
      const { response } = await host.dialog.showMessageBox({
        message: 'Discard unsaved changes?', buttons: ['Discard', 'Keep editing'],
      });
      return response === 0 ? 'quit' : 'cancel';
    });
  });
</script>

<h1>{host.app.name}</h1>
<textarea bind:value={draft}></textarea>
<button onclick={() => { saved = draft; }}>Mark draft saved</button>
<button onclick={() => host.app.quit()}>Quit</button>
```
