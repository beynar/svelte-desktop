---
title: host.window
description: Read the current window reactively and control its size, position, state, title bar and appearance.
---

`host.window` is the current window's reactive store with the window operations attached. To create, find or parent windows, see [`host.windows`](/host/windows/windows).

How-to: [Windows](/ui/windows).

```svelte
<script lang="ts">
  import { onMount } from 'svelte';

  // Ask before the user closes this window.
  onMount(async () => {
    const disarm = await host.window.onCloseRequested(() => {
      if (confirm('Discard changes?')) host.window.close();
    });
    return () => disarm();
  });
</script>

<header>
  <span>{host.window.title}</span>
  <button onclick={() => host.window.toggleMaximize()}>
    {host.window.maximized ? 'Restore size' : 'Maximize'}
  </button>
</header>
```

| `error` | `Error \| null` | `null` | Initialization failure, if any. |

The settings fields (from `alwaysOnTop` to `cursorHidden`) are read without `await`, and reactive:

```svelte
<button aria-pressed={host.window.alwaysOnTop} onclick={() => host.window.setAlwaysOnTop(!host.window.alwaysOnTop)}>Pin</button>
```

Each one is `null` until it's known, and stays `null` on a platform without its getter (see [platform support](#platform-support)). It's read the first time you use it, so a page pays for nothing it doesn't read. After `await host.window.setAlwaysOnTop(true)` it's up to date, and a setter called from another window or from server code reaches it a moment later. It's also read again when the app or the window comes back to the front. To get the value at this very moment, use the getter: `await host.window.isAlwaysOnTop()`.

Bounds, focus, scale, and fullscreen completion feed the store through native events. A page tracks its own window; server code uses the native default target. Some operations schedule a refresh after 150 ms to allow native geometry to settle. `refresh()` keeps previous scalar values when their queries fail; failed bounds, cursor, and controls queries become `null`.

## Store methods

`init()` refreshes the store, attaches its event subscriptions, sets `ready`, and resolves the namespace. The host calls it during startup. `refresh()` re-reads the native fields and resolves the namespace. `dispose()` synchronously removes the store's own subscriptions; it does not close the native window.

`host.window` also exposes every operation of the [`host.windows`](/host/windows/windows) service, so `host.window.hide()` and `host.windows.hide()` do the same. The store has its own version of the methods below: they target the current window, accept no trailing `windowId`, and resolve `void` rather than the service's result. Any other service method falls through unchanged, with its own signature, optional trailing `windowId` and return value: `host.window.hide(3)` hides window 3, and `host.window.getBounds()` returns the service result.

The table lists only the store's own versions; the service signatures are under [Window operations](#window-operations).

| Method | Parameters | Behavior |
| --- | --- | --- |
| `setTitle` | `title: string` | Set title and update `title`. |
| `setSize` | `width: number, height: number` | Set content size, then schedule a refresh of outer bounds. |
| `setPosition` | `x: number, y: number` | Set frame position and refresh. |
| `setBounds` | `x: number, y: number, width: number, height: number` | Set outer frame and refresh. |
| `center` | None | Center and refresh. |
| `positionTo` | `preset: WindowPositionPreset` | Apply a position preset and refresh. |
| `setFullscreen` | `fullscreen: boolean` | Request native fullscreen, update the field, then refresh. |
| `toggleFullscreen` | None | Toggle native fullscreen and update the field. |
| `setSimpleFullscreen` | `enabled: boolean` | Set macOS simple fullscreen and update the field. |
| `maximize`, `unmaximize`, `toggleMaximize` | None | Update `maximized` from the native reply and refresh. |
| `minimize` | None | Minimize the current window. |
| `restore` | None | Restore normal state and refresh. |
| `focus` | None | Request focus; `focused` changes only through native events. |
| `close` | None | Close and clear `live`. |

`host.window.focus()` and `host.windows.focus()` resolve the same value: `{ activated: boolean }` on macOS, `null` on Linux and Windows.

### `setCloseVeto(enabled)`

Arm or disarm interception of OS close requests. `enabled` is `boolean`. The store method resolves the `boolean` armed state; `host.windows.setCloseVeto(enabled, windowId?)` instead resolves `{ armed: boolean }`.

### `onCloseRequested(handler)`

Arm the veto and subscribe to `willClose`. `handler` has type `() => void`. Resolves an async disarm function of type `() => Promise<void>`; await it to disarm and unsubscribe. Arming failures reject and remove the subscription.

```ts
const disarm = await host.window.onCloseRequested(() => {
  // Ask the user, then call host.window.close() if they confirm.
});
// When this guard is no longer needed:
await disarm();
```

The veto is one native flag per window. Use one guard at a time; disarming one registration also drops the flag used by another. `close()` is a programmatic close and bypasses the veto. This helper subscribes to the event stream without filtering `windowId`; when several windows install guards, use [`host.windows.onWillClose()`](/host/windows/windows#events) and explicit IDs to filter requests yourself.

### Store event methods

`on(event, callback)` returns an unsubscribe function. `once(event, callback)` returns one too and unsubscribes after the first delivery. Both are synchronous and accept the store's typed event names:

| Event | Callback payload type |
| --- | --- |
| `boundsChanged` | `WindowBounds` |
| `willClose` | `Record<string, never>` |
| `focusChanged` | `{ focused: boolean }` |
| `scaleFactorChanged` | `{ scaleFactor: number }` |

The native payloads also carry window IDs, but these store callback types omit them. Use the service's typed helpers when you need IDs or completed transitions. `host.window.on()` is the store's method, so it does not accept the transition names supported by [`host.windows.on()`](/host/windows/windows#events).

## Window operations

Every method in this part is a service operation, available as `host.window.method(...)` for the current window. Pass a trailing `windowId?: number` (omitted from the signatures below) to target another window; it is also how `host.windows` calls them. With no ID, a page targets its own window; server calls resolve the active/key window, then the primary window. `0` addresses the primary window. Unknown target windows reject `invalid_args`. See [`host.windows`](/host/windows/windows#hostwindows) for IDs and labels.

Unless stated otherwise, setters and commands resolve `null`. Numeric coordinates use a top-left screen origin, with y increasing downward, in macOS points, Linux logical coordinates, or Windows DIPs.

### Geometry

`WindowBounds` is `{ x: number; y: number; width: number; height: number }`. Frame measurements include decorations; content measurements exclude them.

| Method, before optional `windowId` | Resolves | Description |
| --- | --- | --- |
| `getBounds()` | `{ bounds: WindowBounds; state: WindowStateName }` | Outer frame and state. |
| `setBounds(x: number, y: number, width: number, height: number)` | `null` | Set the outer frame. |
| `getSize()`, `getContentSize()`, `innerSize()` | `{ width: number; height: number }` | Content size. |
| `setSize(width: number, height: number)` | `null` | Set content size. |
| `outerSize()` | `{ width: number; height: number }` | Frame size. |
| `getPosition()`, `outerPosition()` | `{ x: number; y: number }` | Frame origin. |
| `innerPosition()` | `{ x: number; y: number }` | Content origin in screen coordinates. |
| `setPosition(x: number, y: number)` | `null` | Move the frame. |
| `center()` | `null` | Center on the screen/work area. |
| `positionTo(preset: WindowPositionPreset)` | `null` | Position relative to screen, tray, or cursor. |
| `setMinSize(width: number, height: number)` | `null` | Set minimum content size; `0, 0` clears the explicit constraint. |
| `setMaxSize(width: number, height: number)` | `null` | Set maximum content size; a `0` axis clears its constraint. |
| `getMinSize()`, `getMaxSize()` | `{ width: number; height: number }` | Content limits; `0` means unconstrained. |
| `setAspectRatio(ratio: number \| null)` | `null` | macOS content width/height ratio; `null` clears it. |
| `getAspectRatio()` | `number \| null` | That ratio; `null` when free. macOS. |
| `getScaleFactor()` | `number` | Display backing scale. |
| `getCursorPoint()` | `{ x: number; y: number }` | Cursor relative to the window content. |
| `setCursorPosition(x: number, y: number)` | `null` | Warp the OS cursor in screen coordinates. |
| `setCursorHidden(hidden: boolean)` | `null` | Hide or show the OS cursor. |
| `isCursorHidden()` | `boolean` | Whether the app hid it. |

`WindowPositionPreset` is `'center' | 'trayCenter' | 'trayLeft' | 'trayRight' | 'trayTop' | 'trayBottom' | 'cursorTopLeft' | 'cursorBottomLeft'`. Unknown presets reject `invalid_args`. Tray presets reject `unavailable` without a tray item on macOS/Windows; Linux cannot retrieve tray geometry and rejects `unavailable` for all tray presets.

For persistence, see [`host.windowState`](/host/windows/window-state).

### Visibility, focus, and window state

| Method, before optional `windowId` | Resolves | Description |
| --- | --- | --- |
| `show()`, `hide()` | `null` | Show or hide without destroying. |
| `minimize()`, `unminimize()` | `null` | Minimize or deminiaturize. |

| `maximize()`, `unmaximize()`, `toggleMaximize()` | `{ maximized: boolean }` | Change maximize/zoom state. |
| `isMaximized()` | `boolean` | Current maximize/zoom state. |
| `restore()` | `null` | Restore from minimized/maximized/native-fullscreen state. |
| `setFullscreen(fullscreen: boolean)`, `toggleFullscreen()` | `{ fullscreen: boolean }` | Request native fullscreen. |
| `isFullscreen()` | `boolean` | Native fullscreen observation. |
| `setSimpleFullscreen(enabled: boolean)` | `null` | macOS borderless screen-sized window without a dedicated Space. |
| `isSimpleFullscreen()` | `{ simpleFullscreen: boolean }` | macOS simple fullscreen state. |
| `focus()` | `{ activated: boolean } \| null` | Request focus and app activation. macOS returns the observed activation result; Linux and Windows return `null`. |
| `blur()` | `null` | Give up focus. |
| `isFocused()` | `boolean` | Keyboard focus. |
| `isActive()` | `boolean` | Active/key window (and app active on macOS). |
| `isHovered()` | `{ hovered: boolean }` | Pointer within the frame. |
| `isOccluded()` | `boolean` | macOS: no visible pixels; Linux/Windows only detect hidden/minimized/offscreen-like states, not full overlap by other windows. |
| `requestAttention()` | `null` | Dock bounce, urgency hint, or taskbar flash. |
| `setCloseVeto(enabled: boolean)` | `{ armed: boolean }` | Intercept OS close requests. |
| `hasCloseVeto()` | `boolean` | Whether close requests are intercepted. |
| `close()` | `null` | Programmatic close, bypassing the veto. |

On macOS, native fullscreen resolves before its animated transition finishes. Listen for `fullscreenChanged` to observe completion. Panels and modal children reject `unsupported` when asked to own a fullscreen Space. Simple fullscreen is a separate state; turn it off with `setSimpleFullscreen(false)`.

On macOS, `focus()` rejects `unavailable` for a nonfocusable window. A refused app activation instead resolves `{ activated: false }`; another foreground app may retain focus. Successful activation requests are not guarantees of focus.

On macOS, `'transparent'` extends content under the title bar but keeps the title. `'hidden'` hides the title; `'hiddenInset'` also insets traffic lights. The two z-order setters each choose a level; they are not independent flags. On macOS, disabling either returns the level to normal. Capture protection cannot always be reversed on macOS: disabling rejects `unsupported` if AppKit keeps the window protected. Windows uses capture exclusion, with a black-window fallback on older systems, and rejects `unavailable` if the native call fails.

### `setVibrancy(material, options?, windowId?)`

For a material behind one element rather than the whole window, declare it in CSS: `--desktop-material: sidebar` (see [Vibrancy and Liquid Glass](/ui/windows#in-css)).

Set native material behind transparent page areas, or pass `null` to remove it. Resolves `null`. macOS, and Windows 11 22H2 and later: older Windows rejects `unavailable`. See [Windows](/ui/windows#windows-materials) for what each name becomes there.

`material` is `VibrancyMaterial | null`. Materials are `'sidebar'`, `'titlebar'`, `'header'`, `'content'`, `'window'`, `'underWindow'`, `'underPage'`, `'menu'`, `'popover'`, `'sheet'`, `'hud'`, `'tooltip'`, `'fullscreenUI'`, and `'selection'`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `state` | `VibrancyState` | `'followsWindow'` | `'followsWindow'`, `'active'`, or `'inactive'`; control whether the material dims with the window. Windows can't choose: `getVibrancy()` always answers `'followsWindow'` there. |

Unknown materials reject `invalid_args`.

```ts
await host.window.setVibrancy('sidebar', { state: 'active' });
```

`getVibrancy()` resolves `{ material, state }`, or `null` without vibrancy.

The material takes the window's appearance (light or dark), not the page's. When the page's theme can differ from the system's, match it with [`setTheme`](#title-bar-appearance-and-behavior).

### `setGlass(glass, windowId?)`

macOS 26. Put Liquid Glass behind transparent page areas, or pass `null` to remove it. The window becomes non-opaque while it's on, and its opacity and background color come back when it's removed. It replaces vibrancy: one effect at a time. Resolves `{ glass: true }`, or `{ glass: false }` before macOS 26 and on Windows, where the `underWindow` vibrancy material is used instead; `null` when removing.

`glass` is `GlassOptions | null`:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `style` | `'regular' \| 'clear'` | `'regular'` | `regular` is frosted and readable over anything; `clear` is more transparent. |
| `tint` | `string` | None | `#rgb`, `#rrggbb` or `#rrggbbaa`; the alpha is the tint's strength. |
| `cornerRadius` | `number` | `0` | Rounds the glass's corners, in points. |

An unknown style or a malformed tint rejects `invalid_args`.

```ts
await host.window.setGlass({ style: 'clear', tint: '#5f62ef40' });
```

`getGlass()` resolves the window's `GlassOptions`, or `null` without glass. Before macOS 26 and on Windows, read `getVibrancy()` instead.

### `setTrafficLightPosition(position, windowId?)`

macOS only. `position` is `{ x: number; y: number } | null`: the close button's top-left in points from the frame's top-left. Use with a hidden/hidden-inset title bar; `null` restores system placement. Resolves `null`. The shell's title bar CSS measurements follow the controls.

`getTrafficLightPosition()` resolves the position set, or `null` at the system's place.

### Controls area

`getControlsArea(windowId?)` resolves `WindowControlsArea | null`. macOS measures native buttons and Windows asks DWM for its caption buttons; a window without them returns `null`. Linux registers the query but always returns `null` for server-side decorations.

`WindowControlsArea` contains `x`, `y`, `width`, and `height` (all `number`) in **window-frame coordinates**, plus:

| Field | Type | Description |
| --- | --- | --- |
| `contentTop` | `number` | Drawable content's inset from frame top. Subtract from `y` to convert the cluster's vertical offset to content coordinates. |
| `side` | `'left' \| 'right'` | Controls edge: `'left'` on macOS, `'right'` on Windows. |
| `buttons` | `{ close?: ControlsRect & { visible: boolean }; minimize?: ControlsRect & { visible: boolean }; zoom?: ControlsRect & { visible: boolean } }` | Per-button frame rectangles and visibility. |

`ControlsRect` is `{ x: number; y: number; width: number; height: number }`. The reactive `host.window.controlsArea` exposes the same coordinates without conversion.
