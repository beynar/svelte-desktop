title: Events and broadcast
description: Listen to native events, dispatch local events and send messages between pages and server code.
---

Use `host.on` for native notifications, `host.events` for local application events, and `host.broadcast` to reach other contexts. Subscriptions return synchronous unsubscribe functions; dispose them when their owner goes away.

How-to: [Menus](/ui/menus) and [menu bar and popovers](/ui/menu-bar-and-popovers).

## Native events

### `host.on<T = unknown>(event, fn)`

Listens to a native event by name. Returns `() => void`. `event` is a `string`; `fn` has type `(data: T) => void`. The type parameter describes the payload; it does not validate it or infer it from the event name.

```ts
const off = host.on<{ dark: boolean }>('appearanceChanged', (info) => {
  console.log(info.dark);
});
off();
```

Most services also offer typed helpers such as `host.theme.onChange`, `host.menu.onAction` and `host.webview.onFileDrop`. These return unsubscribe functions too. Use the helpers when available.

## Local events: `host.events`

This bus stays in the current JavaScript context. Its events do not enter the native bridge or reach other pages.

### Reactive state

| Property | Type | Description |
| --- | --- | --- |
| `ready` | `boolean` | `true` after initialization. |
| `error` | `Error \| null` | Initialization failure, normally `null` for this local bus. |

### `on<T = unknown>(name, cb)`

Subscribes to a local event. `name` is a `string`; `cb` is `(data: T) => void`. Returns `() => void`.

### `once<T = unknown>(name, cb)`

The same signature as `on`, but removes the subscription before the first callback. Its unsubscribe function can cancel it before delivery.

### `emit(name, payload?)`

Calls local listeners synchronously. `name` is a `string`, `payload` is `unknown` and defaults to `undefined`. Returns `void`. A throwing listener is caught so other listeners still run.

### `emitTo(windowId, name, payload?)`

Returns `Promise<void>`. `windowId` and `name` are strings; `payload` is optional `unknown`.

| `windowId` | Delivery |
| --- | --- |
| `'main'` or `'0'` | Calls `host.events.emit` in this context. |
| A string converting to a positive integer, such as `'2'` | Dispatches on this context's platform bus with a numeric `windowId`. Receive with `host.on` or the platform module's `onWindow(id, name, fn)`. Object payloads gain `windowId`; other supplied values become `{ windowId, data }`. |
| Anything else | Rejects with `invalid_args`. |

Despite its name, `emitTo` does not send to another process or page. Use `host.broadcast` for cross-context messages.

### `init()`

Sets `ready` and returns the store itself synchronously. Called automatically by the runtime.

## Broadcast between contexts

### `host.broadcast(channel, data?)`

Sends a message to every app window, popover and server listener, including the sender's context. Resolves `null`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `channel` | `string` | Required | Non-empty channel name. An empty name rejects with `invalid_args`. |
| `data` | `unknown` | `null` | JSON-serializable message data. `undefined` also becomes `null`. |

### `host.onBroadcast<T = unknown>(channel, fn)`

Subscribes to one `string` channel. `fn` is `(data: T, from: string | number) => void`. Returns `() => void`.

`from` is the sender's popover id (`string`) or public window id (`number`). Server calls use `0`, as does the primary window; it is a routing identity, not a unique identity for each context.

```ts
// In a popover route:
await host.broadcast('notes-changed');

// In the main window (dispose off when the component unmounts):
const off = host.onBroadcast('notes-changed', (_data, from) => {
  console.log('Refresh requested by', from);
});
```

For the explicit `desktop.publish` / `onDesktopEvent` API, see [Server code](/host/data/server#messages-to-pages).

## Platform support

| Method | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `host.on` (subscription) | ✓ | ✓ | ✓ |
| `host.events.on`, `once`, `emit`, `emitTo`, `init` | ✓ | ✓ | ✓ |
| `host.broadcast`, `host.onBroadcast` | ✓ | ✓ | ✓ |

Local methods do not require native operations. Native event availability follows the owning service, as linked in the index.

## Example

```svelte
<script lang="ts">
  import { onMount } from 'svelte';

  let lastSender = $state<string | number | null>(null);
  onMount(() => host.onBroadcast('notes-changed', (_data, from) => {
    lastSender = from;
  }));
</script>

<button onclick={() => host.broadcast('notes-changed')}>Notify all pages</button>
{#if lastSender !== null}<p>Last update from {lastSender}</p>{/if}
```
