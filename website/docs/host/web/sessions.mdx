---
title: host.sessions
description: Manage website profiles, cookies and per-session proxies.
---

`host.sessions` manages the website data stores used by [web views](/host/web/webview). Use named profiles for separate accounts or private browsing. This service has no reactive state. See [Platform support](#platform-support) for where Windows differs.

How-to: [Sessions and private profiles](/ui/web-view#sessions-and-private-profiles).

## Methods

### `create(options)`

Creates a named profile and resolves `SessionInfo`.

```ts
const profile = await host.sessions.create({ id: 'work', persistent: true });
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | Required | Unique, nonempty profile id, at most 200 characters. Cannot be `'default'`. |
| `persistent` | `boolean` | Required | Keep website data across launches, or use a private in-memory store. |

`SessionInfo` has `id: string` and `persistent: boolean`. The shell owns the persistent `'default'` profile. Select a profile with the `session` option when creating a [window](/host/windows/windows), [view](/host/windows/view) or [popover](/host/windows/popover). New views use `'default'` unless explicitly configured; they do not inherit the caller's profile. A view's profile cannot change after construction.

Persistent named profiles require macOS 14+ on macOS. Recreating the same id with the same app identifier opens its existing data. Private profiles keep their cookies and storage separate from other profiles.

Other cookies and storage are not copied from the default profile, and the app's own server still works in a named profile. Rejects with `invalid_args` for an invalid or duplicate id, `unsupported` for persistent named profiles before macOS 14, or `unavailable` when app authentication is not ready or WebKit does not retain it. Profiles still share the app's server authority.

### `list()`

Resolves `SessionInfo[]`, sorted by id, including `'default'` and profiles opened during this app run. It does not enumerate unopened profiles saved on disk.

```ts
const profiles = await host.sessions.list();
```

### `remove(id)`

Removes a named profile and deletes its website data, including persistent data. Resolves `null`.

| Parameter | Type | Description |
| --- | --- | --- |
| `id` | `string` | Profile to delete. |

Close or destroy every window, view and popover using the profile, and await its pending cookie operations first. Rejects with `invalid_args` for an unknown or removing profile, `denied` for `'default'`, or `unavailable` while the profile is in use or deletion fails.

### `setProxy(id, proxy)`

Sets a profile's HTTP CONNECT or SOCKSv5 proxy. Pass `null` to restore system defaults. Resolves `null`. Requires macOS 14+ on macOS.

```ts
await host.sessions.setProxy('work', {
  type: 'http', host: 'proxy.example.com', port: 8080, tls: true
});
```

| Parameter | Type | Description |
| --- | --- | --- |
| `id` | `string` | Profile to configure, including `'default'`. |
| `proxy` | `SessionProxy \| null` | Configuration below, or system defaults. |

Every field of `SessionProxy`:

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `'http' \| 'socks'` | Required | HTTP CONNECT or SOCKSv5. |
| `host` | `string` | Required | Nonempty proxy host. |
| `port` | `number` | Required | Integer from 1 to 65535. |
| `username` | `string` | Omitted | Proxy authentication username. |
| `password` | `string` | Omitted | Proxy authentication password; requires `username`. |
| `tls` | `boolean` | `false` | Encrypt the connection to an HTTP proxy; unavailable for SOCKS. |

Loopback hosts (`127.0.0.1`, `localhost`, `::1`) always bypass the proxy. Direct failover is disabled. This affects WebKit networking, independently of Bun `fetch()` and jobs. Existing connections may outlive a configuration change. TLS validation and App Transport Security still apply.

Rejects with `invalid_args` for invalid fields, an unknown profile, SOCKS with TLS, or a password without a username. Unknown proxy fields, including PAC and custom bypass options, reject with `unsupported`, as do proxy changes before macOS 14. Failure to create the native configuration rejects with `unavailable`.

### `getProxy(id = 'default')`

Resolves `SessionProxyInfo | null`. Returns the host-owned configuration, not resolved system settings or proof of a successful connection. `null` means system defaults.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | `string` | `'default'` | Profile to inspect. |

`SessionProxyInfo` contains `type: 'http' | 'socks'`, `host: string`, `port: number`, `tls: boolean` and `authenticated: boolean`. Credentials are never returned. `authenticated` means a username was configured, not that authentication succeeded. Rejects with `invalid_args` for an unknown or removing profile.

### `capabilities()`

Resolves `SessionCapabilities` for the running OS version.

| Property | Type | Description |
| --- | --- | --- |
| `private` | `boolean` | Private profiles are supported (`true`). |
| `persistentNamed` | `boolean` | Named persistent profiles are supported on macOS 14+, on Linux and on Windows. |
| `proxy` | `boolean` | Per-profile proxies are supported on macOS 14+ and on Linux. On Windows, on named profiles only. |
| `proxyAuthentication` | `boolean` | Proxy credentials are supported on macOS 14+, on Linux and on Windows. |
| `pac` | `boolean` | PAC configuration is unsupported (`false`). |
| `customBypass` | `boolean` | Custom bypass rules are unsupported (`false`). |

### `cookies.get(filter = {})`

Resolves `SessionCookie[]` matching the filter.

| `CookieFilter` field | Type | Default | Description |
| --- | --- | --- | --- |
| `session` | `string` | `'default'` | Profile id. |
| `url` | `string` | Omitted | HTTP(S) URL; match domain, path boundaries and the cookie's Secure flag. |
| `name` | `string` | Omitted | Exact cookie name. |

`SessionCookie` contains:

| Property | Type | Description |
| --- | --- | --- |
| `name`, `value` | `string` | Cookie name and value. |
| `domain`, `path` | `string` | Cookie scope. |
| `secure` | `boolean` | Restricted to HTTPS. |
| `httpOnly` | `boolean` | Hidden from page JavaScript. |
| `sessionOnly` | `boolean` | A session cookie. |
| `expires` | `number` (optional) | Seconds since the Unix epoch; omitted for session cookies. |
| `sameSite` | `'Lax' \| 'Strict' \| 'None'` (optional) | SameSite policy when reported by WebKit. |

Rejects with `invalid_args` for an unknown profile, invalid URL or invalid filter type. The shell authentication cookie is omitted; requesting its name (`'__kitop'`) rejects with `denied`.

### `cookies.set(options)`

Sets a cookie and resolves `null` after checking that WebKit retained it, or that its expiry is already in the past.

| `CookieSetOptions` field | Type | Default | Description |
| --- | --- | --- | --- |
| `session` | `string` | `'default'` | Profile id. |
| `url` | `string` | Required | HTTP(S) origin URL for the cookie. |
| `name` | `string` | Required | Nonempty cookie name. |
| `value` | `string` | Required | Cookie value; may be empty. |
| `domain` | `string` | URL host | Exact host, or a matching domain prefixed with `.`. |
| `path` | `string` | `'/'` | Cookie path; must begin with `/`. |
| `secure` | `boolean` | `false` | Requires an HTTPS URL. |
| `httpOnly` | `boolean` | `false` | Hide the cookie from page JavaScript. |
| `expires` | `number` | Omitted | Finite seconds since the Unix epoch; omit for a session cookie. |
| `sameSite` | `'Lax' \| 'Strict' \| 'None'` | Omitted | `'None'` requires `secure: true`. |

Rejects with `invalid_args` for an unknown profile or invalid cookie fields, including a domain that does not match the URL. Names cannot contain `=`, `;`, a space, CR, LF or tab; values cannot contain `;`, CR or LF. Replacing the shell authentication cookie rejects with `denied`. WebKit refusing to retain the cookie rejects with `unavailable`.

### `cookies.remove(options)`

Deletes all cookies matching the URL and name, across applicable paths. Resolves `{ removed: number }`.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `session` | `string` | `'default'` | Profile id. |
| `url` | `string` | Required | HTTP(S) URL, matched using the same rules as `cookies.get`. |
| `name` | `string` | Required | Nonempty cookie name. |

Rejects with `invalid_args` for an unknown profile, missing name or invalid URL. Removing the shell authentication cookie rejects with `denied`.

## Events

### `cookies.onChanged(callback)`

Subscribes to cookie changes across profiles and returns `() => void` to unsubscribe.

| Parameter | Type | Description |
| --- | --- | --- |
| `callback` | `(event: CookieChangedEvent) => void` | Receives each reported cookie change. |

| Event | Payload | When |
| --- | --- | --- |
| `sessionCookieChanged` | `CookieChangedEvent` | A cookie is added, updated or removed. |

`CookieChangedEvent` contains `session: string`, `cookie: SessionCookie` and `removed: boolean`. Additions and updates have `removed: false`; removals carry the previous cookie and `removed: true`. The shell authentication cookie is excluded.

`onChanged` can miss very short-lived changes, so it is not an audit log. To catch `document.cookie` changes that WebKit does not report, on macOS the shell polls profiles with open views once per second, only while someone listens through `cookies.onChanged`. `host.on('sessionCookieChanged', callback)` does not enable that polling; use `cookies.onChanged`. Linux polls nothing: WebKitGTK reports every change. WebView2 has no cookie event, so Windows compares profiles the same way as macOS, and only notices a page's own change at the next comparison.

## Platform support

| Method | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `create`, `remove`, `setProxy` | ✓¹ | ✓³ | ✓² |
| `list`, `getProxy`, `capabilities` | ✓ | ✓ | ✓ |
| `cookies.get`, `cookies.set`, `cookies.remove`, `cookies.onChanged` | ✓ | ✓⁴ | ✓ |

1. Private profiles work on any supported macOS; `persistent: true` and `setProxy` need macOS 14+.
2. See [Windows](#windows). A runtime too old for WebView2 profiles rejects `create` with `unavailable`, and `capabilities` says `false`.
3. A persistent profile's data is in `sessions/` under the app's data folder, and removing it deletes that folder. A plain HTTP proxy receives `http://` requests directly (`GET http://host/`) rather than through CONNECT; over TLS, and for `https://` URLs, it's a CONNECT. Run against local HTTP, TLS and SOCKS5 proxies written for the tests, not against commercial ones.
4. A cookie set without `SameSite` reads back as `Lax`, where macOS omits the field. The default profile keeps its lasting cookies in `cookies.sqlite` in the app's data folder.

### Windows

A session is a WebView2 profile: a folder under `WebView2` in the app's data folder for a persistent one, a private profile for the others. The shell keeps a hidden web view open in each session: that's what reaches its cookies with no view of yours in it, and what keeps a private session's data alive. It costs a renderer process per session. Removing a persistent session clears its data at once; WebView2 deletes its folder when the browser process has gone, or at a later launch. A private session leaves an empty folder there, deleted at a later launch.

WebView2 has no per-profile proxy. A proxy is a `--proxy-server` argument for a whole browser process, fixed when that process starts. So on Windows:

- **Views already open:** `setProxy` rejects with `unavailable` while a window, view or popover is open in the session, and nothing changes. Close them, set the proxy, open them again. They'd otherwise have to die, or stay behind on the old proxy with another cookie store.
- **The first proxy moves the session.** It gets a browser process and a user data folder of its own (`WebView2-sessions` in the app's data folder), for good, even after `setProxy(id, null)`. Its cookies come along, and its other storage (localStorage, IndexedDB, cache) doesn't: it's deleted with the profile it was in. Later changes keep all of it, and restart that browser process, which takes a moment. A private session's own folder is deleted with it, and swept at a later launch if the app ends first.
- **The default session can't have one.** `setProxy('default', proxy)` rejects with `unsupported`, because the app's own pages run in that browser process. `setProxy('default', null)` resolves.
- A proxy isn't kept across launches, on any platform: set it again after `create`. On Windows a persistent session with its own folder comes back to it, without a proxy until then.
- Everything the browser process sends goes through the proxy, including WebView2's own requests to Microsoft (`config.edge.skype.com` and SmartScreen were seen on the test runner). A plain HTTP proxy receives `http://` requests directly rather than through CONNECT. Loopback hosts bypass it, the whole of `127.0.0.0/8`.
- A SOCKS proxy can't have credentials: Chromium doesn't send them, so they reject with `unsupported`. HTTP proxy credentials are answered by the shell when the proxy asks, and only then: a site asking for a password through that proxy goes to your [authentication handler](/host/web/web-policy) like any other. Wrong ones are tried three times in ten seconds, then the proxy's own answer reaches the page.
- Run against local HTTP, TLS and SOCKS5 proxies written for the tests, not against commercial ones.

Windows, views and popovers take `session` as elsewhere, and `host.webview.clearData` leaves named sessions alone. Tested on one runtime on a runner: see [limitations](/shipping/limitations#windows).

## Example

Cookies only exist once a view has loaded a site in the profile. Open a view in the session with the `session` option, then work with its cookies:

```ts
await host.sessions.create({ id: 'preview', persistent: false });
await host.view.create({
  id: 'preview-view', session: 'preview', url: 'https://example.com/',
  bounds: { x: 0, y: 0, width: 800, height: 600 },
});
const off = host.sessions.cookies.onChanged(({ session, cookie, removed }) => {
  if (session === 'preview') console.log(cookie.name, removed);
});

try {
  await host.sessions.cookies.set({
    session: 'preview', url: 'https://example.com/',
    name: 'theme', value: 'dark', secure: true, sameSite: 'Lax'
  });
  const cookies = await host.sessions.cookies.get({ session: 'preview' });
  console.log(cookies.map((cookie) => cookie.name));
  await host.sessions.cookies.remove({
    session: 'preview', url: 'https://example.com/', name: 'theme'
  });
} finally {
  off();
  await host.view.destroy('preview-view');
  await host.sessions.remove('preview');
}
```
