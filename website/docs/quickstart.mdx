**Requirements for this macOS quick start:** macOS 12+, Bun 1.4 or newer and the Xcode command line tools (`xcode-select --install`). The desktop plugin runs on Bun, so Vite is always started with `bunx --bun`. This page covers macOS; the [Platforms](/#platforms) table shows the status of Linux and Windows.

An app needs these versions. `create` writes them for you; an existing app installs the adapter below, and must already be on the other two.

| Package | Version |
| --- | --- |
| `@sveltejs/kit` | `^3.0.0-next.0`: SvelteKit 3, pre-releases included |
| `@sveltejs/adapter-bun` | `1.0.0-next.2` exactly: a pre-release, pinned, so name the version when you install it |
| `svelte` | `^5.56.0` |

<Tabs>
  <Tab title="New project">

```sh
bunx -p @kitop/shell kitop create my-app
cd my-app && bun install && bun run dev
```

`create` needs an empty or missing directory. It writes a SvelteKit app with a remote function, `desktop.config.ts`, a Swift plugin sample and a test, with `@kitop/shell` pinned to the version that ran it ([Versions](/reference/versioning)).

  </Tab>
  <Tab title="Existing SvelteKit app">

```sh
bun add -d @kitop/shell @sveltejs/adapter-bun@1.0.0-next.2 @types/bun
bunx kitop init
bun run dev
```

Step by step: [Convert a SvelteKit app](/convert-sveltekit-app). `init` writes `desktop.config.ts`, switches `vite.config.ts` to the `desktop()` plugin, and sets the `dev`, `build` and `test:desktop` scripts. If it prints a warning, see [Adopting an existing app](/concepts/adopting) for what it changes and what to check.

  </Tab>
</Tabs>

`bunx kitop doctor` checks Bun, the Xcode tools, the versions above and the config, and on macOS the signing identity and notary profile.

## Develop

<Steps>
  <Step title="Run the app">
    `bun run dev` (`bunx --bun vite dev`) opens the native window on the Vite server: HMR in the window, the Web Inspector, and server code reaching native APIs through an RPC bridge. The first run compiles the native shell, which takes a while. A new project shows a button, "Clicked 0 times", that increments through a remote function.
  </Step>
  <Step title="Edit freely">
    Svelte files hot-reload. Editing `desktop.config.ts` restarts the dev server and shell; changing existing plugin sources under `native/` rebuilds the plugins and restarts the shell. Native sources do not hot-reload in place. Closing the window ends `vite dev` by default (`exitOnClose: false` keeps Vite running).
  </Step>
  <Step title="Build">
    `bun run build` (`bunx --bun vite build`) writes `.desktop/dist/<App>.app`, a zip and a DMG, plus `release/` when [self-update](/shipping/self-update) is configured. Without a signing identity the app is ad-hoc signed: it runs locally, Gatekeeper blocks it once downloaded. See [Distribution](/shipping/distribution).
  </Step>
  <Step title="Test">
    `bun run test` opens a real window and drives it (in a project set up with `init`, the script is `test:desktop`). It runs the built app, so build first: `bun run build && bun run test`. `DESKTOP_TEST_DEV=1 bun run test` runs against `vite dev` instead. See [Testing](/features/testing).
  </Step>
</Steps>

:::tip
`desktop({ ... }, { noWindow: true })` in `vite.config.ts`, or `KITOP_NO_WINDOW=1`, runs `vite dev` without the native window, for browser-only work. Server code still gets addons and sidecars.
:::

## Project layout

What `create` scaffolds, plus the types and output generated by dev and build. `src/services/`, `src/jobs/` and the root icon are optional and not scaffolded:

<FileTree>

- my-app/
  - desktop.config.ts
  - vite.config.ts
  - package.json
  - tsconfig.json
  - native/
    - Hello.swift
  - src/
    - app.html
    - host.d.ts
    - native.d.ts
    - lib/
      - hello.remote.ts
    - routes/
      - +page.svelte
  - tests/
    - app.test.ts
  - .desktop/

</FileTree>

| Path | What it is |
| --- | --- |
| `desktop.config.ts` | App name, identifier, window, permissions, signing: see [Configuration](/concepts/configuration). |
| `native/` | Optional [native plugins](/native/plugins), compiled automatically. Swift, Objective-C, C and C++ sources; Rust crates and Go modules build separately. Delete it if you don't need plugins. |
| `src/host.d.ts` | Types for the [`host` global](/host). Written once by the Vite plugin; keep it in git. |
| `src/native.d.ts` | Types for plugin commands, regenerated by dev and build when plugins are present. |
| `src/services/` | Optional [persistent services](/native/services), one file per service. |
| `src/jobs/` | Optional [background jobs](/native/jobs), one file per job. |
| `icon.png` or `icon.svg` | Optional [app icon](/shipping/app-icon) at the project root. |
| `.desktop/` | Build output and caches (`dist/`, `icons/`, `dev/`). Ignored by git. |

## A first native call

```svelte src/routes/+page.svelte
<p>{host.app.name} · {host.theme.dark ? 'dark' : 'light'}</p>
<button onclick={() => host.clipboard.writeText('Hello')}>Copy</button>
<button onclick={() => host.window.setTitle('Hello')}>Rename window</button>
```

`host` needs no import and is reactive in components. In a plain browser tab, `host.available` is `false`. Some services only work in the built app: in `vite dev`, [notifications](/features/notifications) do nothing.
