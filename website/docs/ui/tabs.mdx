Two components, each configured by its props and drawn with snippets:

- **`<WindowTabs>`** — the window's tabs, in the title bar. Its tabs are your SvelteKit routes: you write links as usual, and the tabs follow.
- **`<Tabs>`** — tabs inside a page, on your own items: boards, documents, a segmented control.

## The window's tabs

One declaration, in the root layout. `page` is the layout's `children`; `layout` puts the bar in the title bar and the content where the page goes:

```svelte src/routes/+layout.svelte
<script lang="ts">
	import { WindowTabs } from '@svelte-desktop/shell/tabs';

	let { children } = $props();
</script>

<WindowTabs page={children} newTab="/" keepAlive={['/chat', '/terminal/[id]']}>
	{#snippet layout({ bar, content })}
		<header class="titlebar">{@render bar()}</header>
		<Sidebar />
		<main>{@render content()}</main>
	{/snippet}
</WindowTabs>

<style>
	.titlebar {
		height: max(var(--desktop-titlebar-height, 0px), 2.75rem);
		padding-left: max(var(--desktop-controls-width, 0px), 0.75rem); /* clear the traffic lights */
		--app-region: drag; /* its empty parts move the window */
	}
</style>
```

Each page names its tab with its `<title>`, like in a browser:

```svelte src/routes/invoices/[id]/+page.svelte
<svelte:head><title>Invoice {data.invoice.number}</title></svelte:head>
```

From there, it's links:

```svelte
<a href="/reports">Reports</a>                 <!-- the active tab goes to /reports -->
<a href="/reports" target="_blank">Reports</a> <!-- a new tab (⌘-click, a middle click: in the background) -->
<a href="/chat">Chat</a>                       <!-- /chat is keepAlive: its own tab, which keeps running -->
```

| You | The tabs |
| --- | --- |
| A link, `goto()`, the sidebar | The active tab goes there — the page you leave is unmounted, as on any SvelteKit navigation |
| `target="_blank"` / ⌘-click, middle click | A new tab on it, in front / in the background — on a `keepAlive` route too: another one, with its own view, running from the start (in the background too) |
| A link or `goto()` to a `keepAlive` route | Its tab if it's open, else a new one: it runs in its own web view and goes on while you're elsewhere (timers, sockets, what you typed). The page you were on stays on screen until the view is drawn, then the window's address becomes the tab's: `page.url`, your sidebar's active link, follow it |
| ⌘T / the + button | A new tab on `newTab` |
| ⌘W / × | Close the tab (`beforeClose` can keep it); the main window keeps a tab on `newTab` |
| Drag a tab | Reorder. A regular route tab can move to another window's bar; with at least two tabs, dragging it outside opens a new window. Kept-alive and external tabs stay in their window |
| Back / Forward | The browser's history, shared by the tabs |

You never create a tab by hand: a route that must keep running is declared once, in `keepAlive`, with SvelteKit's route ids (`/terminal/[id]`, `/docs/[...rest]`), and every link to it follows. Each kept-alive tab uses another web view and consumes more memory: keep it for pages that need to stay mounted. Hidden views can still be throttled, and suspension or a process crash loses in-memory state. Put work that must outlive a page in [background jobs](/native/jobs) or [services](/native/services). While one is shown, the window takes its address without navigating there — no `load`, no page code in the window (the view runs the page) — and `page.url`, your sidebar's active link, Back and Forward follow. A link followed from your layout while it's shown (the sidebar) goes to a tab of the page: the one already at that address, else the last one shown.

The main window's tabs are restored at the next launch. For a regular active tab, the window opens on its page. For a kept-alive active tab, it opens on the last regular page, then shows the tab's view when ready. Restored kept-alive tabs start after the window page hydrates, subject to `maxViews`; the window title follows the active tab; a native **Tab** menu has ⌘T ⌘W ⇧⌘T ⌃⇥ and ⌘1–9 (in its **Select Tab** submenu), and wins over the page — and over a kept-alive tab's view; only the focused window acts on it. These Command shortcuts use Ctrl on Linux and Windows, and ⌘9 / Ctrl+9 selects the last tab. With `titleBarStyle: 'hiddenInset'` the bar sits next to the traffic lights: tabs and buttons stay clickable, the empty parts of the strip move the window.

### Snippets

```svelte
<WindowTabs page={children} newTab="/">
	{#snippet tab({ tab, active, close })}
		<RouteIcon path={tab.path} />
		<span>{tab.title}</span>
		<button onclick={close}>✕</button>  <!-- a control in a tab doesn't activate it -->
	{/snippet}

	{#snippet layout({ bar, content, api })}
		<header class="titlebar">{@render bar({ class: 'my-tabs', label: 'Open pages' })}</header>
		<AppShell title={api.active?.title}>
			{#snippet headerActions()}
				<button onclick={() => api.open('https://svelte.dev/docs')}>Docs</button>
			{/snippet}
			{@render content({ class: 'h-full' })}
		</AppShell>
	{/snippet}

	{#snippet embedded({ page })}
		<div class="p-6">{@render page()}</div>
	{/snippet}
</WindowTabs>
```

- `tab` draws each tab (default: its title and a close button).
- `layout` gets `bar` (the tab bar: `class`, `label`, `start`, `end`), `content` (the page, and each kept-alive tab's view in the same place) and `api`; without it, the bar goes above the content.
- `embedded`: a kept-alive tab's view runs your app again, layout included — there `<WindowTabs>` renders the page alone (or this snippet), on the server too (the view's request says so), so the view shows at its first paint. Your own code can test `embedded` from `@svelte-desktop/shell/tabs` (in the page).

`api` (also `bind:api`, set in the browser: on the server, `layout`'s `api`): `items`, `active`, `open(path | url, { background, reuse })` (`reuse: false`: another tab on a kept-alive route already open), `close(id?)`, `activate(id)`, `reopen()`, `cycle(1 | -1)`, `move(id, index)`. `api.open('https://…')` shows another site in a tab of its own (external links keep opening the browser); it can't call native APIs and receives none of the app's events. A tab is `{ id, path?, url?, title? }`. Reuse of a kept-alive tab matches the pathname, ignoring query and hash; it activates the existing tab without changing its URL. Use `reuse: false` to open a separate tab with different parameters.

A view is drawn over the page: your page's popovers and dialogs can't cover a kept-alive tab or another site. A kept-alive tab's view is see-through: where its page paints nothing, the background of your layout around `content` shows — give the `embedded` page no background of its own and it blends in. It waits for its page-ready signal (or a load failure or three-second timeout); until then the tab you were on stays. A link to a kept-alive route makes its view ahead when SvelteKit would preload it — `data-sveltekit-preload-data="hover"` (in the default `app.html`) once the pointer rests on it, `"tap"` when pressed, `"false"` never — so the click shows it at once (unused, it's dropped after 5 s); at launch, restored kept-alive tabs start once your page is up.

## Tabs in a page

`<Tabs>` takes your items and renders a bar and a panel per tab. An item is a string, or `{ value, label }` plus `pinned`, `closable` and your own fields. Give each item a unique, stable `value`. `pinned` hides its close button and excludes it from `closeOthers`; use `closable: false` too if it must not close through the API or a middle click:

```svelte
<script lang="ts">
	import { Tabs } from '@svelte-desktop/shell/tabs';

	let boards = $state([
		{ value: 'current', label: 'Current sprint', pinned: true },
		{ value: 'backlog', label: 'Product backlog' }
	]);
	let active = $state('current');
</script>

<Tabs
	bind:items={boards}
	bind:value={active}
	mount="once"
	persist="board-tabs"
	closable={(b) => !b.pinned}
	reorderable
	onAdd={() => ({ value: crypto.randomUUID(), label: 'New board' })}
	beforeClose={({ item }) => confirm(`Close ${item.label}?`)}
>
	{#snippet children({ item })}<Board id={item.value} />{/snippet}
</Tabs>
```

`beforeClose` is synchronous: return `false` to veto a close; a promise is not awaited. Adding (the + button, with `onAdd`), closing and dragging write back to `bind:items`; your array changing is what the bar shows. Persisted items must be JSON-serializable. In-page groups save only in the main window. A fixed segmented control is just items:

```svelte
<Tabs items={['Day', 'Week', 'Month']} bind:value={range} class="segmented">
	{#snippet children({ item })}<Agenda {range} />{/snippet}
</Tabs>
```

`tab` draws each tab and `layout` places the bar and the panels — a bar in a card's header, say:

```svelte
<Tabs items={lists}>
	{#snippet tab({ item, closable, close })}
		<span>{item.label}</span>
		{#if closable}<button onclick={close}>✕</button>{/if}
	{/snippet}
	{#snippet layout({ bar, content })}
		<header><h2>This week</h2>{@render bar()}</header>
		{@render content({ class: 'p-4' })}
	{/snippet}
	{#snippet children({ item })}…{/snippet}
</Tabs>
```

## Styling

The bar only lays out (zero-specificity styles): style it with `class` and the state attributes.

| Selector | |
| --- | --- |
| `[role=tablist]` (`data-sd-tabbar`) | The bar; its `gap` spaces the tabs |
| `[role=tab]`, `[data-active]`, `[data-pinned]`, `[data-suspended]`, `[data-dragging]` | A tab and its states (`data-suspended`: its view closed to free memory) |
| `[data-sd-tab-drop]` | The line where a dragged tab lands (`--sd-tab-drop-color`, default `Highlight`) |
| `[data-sd-tab-title]`, `[data-sd-tab-close]` | The default content |
| `[data-sd-tab-new]` | The + button |
| `[role=tabpanel]` (`data-sd-tabpanel`) | A panel (`hidden` when inactive) |

The drag is native drag and drop ([pragmatic-drag-and-drop](https://atlassian.design/components/pragmatic-drag-and-drop/)): the system's drag image follows the pointer, beside it, out of the window and over other windows. The [dashboard example](https://github.com/beynar/svelte-desktop/tree/bun-webview-shell/examples/dashboard) has the window's tabs (with a kept-alive `/activity`), boards with rename, and a segmented control.
