`@svelte-desktop/shell/tabs` gives you a tab group (`Tabs`, Svelte 5 runes) and the components to render it: `<TabBar>`, `<TabContent>` (route tabs) and `<TabPanels>` (state tabs). One group is the window's own tab bar, in the title bar; others can live anywhere inside your pages. Drawing tabs is the easy part — the module brings what makes them feel native: the window title, a **Tab** menu with ⌘T ⌘W ⇧⌘T ⌃⇥, ⌘1–9, ⌘-click on a link, restoring the tabs at launch.

## In the title bar

Route tabs are places in your app: activating a tab navigates to its path, and navigating (a link, the sidebar) changes the active tab's path — each tab remembers where it was.

```svelte src/routes/+layout.svelte
<script lang="ts">
	import { Tabs, TabBar, TabContent } from '@svelte-desktop/shell/tabs';

	let { children } = $props();

	const tabs = new Tabs({
		id: 'app',
		route: true,      // tabs are app routes
		primary: true,    // the window's tab bar: title, Tab menu, shortcuts, restored at launch
		create: () => ({ path: '/' }),
		onLastClose: 'new',
		title: (url) => titles[url.pathname] ?? 'Untitled'
	});
</script>

<header class="titlebar">
	<TabBar {tabs} label="Open pages" />
</header>
<TabContent {tabs}>{@render children()}</TabContent>

<style>
	.titlebar {
		height: max(var(--desktop-titlebar-height, 0px), 2.75rem);
		padding-left: max(var(--desktop-controls-width, 0px), 0.75rem); /* clear the traffic lights */
		--app-region: drag; /* its empty parts move the window */
	}
</style>
```

With `titleBarStyle: 'hiddenInset'` the bar sits next to the traffic lights. Tabs and buttons stay clickable, the empty parts of the strip move the window, and a double-click on them zooms it.

| Shortcut | |
| --- | --- |
| ⌘T / the + button | A new tab from `create()`, at the end |
| ⌘W | Close the active tab (`onLastClose` decides what the last one does) |
| ⇧⌘T | Reopen the last closed tab |
| ⌃⇥ / ⌃⇧⇥ | Next / previous tab |
| ⌘1 – ⌘8, ⌘9 | That tab, the last one |
| ⌘-click or middle-click a link | Open it in a new tab, in the background |
| Middle-click a tab | Close it |
| Drag a tab | Reorder (a line shows where it lands) |
| Drag a tab out of the window | Open it in its own window, right where it's let go — or, dropped on another window's tab bar, move it there (isolated tabs stay in their window) |
| Tab › Move Tab to New Window | The same, from the menu |

The shortcuts are a **Tab** menu inserted before Window (⌘1–9 in its **Select Tab** submenu), so they show in the menu bar and win over the page — and over an isolated tab's web view. Only the focused window acts on them. The window title follows the active tab. Each window has its own tabs. The main window's are restored at launch; a window a tab was dragged into starts with that tab (its title and `data` included), and closes when its last tab leaves. The drag is native drag and drop ([pragmatic-drag-and-drop](https://atlassian.design/components/pragmatic-drag-and-drop/)): the system's drag image follows the pointer, beside it, out of the window and over other windows; a tab dropped on another window's bar is a real drop there, and leaves only once that window took it. Let go elsewhere in its own window (or Escape), nothing happens; the main window's last tab only moves onto another window.

## Isolated tabs

A tab can live in **its own web view** — its own process — instead of the page: a page of another site (`url`, always isolated), or an app route kept apart (`isolated: true`). It shares the bar, the shortcuts, the drag and the restore with the other tabs; its title and address follow the page it shows.

```ts
tabs.open({ url: 'https://svelte.dev/docs', title: 'Svelte docs' }); // another site: isolated
tabs.open({ path: '/editor/big-file', isolated: true });            // an app route in its own process
```

`<TabContent>` shows the page for ordinary route tabs and each isolated tab's web view in the same place (kept alive, hidden while another tab shows); in state groups `<TabPanels>` does the same. Isolate a third-party page, a heavy document whose crash or memory must stay apart, or something that must keep running on its own — each one costs a web content process (40–100 MB). A page of another site can't call native APIs and receives none of the app's events: the bridge and the events are the app origin's only.

A web view is drawn over the page: your page's popovers and dialogs can't cover an isolated tab, so show them from a route tab. An app route isolated in its own view runs your layout again, in that view: there `tabs.embedded` is true — the group stays local (no Tab menu, nothing saved) and `<TabBar>` renders nothing — so render the page alone:

```svelte
{#if tabs.embedded}
	{@render children()}
{:else}
	<header class="titlebar"><TabBar {tabs} /></header>
	<TabContent {tabs}>{@render children()}</TabContent>
{/if}
```

## Inside a page

Any other group is plain state: show each tab's content with `<TabPanels>`. Panels are kept alive by default — every tab keeps its components, scroll and inputs.

```svelte src/routes/board/+page.svelte
<script lang="ts">
	import { Tabs, TabBar, TabPanels } from '@svelte-desktop/shell/tabs';

	const boards = new Tabs<{ board: string }>({
		id: 'boards',
		restore: true,
		initial: [{ id: 'current', title: 'Current sprint', data: { board: 'current' }, pinned: true }],
		create: () => ({ title: 'New board', data: { board: crypto.randomUUID() } })
	});
</script>

<TabBar tabs={boards} class="underline-tabs" />
<TabPanels tabs={boards}>
	{#snippet children(tab)}<Board id={tab.data!.board} />{/snippet}
</TabPanels>
```

Fixed tabs (`closable: false`, no `create`) make a segmented control; `keepAlive={false}` renders only the active panel. The [dashboard example](https://github.com/beynar/svelte-desktop/tree/bun-webview-shell/examples/dashboard) shows all three — title-bar tabs, underline tabs with rename and +, and a segmented control.

## Styling

`<TabBar>` only lays out (zero-specificity styles). Style it with `class` and the state attributes, or render each tab yourself with the `tab` snippet:

```svelte
<TabBar {tabs} class="my-tabs">
	{#snippet tab(t, { active, close })}
		<Icon name={t.data.icon} />
		<span>{t.title}</span>
		<button onclick={close} onmousedown={(e) => e.stopPropagation()}>×</button>
	{/snippet}
</TabBar>
```

| Selector | |
| --- | --- |
| `[role=tablist]` (`data-sd-tabbar`) | The bar; its `gap` spaces the tabs |
| `[role=tab]`, `[data-active]`, `[data-pinned]`, `[data-dragging]` | A tab and its states |
| `[data-sd-tab-drop]` | The line where a dragged tab lands (`--sd-tab-drop-color`, default `Highlight`) |
| `[data-sd-tab-title]`, `[data-sd-tab-close]` | The default content |
| `[data-sd-tab-new]` | The + button (when `create` is set) |
| `[role=tabpanel]` (`data-sd-tabpanel`) | A panel (`hidden` when inactive) |

## API

<TypeTable
  type={{
    id: { type: "string", description: "Names the group (saved tabs, element ids, views); unique per window.", required: true },
    route: { type: "boolean", description: "Tabs are app routes: activating navigates, navigating updates the active tab." },
    primary: { type: "boolean", description: "The window's tab bar: window title, Tab menu and shortcuts, ⌘-click on links." },
    restore: { type: "boolean", description: "Save the tabs and restore them at the next launch.", default: "primary" },
    initial: { type: "TabInput[]", description: "The tabs to start with when nothing is restored. Route groups default to the current page." },
    create: { type: "() => TabInput", description: "What a new tab is (⌘T, +). Without it, no new-tab affordance." },
    onLastClose: { type: "'window' | 'new' | 'keep'", description: "Closing the last tab.", default: "'window' (primary), 'keep'" },
    title: { type: "(url: URL) => string", description: "A route tab's title from its URL." },
    detachable: { type: "boolean", description: "Drag a route tab out of the bar: into a new window, or onto another window's bar.", default: "primary route groups" },
    windowAnimation: { type: "boolean | WindowAnimation", description: "How a window a tab was dragged into comes in (macOS): see [Animation](/ui/windows#animation).", default: "true" },
  }}
/>

A tab is `{ id, title, path?, url?, isolated, pinned, closable, data? }`. The group's state is reactive — `tabs.items`, `tabs.activeId`, `tabs.active`, `tabs.window` (this window's label), `tabs.embedded` (this page is an isolated tab's view) — and its methods are `open(input, { activate, index })`, `new()`, `activate(id)`, `close(id?)`, `closeOthers(id)`, `reopen()`, `cycle(1 | -1)`, `move(id, index)`, `update(id, patch)`, `get(id)`, `detach(id, at?)` (into a new window, at a screen point). Your own bar can drag tabs between windows with `handoff(id)` (the data a dragged tab carries), `receive(handoff, index)` (in the window it's dropped on) and `release(id, at)` (when it's let go: it leaves if taken, else opens in a new window at `at`). Without `<TabBar>`, call `tabs.connect()` once (it returns its cleanup) to get the desktop integration with your own markup.
