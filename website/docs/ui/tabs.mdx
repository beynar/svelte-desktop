`@svelte-desktop/shell/tabs` is a set of Svelte components on **your** tabs. `<Tabs>` takes your list and the active id with `bind:`, and everything inside it shows and changes them: `<TabBar>`, `<TabContent>` (route tabs), `<TabPanels>` (state tabs), and `useTabs()` for your own components. Closing, reordering, a new tab, a tab arriving from another window: it all lands on your array, and your array changing is what the bar shows. Drawing tabs is the easy part — the module brings what makes them feel native: the window title, a **Tab** menu with ⌘T ⌘W ⇧⌘T ⌃⇥, ⌘1–9, ⌘-click on a link, restoring the tabs at launch, dragging a tab out into its own window.

## Your tabs

A tab is any object with an `id`. The fields the bar knows are optional, and your own go right on it:

```svelte
<script lang="ts">
	import { Tabs, TabBar, TabPanels } from '@svelte-desktop/shell/tabs';

	let boards = $state([
		{ id: 'current', title: 'Current sprint', pinned: true, board: 'current' },
		{ id: 'backlog', title: 'Product backlog', board: 'backlog' }
	]);
	let active = $state('current');
</script>

<Tabs
	bind:tabs={boards}
	bind:active
	newTab={() => ({ title: 'New board', board: makeBoard() })}
	onclose={(tab) => isEmpty(tab.board) || confirm(`Close ${tab.title}?`)}
>
	<TabBar />
	<TabPanels>
		{#snippet children(tab)}<Board id={tab.board} />{/snippet}
	</TabPanels>
</Tabs>

<p>{boards.length} boards — {boards.find((b) => b.id === active)?.title}</p>
```

`boards.push(…)`, a renamed `title`, a new `active`: the bar follows. Without `bind:`, `tabs={[…]}` is where it starts and the group keeps the list itself. Fixed tabs (`closable: false`, no `newTab`) make a segmented control; panels are kept alive (each tab keeps its components, scroll and inputs) — `keepAlive={false}` renders only the active one.

## In the title bar

The window's own bar goes in the root layout. Its tabs are places in your app (`route`): each one has a `path`, and SvelteKit works as always — one page shown, the active tab's.

```svelte src/routes/+layout.svelte
<script lang="ts">
	import { Tabs, TabBar, TabContent } from '@svelte-desktop/shell/tabs';

	let { children } = $props();
</script>

<Tabs route primary newTab={() => ({ path: '/' })} title={(url) => titles[url.pathname] ?? 'Untitled'}>
	<header class="titlebar">
		<TabBar label="Open pages" />
	</header>
	<TabContent>{@render children()}</TabContent>
</Tabs>

<style>
	.titlebar {
		height: max(var(--desktop-titlebar-height, 0px), 2.75rem);
		padding-left: max(var(--desktop-controls-width, 0px), 0.75rem); /* clear the traffic lights */
		--app-region: drag; /* its empty parts move the window */
	}
</style>
```

| You | The tabs |
| --- | --- |
| Click a tab | SvelteKit navigates to its `path` |
| Follow a link, `goto()`, the sidebar | The active tab follows: its `path` (and title) become the new URL |
| ⌘-click or middle-click a link | A new tab on it, in the background |
| ⌘T / the + button | `newTab()`, at the end, and it navigates there |
| Back / Forward | The browser's history, shared by the tabs |

Switching route tabs is a navigation: the page you leave is unmounted like on any SvelteKit navigation (keep what must survive in a store, or [snapshots](https://svelte.dev/docs/kit/snapshots)) — or isolate the tab. `primary` makes it the window's bar: the window title follows the active tab, the shortcuts and the Tab menu, ⌘-click on links, and the tabs are restored at launch. `bind:tabs` works here too, to read or drive the window's tabs.

With `titleBarStyle: 'hiddenInset'` the bar sits next to the traffic lights. Tabs and buttons stay clickable, the empty parts of the strip move the window, and a double-click on them zooms it.

| Shortcut | |
| --- | --- |
| ⌘T / the + button | `newTab()`, at the end |
| ⌘W | Close the active tab (the main window keeps its last one unless `newTab` replaces it) |
| ⇧⌘T | Reopen the last closed tab |
| ⌃⇥ / ⌃⇧⇥ | Next / previous tab |
| ⌘1 – ⌘8, ⌘9 | That tab, the last one |
| ⌘-click or middle-click a link | Open it in a new tab, in the background |
| Middle-click a tab | Close it |
| Drag a tab | Reorder (a line shows where it lands) |
| Drag a tab out of the window | Open it in its own window, right where it's let go — or, dropped on another window's tab bar, move it there |
| Tab › Move Tab to New Window | The same, from the menu |

The shortcuts are a **Tab** menu inserted before Window (⌘1–9 in its **Select Tab** submenu), so they show in the menu bar and win over the page — and over an isolated tab's web view. Only the focused window acts on them.

## Between windows

A route tab dragged out of the window opens in a new window of its own, where it's let go — with its title and your fields — and that window comes in animated (`windowAnimation`, see [Animation](/ui/windows#animation)). Dropped on another window's tab bar, it moves there. Each window has its own tabs: the main window's are restored at launch, a window a tab was dragged into closes when its last tab leaves.

The drag is native drag and drop ([pragmatic-drag-and-drop](https://atlassian.design/components/pragmatic-drag-and-drop/)): the system's drag image follows the pointer, beside it, out of the window and over other windows; a tab dropped on another window's bar is a real drop there, and leaves only once that window took it. Let go elsewhere in its own window (or Escape), nothing happens. `detachable` turns it off, or decides per tab (`detachable={(tab) => !tab.unsaved}`); `ondetach` tells you a tab left.

## Isolated tabs

A tab can live in **its own web view** — its own process — instead of the page: a page of another site (`url`, always isolated), or an app route kept apart (`isolated: true`). It shares the bar, the shortcuts and the restore; its title and address follow the page it shows; it stays alive while another tab is shown. It's decided per tab, in your list:

```ts
tabs.push({ id: 'docs', url: 'https://svelte.dev/docs', title: 'Svelte docs' }); // another site
tabs.push({ id: 'big', path: '/editor/42', isolated: true });                    // an app route, apart
```

(Or `useTabs().open({ … })` from a component inside `<Tabs>`.) `<TabContent>` shows the page for the route tabs and each isolated tab's web view in the same place; in state groups `<TabPanels>` does the same. Isolate a third-party page, a heavy document whose crash or memory must stay apart, or something that must keep its state or keep running — each one costs a web content process (40–100 MB). A page of another site can't call native APIs and receives none of the app's events.

A web view is drawn over the page: your page's popovers and dialogs can't cover an isolated tab. An app route isolated in its own view runs your app again, layout included: there the group's `embedded` is true — `<TabBar>` renders nothing, nothing is saved, no second menu — so render the page alone:

```svelte src/routes/+layout.svelte
<script lang="ts">
	let { children: page } = $props(); // <Tabs> has its own `children` snippet
</script>

<Tabs route primary newTab={() => ({ path: '/' })}>
	{#snippet children(tabs)}
		{#if tabs.embedded}
			{@render page()}
		{:else}
			<header class="titlebar"><TabBar /></header>
			<Sidebar />
			<TabContent>{@render page()}</TabContent>
		{/if}
	{/snippet}
</Tabs>
```

## Inside your components

Anything inside `<Tabs>` gets the group with `useTabs()`; the component that renders `<Tabs>` gets it as its `children` snippet's argument.

```svelte
<script lang="ts">
	import { useTabs } from '@svelte-desktop/shell/tabs';
	const tabs = useTabs();
</script>

<h1>{tabs.active && tabs.titleOf(tabs.active)}</h1>
<button onclick={() => tabs.open({ path: '/reports' })}>Reports</button>
```

The group: `items`, `activeId`, `active`, `embedded`, `window` (this window's label); `open(tab, { activate, index })` (an existing id is activated instead), `new()`, `activate(id)`, `close(id?)`, `closeOthers(id)`, `reopen()`, `cycle(1 | -1)`, `move(id, index)`, `update(id, patch)`, `get(id)`, `detach(id, at?)`; `titleOf(tab)`, `isIsolated(tab)`. Groups nest: an inner `<Tabs>` is the one its content sees.

## Styling

`<TabBar>` only lays out (zero-specificity styles). Style it with `class` and the state attributes, or render each tab yourself with the `tab` snippet:

```svelte
<TabBar class="my-tabs">
	{#snippet tab(t, { active, close })}
		<Icon name={t.icon} />
		<span>{t.title}</span>
		<button onclick={close} onmousedown={(e) => e.stopPropagation()}>×</button>
	{/snippet}
</TabBar>
```

| Selector | |
| --- | --- |
| `[role=tablist]` (`data-sd-tabbar`) | The bar; its `gap` spaces the tabs |
| `[role=tab]`, `[data-active]`, `[data-pinned]`, `[data-dragging]` | A tab and its states |
| `[data-sd-tab-drop]` | The line where a dragged tab lands (`--sd-tab-drop-color`, default `Highlight`) |
| `[data-sd-tab-title]`, `[data-sd-tab-close]` | The default content |
| `[data-sd-tab-new]` | The + button (when `newTab` is set) |
| `[role=tabpanel]` (`data-sd-tabpanel`) | A panel (`hidden` when inactive) |

Props are live: change `newTab`, `title`, `windowAnimation` or a callback and the next use takes it (`id` and `route` are read once). The [dashboard example](https://github.com/beynar/svelte-desktop/tree/bun-webview-shell/examples/dashboard) has the three looks — title-bar tabs, underline tabs with rename and +, and a segmented control.
