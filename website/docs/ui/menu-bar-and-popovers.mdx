---
title: Menu bar and popovers
description: Status items, routes in native popovers, and Spotlight-style panels on a global shortcut.
---

:::note
API reference: [`host.tray`](/host/input/tray), [`host.popover`](/host/windows/popover).
:::

A popover is **a route of your SvelteKit app** shown in a native macOS popover (with the arrow) or in a borderless translucent panel. It runs in its own web view with the same server, default web session, remote functions and `host` API as the main window. A full external URL uses `url` instead of `route` and gets no native bridge. On macOS, `session` can select a separate [profile](/host/web/sessions).

| Platform | Presentation |
| --- | --- |
| macOS | Native arrowed popover, or a borderless panel with system vibrancy |
| Linux | Borderless window; no native arrow or vibrancy |
| Windows | Borderless window; no native arrow or vibrancy |

## 1. Write the route

Put the popover routes in their own group, apart from the window's layout:

<FileTree>

- src/routes/
  - +layout.svelte
  - (app)/
    - +layout.svelte
    - +page.svelte
  - (popover)/
    - quick/
      - +page.svelte

</FileTree>

```svelte src/routes/(popover)/quick/+page.svelte
<script lang="ts">
  import PopoverContent from '@svelte-desktop/shell/platform/PopoverContent.svelte';
  import { addNote } from '$lib/data.remote';
</script>

<!-- transparent page, and the popover is sized to this content -->
<PopoverContent>
  <h3>Quick note</h3>
  <form {...addNote.enhance(async ({ submit }) => { await submit(); await host.broadcast('notes-changed'); })}>
    <input {...addNote.fields.text.as('text')} />
  </form>
  <button onclick={() => host.closePopover()}>Done</button>
</PopoverContent>
```

`PopoverContent` props: `fit` (`height`, the default, keeps the given width and follows the content height; `both` also uses the content width; `none`), `padding` (default `12px`), `class`. A route group does not replace the root `+layout.svelte`: the popover renders inside it too. Keep the root layout minimal and put the window chrome in `(app)/+layout.svelte`, such as a sidebar or header. [`<WindowTabs>`](/ui/tabs) in the root layout renders only the page inside a popover, so it is safe there.

## 2. Open it

### From the menu bar

```svelte src/routes/(app)/+layout.svelte
<script>
  import StatusItem from '@svelte-desktop/shell/platform/StatusItem.svelte';
</script>

<StatusItem icon="note.text" tooltip="Quick note" popover={{ route: '/quick', width: 320 }} />
```

```svelte
<StatusItem icon="note.text" popover="/quick" bind:open />                    <!-- route string -->
<StatusItem icon="bolt" style="panel" popover="/palette" position="tray" />     <!-- panel under the icon -->
<StatusItem icon="note.text" items={[{ label: 'Quit', role: 'quit' }]} />       <!-- a menu instead -->
<StatusItem icon="note.text" onClick={() => host.window.show()} />              <!-- plain click -->
```

On macOS, clicks toggle the popover natively, with no round trip through the page, and a click that just dismissed a transient popover is suppressed. `StatusItem` owns the app's single tray slot and removes it on unmount. Mount it once in the owner layout; do not also mount it inside each popover or kept-alive view.

A menu-bar-only app sets `trayOnly: true` (macOS only: no Dock icon, no app menu) and `window: false` or `window: { visible: false }` in `desktop.config.ts`. The main page still loads hidden, so it can own the status item. Set `quitOnLastWindowClosed: false` too if closing a visible window should keep the app running.

### Anchored to an element

```svelte
<script>
  import Popover from '@svelte-desktop/shell/platform/Popover.svelte';
  let button = $state(), open = $state(false);
</script>

<button bind:this={button} onclick={() => (open = !open)}>Emoji</button>
<Popover route="/emoji" anchor={button} bind:open width={260} height={120} edge="bottom" />
```

`<Popover>` takes the [popover options](#popover-options) below as props, plus `anchor` (an element, `'cursor'` or a rect), `shortcut` (a global hotkey that toggles it), `onShow` and `onHide`, and `bind:open`. `id` defaults to one derived from the route and style.

### A panel on a global shortcut

The shortcut works while the app is in the background:

```svelte
<Popover route="/palette" style="panel" position="center" shortcut="Ctrl+Alt+Space" width={520} />
```

### From code

```ts
await host.popover.create({ id: 'quick', route: '/quick', width: 320, tray: true });
await host.popover.show('quick', { anchor: 'cursor' });
await host.popover.toggle('quick');
await host.popover.hide('quick');
host.popover.onShown(({ id }) => {});
host.popover.onHidden(({ id }) => {});
```

`anchor` is `'tray'`, `'cursor'`, a rect in the page (`{ x, y, width, height }`, CSS px, e.g. from `getBoundingClientRect()`) or `{ screen: { x, y, width, height } }`. Other ops: `setSize`, `setPosition`, `isShown`, `get`, `list`, `eval`, `reload`, `destroy`, and the `onReady` and `onResized` events.

## Talking to the main window

Each popover is a separate page. Share state through:

- **the server**: remote functions hit the same Bun process and database;
- **native state**: reactive namespaces such as `host.theme.dark` receive native events; ordinary Svelte state and module globals remain local to each page;
- **broadcast**: `host.broadcast('channel', data)` and `host.onBroadcast('channel', fn)` reach every window, popover and server code.

Inside a popover, `host.currentPopover()` returns `{ id }`, `host.closePopover()` closes it, and every `host.popover` op that takes an `id` defaults to the current popover (`create()` and `list()` don't).

## Lifetime

Use distinct `id` values for independently owned popovers. Reusing an id replaces and destroys the old one. Hiding preserves page state; `destroy` releases the web view. See the [popover reference](/host/windows/popover) for platform details and all options.
