The main window is described by `window` in `desktop.config.ts` and controlled at run time through `host.window`.

```ts desktop.config.ts
window: { width: 960, height: 680, minWidth: 520, minHeight: 400, autosaveName: 'main', titleBarStyle: 'hiddenInset' },
```

`window: false` starts with no visible main window, for [menu-bar apps](/ui/menu-bar-and-popovers). `quitOnLastWindowClosed: false` keeps the app running when the last window closes, like most macOS apps: background work and push connections go on, and a Dock click, a notification click or a second launch shows the window again.

## At run time

```svelte
<h1>{host.window.title}</h1>
{#if host.window.fullscreen}<p>Full screen</p>{/if}
<button onclick={() => host.window.toggleMaximize()}>Maximize</button>
<button onclick={() => host.window.setTitle('Untitled')}>Rename</button>
```

`host.window` is reactive (`title`, `focused`, `maximized`, `fullscreen`, `bounds`, `size`, `position`, `state`, `scaleFactor`) and carries every window op:

| Group | Ops |
| --- | --- |
| Geometry | `setSize`, `setPosition`, `setBounds`, `center`, `positionTo(preset)`, `setMinSize`, `setMaxSize`, `getBounds`, `innerSize`, `outerSize` |
| State | `minimize`, `unminimize`, `maximize`, `unmaximize`, `toggleMaximize`, `restore`, `show`, `hide`, `focus`, `blur`, `close` |
| Full screen | `setFullscreen`, `toggleFullscreen`, `setSimpleFullscreen` (macOS, non-native) |
| Chrome | `setTitle`, `setTitleBarStyle`, `setDecorations`, `setResizable`, `setClosable`, `setMinimizable`, `setMaximizable`, `setHasShadow`, `setOpacity`, `setTheme` |
| Behavior | `setAlwaysOnTop`, `setAlwaysOnBottom`, `setVisibleOnAllWorkspaces`, `setMovable`, `setMovableByWindowBackground`, `setIgnoresMouseEvents`, `setContentProtected`, `setFocusable` |
| macOS document | `setDocumentEdited` (the dot in the close button), `setRepresentedFilename` (title bar document icon) |
| Misc | `requestAttention`, `showCharacterPalette`, `getControlsArea`, `setCursorHidden`, `setCursorPosition` |

`positionTo` presets: `center`, `trayCenter`, `trayLeft`, `trayRight`, `trayTop`, `trayBottom`, `cursorTopLeft`, `cursorBottomLeft`.

## Title bar styles

| `titleBarStyle` | macOS |
| --- | --- |
| `default` | The normal title bar. |
| `transparent` | The page extends under the title bar; the title stays. |
| `hidden` | The page extends under the title bar; traffic lights at the corner. |
| `hiddenInset` | Same, with the traffic lights inset. |

Your header takes the title bar's place. The shell sets CSS variables and attributes so it can line up with the window controls:

```css src/app.css
header {
  --app-region: drag;                                          /* or the data-desktop-drag attribute */
  min-height: max(var(--desktop-titlebar-height, 0px), 2.5rem);
  padding-left: max(var(--desktop-controls-width, 0px), 1rem); /* clear the traffic lights */
}
.search { --app-region: no-drag; }  /* carve out a region; links, buttons and inputs stay clickable anyway */
```

| Set by the shell | |
| --- | --- |
| `--desktop-titlebar-height` | Height of the title bar strip; `0` in full screen |
| `--desktop-controls-width` | Width taken by the window controls; `0` in full screen |
| `html[data-desktop-titlebar]` | Present with a hidden title bar; `fullscreen` while in full screen |
| `html[data-desktop-controls]` | `native` (macOS keeps its buttons) or `none` (the page draws its own) |

- **Drag regions.** Any element with `--app-region: drag` or the `data-desktop-drag` attribute drags the window. Double-click follows the system setting (zoom or minimize).
- **The title bar strip behaves like a title bar.** It drags the window whatever the page puts there (controls stay clickable; `--app-region: no-drag` opts an element out). Scrolling over it doesn't scroll the page, so title-bar gesture tools such as Swish keep working. A gesture is routed as a whole by where it began: one started in the page keeps scrolling.
- **Switch at run time** with `host.window.setTitleBarStyle(style)`.

### Linux and Windows

A hidden title bar there is a frameless window: there are no native buttons to keep, so `html[data-desktop-controls="none"]` tells the page to draw its own. Drag regions and double-click to maximize work the same.

```css
.window-buttons { display: none; }
:root[data-desktop-controls="none"] .window-buttons { display: flex; }
```

```svelte
<div class="window-buttons">
  <button onclick={() => host.window.minimize()}>–</button>
  <button onclick={() => host.window.toggleMaximize()}>□</button>
  <button onclick={() => host.window.close()}>×</button>
</div>
```

## No elastic overscroll

On desktop, the bridge sets `:where(html, body) { overscroll-behavior: none }`, with zero specificity, so the page doesn't rubber-band. Bring it back with `html { overscroll-behavior: auto }`, or set it per scroll container.

## Multiple windows

```ts
const { windowId } = await host.windows.create({ path: '/inspector', title: 'Inspector', width: 520, height: 420, animate: true });
await host.windows.setTitle('Inspector (2)', windowId);
host.windows.onClosed(({ windowId }) => console.log('closed', windowId));
```

Every window op takes an optional trailing `windowId`; without it the op targets the window whose page made the call (`0` is the main window). `host.windows.list()` returns `{ windowId, label, focused, visible, bounds }` rows, `host.windows.getInfo()` the calling window's own row, and `host.windows.get(label)` finds one.

## Animation

A window can come in animated each time it shows — at launch, `windows.create`, `window.show()`: `animate: true` fades it in while it slides down 10 points into place, in 180 ms. Or describe your own:

```ts
host.windows.create({
	path: '/inspector',
	animate: { duration: 260, easing: [0.2, 0.9, 0.1, 1], offset: { x: 0, y: 24 }, scale: 0.96, opacity: 0 },
});
```

## Confirm before closing

Arm the close veto: the red button and Cmd+W then emit `willClose` instead of closing.

```ts
await host.windows.setCloseVeto(true);
host.windows.onWillClose(async () => {
  const { response } = await host.dialog.showMessageBox({
    type: 'warning', message: 'Discard unsaved changes?', buttons: ['Discard', 'Cancel'],
  });
  if (response === 0) {
    await host.windows.setCloseVeto(false);
    await host.windows.close();
  }
});
```

## Saving the frame

`autosaveName` persists the main window's frame natively. For more control, `host.windowState` writes a JSON snapshot (`window-state.json` in the app's data directory). It uses Bun's file API, so call it from server code:

```ts
await host.windowState.save({ flags: ['size', 'position', 'maximized'] });
await host.windowState.restore(); // applies what the snapshot captured
```

Flags: `size`, `position`, `maximized`, `visible`, `fullscreen` (default: all).
