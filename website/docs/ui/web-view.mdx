`host.webview` controls the web view of a window, popover or embedded view. Unless a section says "server code", the calls below work from page code and from the server. They act on the page that made the call by default; pass a target (`{ windowId }`, `{ popoverId }` or `{ viewId }`) to act on another one. The [webview reference](/host/web/webview) has the target rules and per-method platform support. Most of this page is macOS; Linux and Windows use their web engine's behavior where the shell has no integration.

## Built-in behavior

| Web feature | In the app |
| --- | --- |
| `alert`, `confirm`, `prompt` | Native sheets that never block the run loop. Each emits `jsDialog`. |
| `<input type="file">` | A native open panel, filtered by `accept` (folders with `webkitdirectory`). |
| `getUserMedia`, `navigator.geolocation`, `SpeechRecognition` | Allowed on the app origin, then OS consent. Other origins need a [policy](#web-permissions). |
| `getDisplayMedia` | Allowed on the app origin, then Screen Recording consent: if it's missing, the first attempt is denied while macOS asks. Other origins need a [policy](#web-permissions). |
| `Notification` | The app's notifications (`host.notifications`). |
| `window.open`, external links | Open in the default browser. |
| `window.close()` | Closes the window, respecting the close veto; in a popover it emits `closeRequested`. |
| `window.print()` | The native print panel. |

The reasons in the OS prompts are defaults; set your own, or turn one off with `false`, in [`permissions`](/features/permissions).

## File drop

The page keeps its normal DOM drag events with `File` objects. The shell adds the real paths, which the DOM can't expose (macOS and Linux; on Linux the DOM event's `files` is empty):

```ts
host.webview.onFileDrop(({ paths, x, y }) => importFiles(paths)); // x, y in CSS px
host.webview.onFileDragEnter(({ paths }) => (dragging = true));
host.webview.onFileDragLeave(() => (dragging = false));
```

Call `preventDefault()` on the DOM `drop` event as usual. `host.webview.setFileDrop({ enabled: false })` turns the native path events off.

## Downloads

`<a download>`, attachments and responses the web view can't display are saved to the download directory (`~/Downloads` by default) under a unique name. Start one yourself and follow it:

```ts
const { id } = await host.webview.download('/export.csv'); // uses the page's cookies
host.webview.onDownloadProgress(({ id, fraction }) => (progress = fraction));
host.webview.onDownloadFinished(({ path }) => host.shell.showItemInFolder(path));
```

To choose the destination, install one app-wide handler and return `{ path }`, `'cancel'` or `'default'`. Await the installation before starting a download:

```ts
const stop = await host.downloads.onRequested(async ({ suggestedFilename }) => {
  const { canceled, path } = await host.dialog.showSaveDialog({ suggestedName: suggestedFilename });
  return canceled || !path ? 'cancel' : { path };
});
```

`host.downloads` also lists records (history survives relaunches) and pauses, resumes and cancels transfers: `pause(id)`, `resume(id)`, `cancel(id)`, `list()`. See the [downloads reference](/host/web/downloads) for the record shape, resume behavior and timeouts.

## Print and PDF

```ts
const printers = await host.webview.getPrinters();          // names, possibly []
await host.webview.print();                                // the panel
await host.webview.print({ printer: printers[0], copies: 2, silent: true });
await host.webview.printToPDF('/Users/me/notes.pdf', {
  pageRanges: [{ from: 2, to: 3 }],      // one-based, inclusive
  paperSize: { width: 595, height: 842 }, // points, about A4
  orientation: 'portrait',
  margins: { top: 36, right: 36, bottom: 36, left: 36 },
});
```

Omit `printer` for the system default. `pdfPath` on `print` saves a PDF silently. Invalid options reject before a job starts, and failed or canceled jobs reject with `unavailable`. The view must be attached to a window. The extended options work on all three; see the [reference](/host/web/webview#printoptions) for limits on copies, ranges and margins.

## Find and zoom

```ts
const { matchFound } = await host.webview.find({ text: 'todo', caseSensitive: false });
await host.webview.clearFind();
await host.webview.setZoom(1.25); // clamped to 0.25 to 5
```

`find` works on macOS and Linux; zoom works on all three.

## Context menu

```ts
await host.webview.setContextMenu({ mode: 'custom', items: [{ id: 'paste-plain', label: 'Paste as Plain Text' }] });
```

| `mode` | |
| --- | --- |
| `none` | The production default: no menu, except Cut, Copy, Paste and spelling suggestions on editable text or a selection (`editMenu: false` removes those too). |
| `default` | WebKit's own menu (the default in debug views). |
| `custom` | Your items, which fire `menuAction`, with the edit items above them when editing. |

Whatever the mode, `onContextMenu` reports `{ x, y, linkURL, srcURL, selectionText, editable }`, and a page can `preventDefault()` its own `contextmenu` event and call `host.menu.popup`. Windows supports only `none` and `default`. See [`setContextMenu`](/host/web/webview#setcontextmenuoptions) for `all`.

## Sound and media

```ts
await host.webview.setAudioMuted(true);  // sound off; the page keeps playing
await host.webview.pauseMedia();         // every audio and video paused
const media = await host.webview.getMediaState(); // { audible, muted, playback, camera, microphone }
```

macOS only.

## Website data

Clear what other sites stored in the default session: cookies, `localStorage`, IndexedDB, caches and so on.

```ts
await host.webview.clearData();                                  // everything, other sites only
await host.webview.clearData({ types: ['cookies'] });            // only their cookies
const { cleared } = await host.webview.clearData({ app: true }); // the app's own storage too
```

The app's own cookies are always kept: they hold its session with its server. Named profiles aren't cleared. To remove individual cookies, use [`host.sessions.cookies`](/host/web/sessions#cookiesgetfilter). macOS only.

## Scripting and capture

```ts
const title = await host.webview.executeJavaScript<string>('document.title'); // JSON result
const { data } = await host.webview.capturePage({ format: 'jpeg', quality: 0.8 }); // base64 image
```

Also: `reload`, `stop`, `goBack`, `goForward`, `getInfo`, `setUserAgent`, `setInspectable`, and `respondToDialog` / `getDialog` to answer an open JavaScript dialog from automation.

## Embedded views

`host.view` embeds extra web views in a window, like Electron's `BrowserView`: an app route or any URL, at CSS-pixel bounds from the window content's top-left corner. External content can't call native APIs.

```ts
await host.view.create({ id: 'preview', url: 'https://svelte.dev', bounds: { x: 240, y: 0, width: 600, height: 400 }, autoresize: 'both' });
await host.view.navigate('preview', { route: '/help' });
host.view.onTitle(({ id, title }) => {});
await host.view.destroy('preview');
```

Views belong to their window and are destroyed when it closes. Reusing an `id` replaces the view; `hide` keeps it alive and `destroy` releases it. Pass `hidden: true` at `create` to load a view out of sight until `show`. Linux and Windows support `host.view` too, but `host.webview` doesn't resolve a `viewId` there: use `host.view` methods. See the [view reference](/host/windows/view).

## Lifecycle and recovery (macOS)

`onLifecycle` reports full WebKit navigations (`navigationStarted`, `loaded`, `failed`, `terminated`); SvelteKit client-side route changes don't count. By default a view whose web process dies reloads at its last URL, losing in-memory state, [a limited number of times](/concepts/architecture#when-something-crashes). Create it with `recovery: 'manual'` to handle that yourself, from another page or the server, since the dead page can't:

```ts
const off = host.webview.onLifecycle(async (event) => {
  if (event.type === 'failed') console.log(event.viewId, event.domain, event.code);
  if (event.type === 'terminated' && event.recovery === 'manual') {
    await host.webview.reload({ viewId: 'preview' });
  }
});
```

See [`onLifecycle`](/host/web/webview#events) and [`setRecovery`](/host/web/webview#setrecoveryrecovery-target) for the event fields.

## Sessions and private profiles (macOS, Linux)

A named profile gives a window, popover or view its own cookies and storage. Choose it when you create the view; it can't change afterward.

```ts
await host.sessions.create({ id: 'account-two', persistent: false });
await host.view.create({
  id: 'account-preview', session: 'account-two', route: '/',
  bounds: { x: 0, y: 80, width: 600, height: 400 }
});
await host.sessions.cookies.set({ session: 'account-two', url: 'https://example.com', name: 'login', value: 'x' });
await host.view.destroy('account-preview');
await host.sessions.remove('account-two');
```

Create profiles after the main app has authenticated: the app's session cookie is copied in so app routes stay authenticated. A profile isn't a sandbox for untrusted app code. Persistent named profiles and per-profile proxies (`host.sessions.setProxy`) need macOS 14 on macOS. See the [sessions reference](/host/web/sessions) for cookies, proxies and removal rules. Windows manages the cookies of the default profile, without named profiles or proxies.

## Native input policy (macOS, Linux)

Declare window-local shortcuts before WebKit and the menu see the keys:

```ts
await host.webview.setInputPolicy({
  intercept: [{ key: 'k', modifiers: ['meta', 'shift'] }],
  menuShortcuts: false, // menu accelerators off for this window, e.g. while an editor has focus
});
const off = host.webview.onBeforeInput((event) => {
  if (event.windowId === 0 && event.type === 'keyDown') openCommandPalette();
});
// On editor blur or component cleanup, restore normal behavior:
await host.webview.setInputPolicy({});
off();
```

Intercepted keys are consumed natively; `onBeforeInput` is told afterwards and can't prevent them. Use normal DOM listeners for ordinary editing. See [input policy](/host/input/input-policy) for key names and modifiers.

## Web permissions

Pages on other origins can't use the camera, microphone, location or screen unless **server code** allows it:

```ts src/hooks.server.ts
host.ready(async () => {
  await host.webview.setPermissionHandler(({ origin, permission }) =>
    origin === 'https://meet.example' && permission === 'microphone' ? 'allow' : 'deny'
  );
});
```

Without a handler, only the app origin is allowed. Once installed, a handler answers for your app's own origin too, so allow what your own pages use. `allow` still needs usage descriptions and OS consent. See the [web policy reference](/host/web/web-policy) for saved decisions and frame checks. macOS and Windows.

## Authentication challenges and TLS (macOS)

HTTP authentication and certificate decisions are also server code. Credentials go to the server only, never to pages:

```ts
host.ready(async () => {
  await host.webview.onAuthChallenge(async (challenge) => {
    if (challenge.origin === 'https://intranet.example' && challenge.method === 'basic' && challenge.previousFailures === 0) {
      return { username: 'alice', password: await readPassword() };
    }
    return 'default';
  });
});
```

Check the exact origin and bound the retries before you supply credentials. To trust a known self-signed certificate, register its expected SHA-256 fingerprint with `host.webview.allowCertificate({ host, fingerprint })` before navigating; there is no wildcard or global bypass. Client certificates, `revokeCertificate` and the rest are in the [reference](/host/web/web-policy#onauthchallengehandler-options).

## Declarative request rules (macOS, Linux)

Block or modify requests with WebKit content-blocker rules, app-wide and not kept across launches:

```ts
await host.webview.setContentRules({
  id: 'privacy',
  rules: [{
    trigger: { 'url-filter': 'https://tracking\\.example/.*' },
    action: { type: 'block' }
  }]
});
await host.webview.removeContentRules('privacy');
```

The app's own documents and bridge are never blocked. To veto navigations in server code:

```ts
await host.webview.setNavigationPolicy(async ({ url }) =>
  new URL(url).hostname === 'unwanted.example' ? 'cancel' : 'allow'
);
```

Both are covered in [content rules and scripts](/host/web/web-content), along with user scripts and content worlds (`host.webview.scripts`). The navigation policy also works on Windows; the rest of this section is macOS and Linux.
