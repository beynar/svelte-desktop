## The default menu

Without any code, a macOS app gets this menu bar, so the usual shortcuts work in the web view. On Linux and Windows the default menu differs: set your own with `setAppMenu` below.

| Menu | Items |
| --- | --- |
| App name | About, Hide (Cmd+H), Hide Others (Cmd+Alt+H), Show All, Quit (Cmd+Q) |
| Edit | Undo, Redo, Cut, Copy, Paste, Select All |
| View | Reload (Cmd+R), Enter Full Screen (Cmd+Ctrl+F) |
| Window | Minimize (Cmd+M), Zoom, Close (Cmd+W) |

## Replacing the app menu

`host.menu.setAppMenu` builds the whole menu bar from named menus, from a page or server code. Call it once at startup: in the root layout's `onMount`, or inside `host.ready()` in `hooks.server.ts`. Item clicks arrive through `host.menu.onAction`.

```ts
await host.menu.setAppMenu([
  { name: 'Notes', items: [{ role: 'about' }, { type: 'separator' }, { role: 'quit' }] },
  { name: 'File', items: [{ id: 'new', label: 'New Note' }, { id: 'pin', label: 'Pin', checked: true }] },
  { name: 'Edit', items: [{ role: 'editMenu' }] },
  { name: 'Window', items: [{ role: 'windowMenu' }] },
]);
host.menu.onAction(({ id }) => { if (id === 'new') createNote(); });
```

:::warning
Replacing the menu drops the default Edit menu: without Cut, Copy, Paste and Select All, those shortcuts stop working in text fields. Keep `{ name: 'Edit', items: [{ role: 'editMenu' }] }`. Linux rejects the `*Menu` presets (`editMenu`, `windowMenu`...) and `visible`, `tooltip` and icons are macOS-only: see the [menu reference](/host/input/menu) for what each platform supports.
:::

| Item field | |
| --- | --- |
| `id` | Reported to `host.menu.onAction`. Items without a role or id report their label. |
| `label` | Text. Roles have a default label. |
| `type` | `action` (default), `separator`, `submenu`, `checkbox` or `radio` |
| `group` | Required for radio items; exclusive within this parent menu (macOS) |
| `visible`, `tooltip` | Visibility (default true) and native tooltip (macOS) |
| `submenu` | Nested items |
| `checked`, `enabled`, `disabled` | State; `enabled` takes precedence over `disabled` |
| `role` | A standard item (see below) |
| `icon` | `{ native: 'add' }` (an AppKit image name) or `{ path: './icon.png' }` |

Roles include `about`, `undo`, `redo`, `cut`, `copy`, `paste`, `pasteAndMatchStyle`, `selectAll`, `delete`, `minimize`, `zoom`, `close`, `quit`, `hide`, `hideOthers`, `front`, `reload`, `toggleDevTools`, `resetZoom`, `zoomIn`, `zoomOut`, `toggleFullscreen`, `help`. The preset roles `appMenu`, `fileMenu`, `editMenu`, `viewMenu` and `windowMenu` expand to a full standard submenu. A menu named `Window` becomes the macOS Windows menu: macOS adds its own items (Fill, Center, Move & Resize, the window list) and window tools such as Swish drive them. One named `Help` becomes the Help menu. Unknown roles reject with `invalid_args`.

:::note
Items take an `accelerator` (`'CmdOrCtrl+Shift+K'`; named keys `plus`, `space`, `tab`, `enter`, `backspace`, `delete`, `escape`, arrows and `F1`…).
:::

### Updating items

```ts
await host.menu.update({ id: 'pin', checked: false, text: 'Unpin', enabled: true });
const item = await host.menu.get('pin');    // current state, or null
const all = await host.menu.items();       // snapshot of the whole menu
```

`update` renames an item with `text`, not `label`. `host.menu.lastAction` holds the last activated id, reactively. Menu ids are app-wide; use distinct ids for items you need to update or handle independently. See the [menu reference](/host/input/menu) for platform support and the full role list.

### Radio groups (macOS)

```ts
await host.menu.insert({ name: 'Mode', items: [
  { id: 'mode-write', label: 'Write', type: 'radio', group: 'mode', checked: true },
  { id: 'mode-read', label: 'Read', type: 'radio', group: 'mode', tooltip: 'Read without editing' },
] });
await host.menu.update({ id: 'mode-read', checked: true, visible: true, enabled: true });
// mode-write is now unchecked. Clicking a radio item also selects it natively.
```

The last checked radio in an initial group wins. Checking an item through `menu.update`
unchecks its siblings in the same group; setting it false permits an empty selection.
Groups in different submenus are independent. Checkbox items toggle natively on activation.
These rules also apply to context, tray and Dock menus. `menu.update` also accepts `tooltip`.

### Menu lifecycle (macOS)

```ts
const offOpen = host.menu.onWillShow('document-actions', () => console.log('opened'));
const offClose = host.menu.onDidClose('document-actions', () => console.log('closed'));
await host.menu.popup({ id: 'document-actions', items: [{ id: 'rename', label: 'Rename' }] });
offOpen(); offClose();
```

Lifecycle ids default to the app menu's name (`MenuSpec.id` overrides it), a submenu
item's id or label, `context` for `popup`, `dock` for `setDockMenu`, and `tray` for
the status item's menu. `popup({ id, items })` and `setDockMenu(items, id)` allow an
explicit id. Use unique ids for independently live menus. `menu.closePopup(id)`
dismisses a tracking popup without input simulation.

The native `NSMenuDelegate` observes update, open and close. Callbacks arrive
asynchronously and do not delay opening while JavaScript runs; prepare state before
opening, or use `menu.update` to refresh an open menu. Lifecycle events and `closePopup` are macOS-only. On other backends, these
lifecycle subscriptions receive no events and `closePopup` rejects with `unsupported`.

### Extra menu bar entries

`host.menu.insert` adds one top-level entry without replacing the menu (before Window by default on macOS, appended on Linux and Windows); `host.menu.remove(name)` drops it. The `MenuBar` component does the same with a component lifecycle: it renders nothing, and unmounting removes the entry.

```svelte
<script>
  import MenuBar from '@kitop/shell/platform/MenuBar.svelte';
</script>

<MenuBar label="Tools" items={[
  { label: 'Refresh', icon: 'refresh', onClick: reload },
  { label: 'Mode', submenu: [{ label: 'Dark', onClick: () => host.theme.set('dark') }] },
  'separator',
  { label: 'Quit', role: 'quit' },
]} />
```

Without `items`, `onClick` makes a plain clickable bar entry. `index` sets the position. The entry is app-wide: mount its owner once, rather than in every window or kept-alive view. A plain clickable top-level entry is macOS-only; Linux and Windows turn it into a submenu containing one action.

## Context menus

Pop a native menu at the cursor or at a screen position (top-left origin). It always resolves `{ dismissed: true }`; the choice arrives through `host.menu.onAction`.

```ts
document.addEventListener('contextmenu', (e) => {
  e.preventDefault(); // suppresses the web view's own menu
  host.menu.popup({ items: [{ id: 'rename', label: 'Rename' }, { id: 'delete', label: 'Delete' }] });
});

host.menu.onAction(({ id }) => {
  if (id === 'rename') rename();
});
```

The web view's built-in menu is controlled separately with `host.webview.setContextMenu`. On macOS the production default is `none`: no menu, except editing items and spelling suggestions on editable text or a selection. `default` keeps WebKit's menu; `custom` shows your items. See [Web view](/ui/web-view#context-menu).

## Dock menu

The Dock menu is macOS-only:

```ts
await host.menu.setDockMenu([{ id: 'new-window', label: 'New Window' }]);
await host.menu.addRecentDocument('/Users/me/notes.md'); // the system's recent documents list
```

`addRecentDocument` also registers a recent document with the desktop on Linux and Windows.

## From server code: `desktop.menu.set`

The older server API takes the whole menu bar as `label`/`submenu` items. Prefer `host.menu.setAppMenu` for new code. Clicks on items with an `id` arrive as `menu` events in the server.

```ts src/hooks.server.ts
import { onDesktopReady } from '@kitop/shell/server';

onDesktopReady((desktop) => {
  desktop.menu.set([
    { label: desktop.appName, submenu: [{ label: `Quit ${desktop.appName}`, role: 'quit', accelerator: 'Cmd+Q' }] },
    { label: 'File', submenu: [{ label: 'New Note', id: 'new-note', accelerator: 'Cmd+N' }] },
    { label: 'Edit', submenu: [{ label: 'Copy', role: 'copy', accelerator: 'Cmd+C' }, { label: 'Paste', role: 'paste', accelerator: 'Cmd+V' }] },
  ]);
  desktop.on('menu', (e) => console.log('clicked', e.id));
});
```

An item is `{ label, id?, role?, accelerator?, enabled?, submenu? }` or `{ type: 'separator' }`.
