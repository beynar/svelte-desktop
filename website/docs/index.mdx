`@kitop/shell` turns a SvelteKit app into a native app without changing the app. SSR, remote functions, form actions, endpoints and `bun:sqlite` run in-process on Bun. The UI is the system web view: WKWebView on macOS, WebKitGTK on Linux, WebView2 on Windows. The build output contains a compiled app executable and the native libraries. On macOS, it is a signed, notarizable `.app` bundle.

```ts vite.config.ts
import { desktop } from '@kitop/shell/vite';
import { defineConfig } from 'vite';

// SvelteKit's own plugin, wired with the desktop adapter and dev mode.
// `remoteFunctions` is SvelteKit's option for `.remote.ts` files.
export default defineConfig({ plugins: [desktop({ experimental: { remoteFunctions: true } })] });
```

```ts desktop.config.ts
import { defineConfig } from '@kitop/shell/config';

export default defineConfig({
  appName: 'Notes',
  identifier: 'com.example.notes',
  window: { width: 960, height: 680, autosaveName: 'main' },
});
```

```sh
bunx --bun vite dev     # the real native window on the Vite server: HMR, Web Inspector, native APIs live
bunx --bun vite build   # macOS: .desktop/dist/<App>.app + .zip + .dmg (+ release/ for the auto-updater)
bun run test:desktop    # drive the real window from tests (against a build; `bun run test` in a `create` project)
```

## Why

- **Your app, unchanged.** No SPA rewrite and no IPC layer to design: load functions, remote functions and `+server.ts` endpoints keep working, served on a loopback port of its own behind a session-cookie gate.
- **Bun on the server side.** Server code has Bun's APIs, `bun:sqlite` and Node-API addons. Sidecars, persistent services and background jobs run in child processes.
- **The system web view.** No bundled Chromium. Menus, windows, dialogs and popovers are the OS's own.
- **One global for native features.** `host.clipboard.writeText()`, `host.notifications.show()`, `host.window.setTitle()`: the same object in page and server code, reactive in components.
- **Self-hosted push.** Remote notifications without an Apple account, through a Web Push compatible server you run.

## Compared

Hello-world app on macOS 26.5 (M4 Pro), all processes counted. Numbers from the [repository's benchmark](https://github.com/beynar/svelte-desktop/tree/main/packages/shell/bench): `bun bench.ts` in `packages/shell/bench`, results in `RESULTS.md`.

| | Bundle | Zip | Ready | Memory |
| --- | --- | --- | --- | --- |
| Electron 45 | 258 MB | 115 MB | 303 ms | 88–149 MB |
| Tauri 2.12 | 4 MB | 1.8 MB | 313 ms | 75–170 MB |
| Electrobun 2.0 | 31 MB (187 MB installed) | 31 MB | 396 ms | 86 MB |
| kitop, Bun stable | 86 MB | 39 MB | 378 ms | 87 MB |
| kitop, `--aot --trim` (Bun canary) | 45 MB | 19 MB | 334 ms | 85 MB |

- **Electron** ships Chromium and Node; you write the main process and IPC yourself. kitop is 3 to 6 times smaller and runs your SvelteKit server unchanged.
- **Tauri** is about 10 times smaller (no bundled server JavaScript runtime). kitop keeps SSR and server code in TypeScript on Bun, with Rust, Go, Swift, Objective-C, C, C++ or Node-API for native code.
- **Electrobun** also uses Bun and the system web view. kitop provides SvelteKit SSR end to end and signed update manifests with archive integrity checks.
