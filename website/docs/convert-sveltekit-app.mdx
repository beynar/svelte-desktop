Your SvelteKit app stays a website and becomes a desktop app as well, from the same code, with one plugin added. Routes, load functions, remote functions, form actions, endpoints and hooks stay as they are, and in the desktop app they run on Bun inside it.

```diff vite.config.ts
 import { sveltekit } from '@sveltejs/kit/vite';
+import { desktop } from '@kitop/shell/vite';
 import { defineConfig } from 'vite';

 export default defineConfig({
-  plugins: [sveltekit({ adapter: adapter() })],
+  plugins: [sveltekit({ adapter: adapter() }), desktop()],
 });
```

Then a flag chooses:

```sh
bun run dev                             # the website, as before
bun run dev --mac                       # a native window, with hot reload
bun run build                           # the website, with your adapter
bun run build --mac --windows --linux   # the desktop apps
```

The steps below make that change for you, then get the app running and built.

## Before you start

- **SvelteKit 3 and Svelte 5.** On SvelteKit 2, upgrade first: kitop doesn't run on it.
- **[Bun](https://bun.sh) 1.4 or newer.** You don't need to move your project to it, but the app's server code will run on it.
- **On macOS,** the Xcode command line tools (`xcode-select --install`). **On Linux or Windows,** see [Distribution](/shipping/distribution).
- **Your project committed in git,** so you can read what changes.
- **The package itself.** `@kitop/shell` isn't on npm yet. Until it is, build it from [the repository](https://github.com/beynar/svelte-desktop):

  ```sh
  git clone https://github.com/beynar/svelte-desktop
  cd svelte-desktop/packages/shell
  bun install && bun pm pack --destination /tmp
  ```

  Then, in the first step below, name the file it wrote (`/tmp/kitop-shell-<version>.tgz`) in place of `@kitop/shell`.

## Convert it

<Steps>
  <Step title="Install the packages">
    From your project's folder:

    ```sh
    bun add -d @kitop/shell @sveltejs/adapter-bun@1.0.0-next.2 @types/bun
    ```

    `adapter-bun` builds the desktop app, and yours keeps building the website. Name its version: the framework needs exactly this one. `@types/bun` keeps `svelte-check` and `tsc` working, since your config now loads code that runs on Bun.
  </Step>

  <Step title="Run init">
    ```sh
    bunx kitop init
    ```

    It does five things:

    - Writes `desktop.config.ts`, with your app's name.
    - Adds `desktop()` next to `sveltekit()` in `vite.config.ts`. Your options and your adapter don't move.
    - Sets the `dev` and `build` scripts to `kitop dev` and `kitop build`, and adds `test:desktop`, replacing any with those names.
    - Adds `.desktop` to `.gitignore`.
    - Writes a first test, `tests/app.test.ts`, if you have no `tests` folder. If you have one, `test:desktop` runs what's in it with `bun test`.

    **Check:** `git diff` shows that, and nothing else. If `init` warns that `svelte.config.js` sets an adapter, move it to `sveltekit({ adapter: … })`.
  </Step>

  <Step title="Name your app">
    Edit `desktop.config.ts`:

    ```ts desktop.config.ts
    import { defineConfig } from '@kitop/shell/config';

    export default defineConfig({
      appName: 'My Site',
      identifier: 'com.acme.mysite', // not com.example: change it now
      window: { width: 1024, height: 720, autosaveName: 'main' },
    });
    ```

    The identifier names your app to the OS and locates its data, so changing it later strands what users have saved. Use a domain you own. The [configuration page](/concepts/configuration) has the other options.
  </Step>

  <Step title="Check your setup">
    ```sh
    bunx kitop doctor
    ```

    Fix what's marked `✗`. Warnings are fine for now, such as a missing icon or `bridge.allow`: they matter when you ship.
  </Step>

  <Step title="Run it">
    ```sh
    bun run dev --mac     # or --windows, --linux: the OS you're on
    ```

    A native window opens on your app, with hot reload. The first run compiles the native shell, which takes a minute. A window only opens on its own OS, so `--windows` needs Windows.

    **Check:** your home page shows, and you can navigate, sign in and submit forms as you do in a browser. On a blank window, see [Troubleshooting](/reference/troubleshooting).
  </Step>

  <Step title="Fix what behaves differently">
    Most apps need little or nothing here. The usual ones:

    | If your app | Then |
    | --- | --- |
    | Reads `.env` at runtime through `$env/dynamic` | There's no `.env` on your users' machines. Use `$env/static` for what's public, and keep secrets on your own backend |
    | Calls an API from the page | It sees your app's `http://127.0.0.1` origin. Allow it in that API's CORS rules, or make the call from server code |
    | Uses a Node-only module | Server code runs on Bun, which supports most of them. Replace one that fails |
    | Signs in through OAuth | Use the [loopback or scheme flow](/features/oauth) |
    | Opens windows with `window.open` | They open in the default browser. Use [`host.windows`](/host/windows/windows) for windows of your app |

    [Adopting an existing app](/concepts/adopting) has the full list.
  </Step>

  <Step title="Build it">
    ```sh
    bun run build --mac   # several flags build one after the other
    ```

    `--mac` needs a Mac. `--windows` and `--linux` also build from another OS, through Docker.

    `bun run check` still works if your project has it. The first run writes `src/host.d.ts`, the types of `host`: keep it in git.

    **Check:** `.desktop/dist` has your app: a `.app`, a `.dmg` and a `.zip` on macOS; a folder, a `.tar.gz` and an AppImage on Linux. Open it. It runs without Vite, and what's stored in `localStorage` and your database stays between launches. `bun run test:desktop` opens the built app and checks that it shows a page.
  </Step>
</Steps>

That's a desktop app, and `bun run build` with no flag still builds your website. The app can't yet be shared with other people without a warning from their OS: [signing it](/shipping/distribution) is the next step for that.

## Deploy the website

Deploy it as you did. `kitop` needs Bun, so where your host runs Node, set its build command to `vite build`, which doesn't. `.desktop` and `desktop.config.ts` play no part in it, and nothing of the shell ships with the site.

## Use the desktop

Nothing above required any new code. When you want more than a browser gives you, `host` is a global in page and server code, with no import. On the website, and in a plain browser tab, `host.available` is `false` and any `host` call rejects, so check it in code they share. Do the same around a component that needs the desktop, such as `<StatusItem>`:

```svelte src/routes/+page.svelte
<script lang="ts">
  async function rename() {
    if (host.available) await host.window.setTitle('Invoices');
  }
</script>

<button onclick={rename}>Rename the window</button>
```
