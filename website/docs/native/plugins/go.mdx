A Go plugin runs inside the shell process, with a goroutine for each command call. Pick it for Go packages and concurrent I/O callable from both pages and SvelteKit server code. Use a [sidecar](/native/sidecars) for a separate process or an independently restartable Go runtime. Shared rules (names, errors, events, `bridge.allow`, dev restarts) are on [Plugins](/native/plugins); toolchains and builds per OS are on [Platforms](/native/plugins/platforms).

## Quick start

```sh
bunx svelte-desktop add go
```

This creates `native/go/go.mod` and `native/go/main.go`, with a `hello.go` command registered in `init()` and an empty `func main() {}`. It refuses to overwrite an existing `native/go`. Install Go 1.22 or later and a C compiler for cgo.

Only one Go plugin is allowed per app: either one module or all the loose `.go` files together. Two modules, or a module plus loose files, fail discovery, because the shell supports one Go runtime per process. Combine packages in one module. Loose files must be `package main`.

Keep the `go.mod` that `add go` wrote and replace `main.go`. The example hashes a document and reports progress; add your own dependencies to the module as usual.

```go native/go/main.go
package main

import (
    "crypto/sha256"
    "fmt"

    "svelte-desktop.dev/go/desktop"
)

type HashArgs struct {
    RequestID string `json:"requestId"`
    Text      string `json:"text"`
}

type Checksum struct {
    Hex   string `json:"hex"`
    Bytes int    `json:"bytes"`
}

type Progress struct {
    RequestID string `json:"requestId"`
    Bytes     int    `json:"bytes"`
}

func init() {
    desktop.Command("checksum.go", func(a HashArgs) (Checksum, error) {
        if a.RequestID == "" {
            return Checksum{}, desktop.InvalidArgs("requestId is empty")
        }
        hash := sha256.New()
        data := []byte(a.Text)
        for offset := 0; offset < len(data); {
            end := offset + 64*1024
            if end > len(data) {
                end = len(data)
            }
            if _, err := hash.Write(data[offset:end]); err != nil {
                return Checksum{}, err
            }
            offset = end
            desktop.Emit("checksum.progress", Progress{a.RequestID, offset})
        }
        desktop.Log("Go checksum complete")
        return Checksum{Hex: fmt.Sprintf("%x", hash.Sum(nil)), Bytes: len(data)}, nil
    })
    desktop.Command("checksum.ready", func(struct{}) (bool, error) {
        return true, nil
    })
}

func main() {}
```

After `vite dev` writes `native.checksum.go` to `src/native.d.ts`, call it from a page or server code:

```ts
import { native } from '@svelte-desktop/shell/native';
import { onPlatform } from '@svelte-desktop/shell/platform';

const requestId = crypto.randomUUID();
const off = onPlatform<{ requestId: string; bytes: number }>(
  'checksum.progress',
  (progress) => {
    if (progress.requestId === requestId) console.log(progress.bytes);
  }
);
try {
  const ready: boolean = await native.checksum.ready();
  const result = await native.checksum.go({ requestId, text: 'A saved document' });
  console.log(ready, result.hex, result.bytes);
} finally {
  off();
}
```

`host.native` and `host.on` are the same without imports. For large files, pass a validated path and stream it in Go. Command names are shared across languages: if you combine this with the Rust example, register `checksum.ready` in only one.

## Type mapping

Go uses `encoding/json`: exported struct fields with `json` tags. Arguments arrive as a JSON object; use `struct{}` for none. Missing fields keep their zero values and unknown fields are ignored, so validate required values in the handler. The SDK reflects the types given to `Command`; it doesn't read your source or run handlers.

| Go type or field | Generated TypeScript |
| --- | --- |
| `bool`, `string` | `boolean`, `string` |
| Signed/unsigned integers and floats | `number` |
| `*T` | The type of `T`, with `\| null` |
| Slices and arrays | Element arrays; byte collections are described as `string` |
| Maps | `Record<string, ValueType>` |
| `time.Time` | `string` |
| Structs | Objects with exported fields; `json` names honored, `json:"-"` omitted |
| `omitempty` or `omitzero` tags | Optional properties |
| Anonymous untagged struct fields | Flattened fields |
| Unsupported kinds, or nesting deeper than eight levels | `unknown` |

Custom `MarshalJSON`, `json:",string"`, fixed byte arrays, nil slices and maps, and embedded pointers aren't fully modeled. Use simple JSON shapes and check `src/native.d.ts`. Keep integers within JavaScript's exact range, or use strings.

## SDK API

Import `svelte-desktop.dev/go/desktop`.

| Public item | Contract |
| --- | --- |
| `Command[A, R](name, f func(A) (R, error))` | Registers `service.op`; call it from `init()`. Decodes JSON into `A` and marshals `R`. |
| `Error` | Struct with `Code` and `Message`. Return a pointer, such as `&desktop.Error{Code: "internal", Message: "failed"}`. |
| `InvalidArgs`, `Unsupported`, `Unavailable`, `Denied` | `fmt.Sprintf`-style constructors returning `*Error` with that code. There is no `Internal`: return an ordinary error. |
| `Emit(event, data)` | Broadcasts JSON from any goroutine. Sends nothing on a marshal error. |
| `Log(message)` | Writes a line through the shell. |

Register in `init()`, not `main()`: this is a `c-shared` library. A name without a dot panics. `init()` also runs when the build reads the commands, so keep it to registration.

## Errors and panics

An unmarshal failure rejects with `invalid_args`. A returned `*desktop.Error` (also when wrapped, via `errors.As`) keeps its code and message; any other error is `internal`, and so is a result marshal failure. A panic on the command goroutine is recovered as `internal`. Not recovered: panics in goroutines you start, during package initialization, fatal runtime errors and process exit. Use a sidecar if a crash mustn't end the app.

## Goroutines and events

Each call runs on its own goroutine, scheduled by the Go runtime, not on the Bun Worker. Concurrent calls to one command can overlap: protect shared state. A command returns `(R, error)` when its work ends; block in the handler and send progress with `Emit`. There is no cancellation context, timeout or concurrency limit; coordinate any goroutines you start yourself.

The SDK can't run code on the UI thread or touch windows: emit an event, and let the page or server act on it.

## Dev and build

`vite dev` builds the host architecture with `go build -buildmode=c-shared` into `.desktop/dev/native/`; `vite build` also strips the library. Loose files are combined into a module in `.desktop/native-projects/go/`, recreated on each build, so don't keep your own files there. Go plugins build only on a host of the target OS; see [Platforms](/native/plugins/platforms) for paths, targets and signing.
