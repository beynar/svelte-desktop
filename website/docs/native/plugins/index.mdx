A plugin adds native commands that pages and SvelteKit server code call the same way. Pick plugins when both need the same native API, or when code must run on the UI thread. For a server-only library, use an [addon](/native/addons). For process isolation, use a [sidecar](/native/sidecars) or [service](/native/services).

## Add a plugin and call it

Add one with the CLI, then edit the generated source:

```sh
bunx svelte-desktop add rust    # or go, python
```

Swift, Objective-C and C/C++ plugins are plain files under `native/`. Each language page has a complete example: [Rust](/native/plugins/rust), [Go](/native/plugins/go), [Python](/native/plugins/python), [Swift](/native/plugins/swift), [Objective-C, C and C++](/native/plugins/objective-c-and-c).

Every command is named `service.op`. Call it from a page or server code:

```ts
import { native } from '@svelte-desktop/shell/native';

const stats = await native.text.stats({ text: 'Hello from the app' });
const again = await host.native.text.stats({ text: 'Another call' }); // same object
```

Arguments and results cross the bridge as JSON; omitted arguments become `{}`. A failure rejects with `NativeApiError`. See the [`host.native` reference](/host/data/native).

## Generated types

`vite dev` (native window) and the macOS packager build the plugins and write their command signatures to `src/native.d.ts`. Keep the file in Git and don't edit it. Browser-only dev doesn't build plugins, and Linux and Windows packaging doesn't regenerate the file: generate it in native-window dev before shipping those targets. Removing every plugin doesn't clear an existing file.

| Commands | Type source |
| --- | --- |
| Rust | The SDK's `TS` declarations. |
| Go | The reflected argument and result types. |
| Python | The functions' annotations. |
| Typed Swift | `Decodable` arguments and results; unsupported shapes can become `unknown`. |
| Untyped Swift, Objective-C and raw C/C++ | `args?: Record<string, unknown>` and `Promise<unknown>`. |

To read the commands, the build loads each library in a subprocess without a running app. Keep setup limited to registration. A library that can't be loaded there is left out of the types.

## Names and collisions

Use one dot between a non-empty service and operation, such as `text.stats`, both valid TypeScript identifiers. Avoid `then` for either. Names share one registry with the built-in operations: a plugin can't override a built-in or an earlier plugin's name, and the rejected registration is logged. Choose an app-specific service name.

## Errors

| Code | Meaning |
| --- | --- |
| `invalid_args` | The handler cannot accept the arguments. |
| `unsupported` | The operation is not supported, or is missing in a known service. |
| `unavailable` | A required resource is unavailable. |
| `denied` | Access was refused, including a page call blocked by `bridge.allow`. |
| `internal` | An unexpected handler, encoding or transport failure. |
| `unknown` | No registered service has that name. |

Rust, Go and Python turn handler panics and exceptions into `internal`; Swift turns thrown errors into rejections. Raw C/C++ handlers must reply exactly once. There is no call timeout or cancellation. A native crash ends the shell process, so use a separate process when you need isolation.

## Events

Plugins emit events with `svelte_desktop::emit` (Rust), `desktop.Emit` (Go), `emit` (Python), `Desktop.emit` (Swift), `SDEmit` (Objective-C) or the C host's `emit`, from any thread. Every app-origin page and the server receive them; replies go only to the caller.

Use an object payload. Other JSON values arrive as `{ value: ... }`. Event payloads aren't in `src/native.d.ts`: the listener supplies the type. Include a request ID when calls run concurrently.

```ts
const off = host.on<{ count: number }>('counter.changed', ({ count }) => {
  console.log(count);
});
off(); // dispose when the owner goes away
```

Events emitted during plugin setup fire before pages load and the server is listening, so don't use them as a startup handshake. See [events](/host/data/events).

## Page access

Page calls go through the same bridge policy as built-in operations:

```ts desktop.config.ts
import { defineConfig } from '@svelte-desktop/shell/config';

export default defineConfig({
  appName: 'Example',
  identifier: 'com.example.plugins',
  bridge: { allow: ['text.*', 'counter.read'] }
});
```

Without `bridge.allow`, pages can call every operation. With it, only matching `service.op` or `service.*` entries; `[]` permits none. Server calls aren't restricted. This is a page-call policy, not a sandbox around native code. See [configuration](/reference/config).

## Source discovery

The source root is `native/` if it exists. Set `native` to another path, or `false` to disable plugins.

```text
native/
  macos/              Swift, Objective-C or macOS C/C++
  linux/              Linux-only sources
  windows/            Windows-only sources
  text.rs             one Rust plugin
  rust/               a Cargo.toml crate
  go/                 a go.mod module
  python/             Python commands (a uv project)
  addons/             Node-API addons, not plugins
  sidecars/           not plugins
```

- `.swift`, `.m`, `.mm`, `.c`, `.cc` and `.cpp` files, anywhere under the root, form one library per app. Headers aren't compiled.
- A folder with `Cargo.toml` is one Rust plugin; each loose `.rs` file is its own crate.
- A folder with `go.mod`, or all the loose `.go` files together, is the Go plugin. Only one Go plugin is allowed per app.
- `addons/`, `sidecars/`, `python/`, `target/`, `node_modules/` and dot directories are skipped by the C-family scan, as are Rust and Go project folders.
- Keep `macos/`, `linux/` and `windows/` directly under the root: a target gets the shared sources plus its own folder. See [platforms](/native/plugins/platforms).

`sidecars/` is only excluded here; executables still need a `sidecars` config entry.

## Dev loop

With the native window on, `vite dev` builds the plugins for the host architecture (Rust and Go in debug) and opens the window. SvelteKit code runs in the Vite process and reaches the native side over a token-protected loopback connection.

Saving an existing file under the native root rebuilds the plugins, regenerates the types and restarts the shell process and window. This is a restart, not a hot reload: native and page state are lost. Ordinary Svelte edits use Vite HMR. The restart ignores `target/`, `Cargo.lock` and `go.sum`, and doesn't fire when you add or remove a native file: restart dev, and delete that plugin's output under `.desktop/dev/native/` if it keeps loading the old library. The C-family cache doesn't track headers in your own source tree, so the same applies after a header-only edit. Python restarts only its own process when its commands don't change; see [Python](/native/plugins/python#dev-and-build).

Build errors are logged and the window starts with the plugins that built. A `desktop.config` change restarts Vite.

## Production and startup

The packager builds one library for the C-family sources, one per Rust project or loose file, one for Go, and `libapp-python` for Python commands, and copies them next to the shell library. Paths, signing and what can be built where are in [platforms](/native/plugins/platforms).

At startup the shell loads the C-family library, then the libraries in `plugins/` in sorted order. Each `sd_plugin_init` runs on the UI thread before the run loop starts. Load failures are logged and startup continues; a loaded library doesn't guarantee that every command registered.

## Threads by language

| Language | Handler runs on | Replying and events |
| --- | --- | --- |
| [Rust](/native/plugins/rust) | A new OS thread per call. | Return a result or error; `emit`. |
| [Go](/native/plugins/go) | A goroutine per call. | Return a result or error; `desktop.Emit`. |
| [Python](/native/plugins/python) | A pool of 8 threads (`def`) or one asyncio loop (`async def`), in a separate Python process. | Return or raise; `emit`. |
| [Swift](/native/plugins/swift) | A `Task` on `MainActor`; may `await`. | Return or throw; keep blocking work off `MainActor`. |
| [Objective-C](/native/plugins/objective-c-and-c) | The UI thread. | Call the reply once from any thread; `SDEmit`. |
| [C and C++](/native/plugins/objective-c-and-c#the-c-abi) | The UI thread. | Schedule work yourself; `resolve`, `reject` and `emit` work from any thread. |

Everything but Python runs in the shell process, separate from the Bun server Worker. Window and webview handles stay on the UI thread. See [threads and processes](/native/threads).
