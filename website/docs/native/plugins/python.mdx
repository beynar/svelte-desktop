Python commands run in one Python process that the app starts and owns. Pick Python for its libraries: data work (numpy, pandas, polars), local models (torch, transformers, onnxruntime, mlx), or Python code you already have. Pages and server code call them through `host.native`. A packaged macOS app ships its own CPython and dependencies, so users install nothing. Packaged apps with Python commands are macOS only (see [Dev and build](#dev-and-build)). Shared rules (names, errors, events, `bridge.allow`) are on [Plugins](/native/plugins).

## Quick start

```sh
bunx kitop add python
```

This creates `native/python/` with a `pyproject.toml` and `hello.py`, which defines `hello.python`. Put your modules in that folder. Replace the generated `dependencies = []` in `pyproject.toml` with your own (for the example below, `["numpy>=2"]`), or run `uv add <package>` from the folder.

Install [uv](https://docs.astral.sh/uv/) on the build machine; it creates the environment. Commit `uv.lock` so builds install exactly those versions. Without `pyproject.toml`, commands run on the standard library alone (Python 3.12, or the version in `.python-version`). The SDK needs Python 3.10 or later.

```python native/python/stats.py
from dataclasses import dataclass

import numpy as np
from kitop import InvalidArgs, command, emit


@dataclass
class Summary:
    mean: float
    std: float
    count: int


@command("stats.summary")
def summary(values: list[float], trim: float = 0) -> Summary:
    if not values:
        raise InvalidArgs("values is empty")
    a = np.sort(np.array(values))
    cut = int(len(a) * trim)
    if cut:
        a = a[cut:-cut]
    return Summary(mean=a.mean(), std=a.std(), count=len(a))


@command("stats.progress")
async def progress(steps: int) -> int:
    for n in range(1, steps + 1):
        emit("stats.step", {"n": n, "of": steps})
    return steps
```

After `vite dev` starts, `src/native.d.ts` declares both commands:

```ts
const off = host.on<{ n: number; of: number }>('stats.step', (s) => console.log(s.n, '/', s.of));
const { mean, std, count } = await host.native.stats.summary({ values: [3, 1, 4, 1, 5], trim: 0.2 });
await host.native.stats.progress({ steps: 3 });
off();
```

`native` from `@kitop/shell/native` is the same object. Command names are shared with the other plugins: two languages can't register the same `service.op`.

## Type mapping

The build imports the modules and reads each signature. Parameters become the argument object; a function without parameters takes none.

| Annotation | TypeScript |
| --- | --- |
| `str`, `bytes`, `datetime`, `date`, `time`, `UUID`, `Path` | `string` |
| `int`, `float`, `Decimal` | `number` |
| `bool`, `None` | `boolean`, `null` |
| `list[T]`, `set[T]`, `Sequence[T]`, `tuple[T, ...]` | `T[]` |
| `tuple[A, B]`, `NamedTuple` | `[A, B]` |
| `dict[str, T]`, `Mapping[str, T]` | `Record<string, T>` |
| `X \| Y`, `Optional[X]` | `X \| Y`, `X \| null` |
| `Literal["a", "b"]`, `Enum` | Unions of literals |
| `TypedDict` (`Required`, `NotRequired`, `total`) | Objects with optional fields |
| Dataclasses, pydantic models | Objects; in arguments, fields with defaults are optional |
| `Any`, no annotation, recursive types, other classes | `unknown` |

An annotation that can't be resolved makes that command's types `unknown`.

The argument object becomes keyword arguments: `summary({ values, trim })` calls `summary(values=..., trim=...)`. A parameter with a default is optional. A missing or unknown argument rejects with `invalid_args`, unless the function takes `**kwargs`. A dict for a dataclass or pydantic parameter is built into that class (a refused field is `invalid_args`); other values arrive as JSON gives them, unchecked.

Results are encoded to JSON:

| Python value | JSON |
| --- | --- |
| `dict`, `list`, `tuple`, `str`, `int`, `float`, `bool`, `None` | As is. `NaN` and infinities become `null`. |
| Dataclasses, pydantic models (`model_dump(mode="json")`) | Objects |
| `Enum` | Its value |
| `set`, `frozenset`, generators and other iterables | Arrays |
| `Path`, `UUID`, `datetime` | Strings (`datetime`, `date`, `time` as ISO 8601) |
| `Decimal`, `bytes` | Numbers, Base64 strings |
| numpy arrays and scalars, torch tensors (`tolist()`, `item()`) | Arrays and numbers |

## SDK API

Import `kitop`. Point your editor at `.desktop/python/venv` to resolve the import.

| Public item | Contract |
| --- | --- |
| `@command("service.op")` | Registers the function. Names are letters, digits, `_` and `-`, with one dot. A duplicate raises at import. |
| `emit(event, data=None)` | Broadcasts JSON `data` from any thread. Event names: letters, digits and `_ . : / -`. |
| `log(message)` | Writes a line in the app's log. |
| `Error(message, code=None)` | Rejects the call with its code (`internal` by default). |
| `InvalidArgs`, `Unsupported`, `Unavailable`, `Denied` | `Error` subclasses with the matching code. |

The app imports every top-level `.py` file of `native/python/` at startup; modules import packages. `test_*.py`, `*_test.py`, `conftest.py`, `setup.py` and names starting with `_` are skipped. Keep module-level code to imports and setup: it also runs when the build reads the commands.

An `Error` rejects with its code and message. Any other exception rejects with `internal` and `ExceptionType: message`, with the traceback in the log.

## The Python process

The Python process runs apart from the shell: a crash in Python or an extension module doesn't take the app down, and the GIL never blocks the window. It starts with the app, so it boots while the page loads. It has no access to windows or `host`: emit an event or return a result, and let the page or server act. See [Threads and processes](/native/threads).

**Concurrency.** `def` handlers run on a pool of 8 threads (`KITOP_PYTHON_WORKERS` in the app's environment changes it). `async def` handlers run on one asyncio loop in its own thread. Calls overlap, so protect shared state. Pure-Python CPU work holds the GIL; numpy, torch and most native libraries release it.

**Output.** `print()` and other stdout or stderr output goes to the app's stderr: the `vite dev` terminal, or a packaged app's log file.

**Crashes and quitting.** The process exits at once when the app quits, and running handlers don't finish. When it exits otherwise, pending calls reject with `internal` and the next call starts a new process, with fresh state (loaded models, caches). If it fails before it is ready, typically on an `ImportError`, the rejection includes the last lines of its stderr.

**Startup time.** Heavy imports delay the first calls: import them inside the commands that need them.

## Dev and build

Modules run from `native/python/` in place. Saving a `.py` file, `pyproject.toml` or `.python-version` reads the commands again and syncs the dependencies:

- **Same commands:** only the Python process restarts, and the page keeps its state.
- **Commands added, removed or renamed:** the window restarts.

Pending calls reject at a restart.

`vite build` on macOS bundles a uv-managed CPython with your modules and dependencies in `Contents/Resources/python`, compiles them to bytecode and signs everything with the app. The standard library adds about 38 MB, plus your dependencies. Paths and signing: [Platforms](/native/plugins/platforms).

| Platform | Dev | Packaged |
| --- | --- | --- |
| macOS | Yes | Yes, one architecture: the build machine's |
| Linux | Yes (needs a C++ compiler) | No: the commands are missing from the package |
| Windows | No | No |

`build.universal` fails with Python commands: build arm64 and x64 separately, each on a machine of that architecture. GPU support is the libraries' own: torch uses Metal (MPS) on Apple silicon without extra setup.
