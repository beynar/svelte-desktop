Use Objective-C plugins for AppKit and other macOS frameworks. Use the C ABI for C/C++ libraries and platform-specific native work. **On macOS, write plugins in Objective-C or Swift:** the build supplies its own `sd_plugin_init`, so a raw C entry point works only on Linux and Windows. Handlers start on the shell's UI thread, in the shell process, so move blocking work to another thread. Shared rules (names, errors, events, `bridge.allow`, dev restarts) are on [Plugins](/native/plugins); per-OS support is on [Platforms](/native/plugins/platforms).

## Quick start: Objective-C

The shell supplies `native/include/SvelteDesktop.h` and `SvelteDesktop.m`, and the build adds the include directory. In a macOS source set with no Swift files, define one `SDSetup` function and register commands in it:

```objc native/macos/Files.m
#import "SvelteDesktop.h"
@import Foundation;

void SDSetup(void) {
  SDCommand(@"folder.count", ^(NSDictionary *args, SDReply reply) {
    id path = args[@"path"];
    if (![path isKindOfClass:NSString.class] || [path length] == 0) {
      reply(nil, SDError(@"invalid_args", @"path must be a non-empty string"));
      return;
    }
    NSString *directory = [path copy];
    dispatch_async(dispatch_get_global_queue(QOS_CLASS_USER_INITIATED, 0), ^{
      @autoreleasepool {
        NSError *error = nil;
        NSArray *files = [NSFileManager.defaultManager
          contentsOfDirectoryAtPath:directory error:&error];
        if (!files) {
          reply(nil, SDError(@"unavailable", error.localizedDescription));
          return;
        }
        NSNumber *count = @(files.count);
        SDEmit(@"folder.counted", @{@"count": count});
        reply(count, nil);
      }
    });
  });

  SDCommand(@"folder.windowTitle", ^(NSDictionary *args, SDReply reply) {
    (void)args;
    NSWindow *window = SDWindow(0);
    reply(window ? window.title : NSNull.null, nil);
  });
}
```

```ts
// In a page or server module
const off = host.on<{ count: number }>('folder.counted', ({ count }) => {
  console.log('Counted', count);
});
const count = await host.native.folder.count({ path: '/tmp' });
const title = await host.native.folder.windowTitle();
off();
```

The example copies the path before leaving the UI thread, calls the reply exactly once, and uses `SDWindow` only from a UI-thread handler.

| API | Behavior |
| --- | --- |
| `SDSetup(void)` | Your registration function, called by the supplied `sd_plugin_init`. |
| `SDCommand(name, handler)` | Registers `service.op`. The block gets an `NSDictionary` and an `SDReply`, and starts on the UI thread. |
| `SDReply(value, error)` | Reply once, now or later, from any thread. `nil` without an error resolves `null`; an error rejects. |
| `SDError(code, message)` | An `NSError` carrying the bridge code. Other errors are `internal` unless their `userInfo` has a `code`. |
| `SDEmit(event, data)` | Broadcasts a JSON event from any thread. Prefer dictionary payloads. |
| `SDWindow(windowId)` | A borrowed `NSWindow` or `nil`; UI thread only. `0` is the main window. |

### Type mapping

Objective-C results are `unknown` in generated TypeScript; narrow them in JavaScript. Arguments arrive as an `NSDictionary`, results are JSON values.

### Mixing sources on macOS

The build links `SvelteDesktop.m` only when there are no Swift sources. With Swift sources, `SvelteDesktop.swift` supplies the entry point and calls `desktopSetup` instead, so don't mix `SDCommand` and Swift setup. A loose C/C++ file defining its own `sd_plugin_init` collides with the supplied one: on macOS, register through Objective-C or Swift and call your C/C++ routines from the handlers. Swift `import` and Objective-C `@import` autolink frameworks; there is no linker-flags option.

## The C ABI

The header is `native/include/svelte_desktop.h` in `@svelte-desktop/shell`, with C++ linkage guards and no Cocoa dependency. A standalone plugin (Linux and Windows) exports:

```c
int sd_plugin_init(const sd_host *host);
```

The shell calls it on the UI thread before the run loop. Return `0` on success, nonzero on failure. Check `host->abi == SD_ABI_VERSION` first, and retain the host pointer: the shell owns it. There is no shutdown callback. Keep initialization to registration; the build also runs it in a subprocess with a recording host.

A handler has this signature:

```c
void handler(sd_call *call, const char *args_json, void *user);
```

`args_json` is a non-null JSON object, valid only during the call: copy it if another thread will use it. `user` is the pointer you registered. `sd_call` is opaque; reply exactly once with `resolve` or `reject`, even on failure, and never use it afterwards. Don't race multiple replies.

### Every `sd_host` function

| Function | Contract and thread |
| --- | --- |
| `register_op(service, op, fn, user)` | Register during initialization. Returns `0`, or `-1` if the name is taken by the shell or another plugin. Handlers run on the UI thread. |
| `resolve(call, value_json)` | Complete with any JSON value (`"42"`, `"null"`, an object). Any thread. |
| `reject(call, code, message)` | Complete with an error. Any thread. Use `invalid_args`, `unsupported`, `unavailable`, `denied` or `internal`. |
| `emit(event, data_json)` | Broadcast an event. Any thread. Objects pass through; other values arrive as `{ value }`. |
| `window(window_id)` | Borrow a native window handle, or null. UI thread only. `0` is the main window. |
| `webview(window_id)` | Borrow a native webview handle, or null. UI thread only. |
| `caller_window(call)` | The calling page's window id, or `-1` for a server call. Read it before replying. |
| `log(message)` | Write a log message (`NSLog` on macOS, stderr elsewhere). |

| Handle | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `window` | `NSWindow *` | `GtkWidget *` | `HWND` |
| `webview` | `WKWebView *` | `WebKitWebView *` | `ICoreWebView2 *` |

The shell owns the handles: don't destroy them or use them after their window closes. The ABI can't schedule callbacks on the UI thread; use the platform's own mechanism. Validating and parsing arguments is up to you.

### C++ and background replies

C compiles as C17 and C++ as C++17. Export `sd_plugin_init` with `extern "C"`. This Linux plugin starts a native thread per call; the same file works under `native/windows/` for production. Don't put two standalone entry points in one platform's source set.

```cpp native/linux/Work.cpp
#include "svelte_desktop.h"
#include <exception>
#include <string>
#include <thread>
#include <utility>

#if defined(_WIN32)
#define PLUGIN_EXPORT __declspec(dllexport)
#else
#define PLUGIN_EXPORT __attribute__((visibility("default")))
#endif

static const sd_host *host;

static void copyLater(sd_call *call, const char *args_json, void *user) {
  (void)user;
  const sd_host *api = host;
  try {
    // Copy on the UI thread: args_json expires when this handler returns.
    std::string args(args_json);
    std::thread([api, call, args = std::move(args)] {
      // Do non-UI work here. Each call owns its copied input.
      api->emit("cppWork.finished", "{\"finished\":true}");
      api->resolve(call, args.c_str());
      // call has been consumed. Never resolve, reject or inspect it again.
    }).detach();
  } catch (const std::exception &error) {
    api->reject(call, "internal", error.what());
  }
}

extern "C" PLUGIN_EXPORT int sd_plugin_init(const sd_host *api) {
  if (!api || api->abi != SD_ABI_VERSION) return -1;
  host = api;
  return host->register_op("cppWork", "copyLater", copyLater, nullptr);
}
```

```ts
const off = host.on<{ finished: boolean }>('cppWork.finished', console.log);
const result = await host.native.cppWork.copyLater({ text: 'Copied off the UI thread' });
off();
// raw ABI results are unknown in the generated types
```

The host accepts replies and events from any thread but doesn't manage the thread's lifetime, cap concurrency, cancel work, or wait for detached threads on quit: own those policies. Catch exceptions inside a background thread; the shell can't.

## Build notes

Objective-C and Swift files are skipped on Linux and make the Windows C-family build skip entirely: keep them under `native/macos/`. Dev restarts and other builds: [Plugins](/native/plugins#dev-loop) and [Platforms](/native/plugins/platforms).
