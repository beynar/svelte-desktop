title: Sidecars
description: Bundle existing executables, spawn them from server code and own their communication and cleanup.

A sidecar is an executable shipped beside your app and started by server code. Pick it for an existing CLI or local server, such as `ffmpeg`. Use a [service](/native/services) for a persistent Bun child that needs managed messages, request/reply, restarts and quit cleanup.

## A complete example

Supply an `ffmpeg` executable for each target you ship. The framework copies these files; it does not download or compile them.

```ts desktop.config.ts
import { defineConfig } from '@kitop/shell/config';

export default defineConfig({
  appName: 'Media Tools',
  identifier: 'dev.example.media-tools',
  sidecars: {
    ffmpeg: {
      macos: 'bin/ffmpeg-macos',
      linux: 'bin/ffmpeg-linux',
      windows: 'bin/ffmpeg.exe',
    },
  },
});
```

Run it from server code:

```ts src/routes/api/ffmpeg-version/+server.ts
export async function GET() {
  const child = await host.sidecar('ffmpeg', ['-version'], {
    stdin: 'ignore',
    stdout: 'pipe',
    stderr: 'pipe',
  }) as Bun.Subprocess<'ignore', 'pipe', 'pipe'>;
  const [stdout, stderr, code] = await Promise.all([
    new Response(child.stdout).text(),
    new Response(child.stderr).text(),
    child.exited,
  ]);
  if (code !== 0) throw new Error(`ffmpeg exited with ${code}: ${stderr}`);
  return new Response(stdout, { headers: { 'content-type': 'text/plain; charset=utf-8' } });
}
```

A page reads the result with `await fetch('/api/ffmpeg-version').then((r) => r.text())`. The endpoint exposes a fixed command rather than accepting arguments from the page. Both output pipes are drained while the child runs, and nonzero exits become server errors.

The subprocess type assertion matches the explicit stdio options. The helper's return type does not infer those options, so TypeScript otherwise includes file descriptors and missing streams in the output types.

### Stop it on quit

Quitting the app does not stop sidecars (see [Lifetime and quit](#lifetime-and-quit)). For a long-running tool, keep the handle and kill it in a server `host.onBeforeQuit` hook:

```ts src/lib/server/ffmpeg.ts
const running = new Set<Bun.Subprocess>();

host.ready(() => {
  host.onBeforeQuit(async () => {
    const children = [...running];
    for (const child of children) child.kill('SIGKILL');
    await Promise.all(children.map((child) => child.exited));
  });
});

export async function spawnFfmpeg(args: string[]) {
  const child = await host.sidecar('ffmpeg', args);
  running.add(child);
  child.exited.then(() => running.delete(child));
  return child;
}
```

## Configuration and paths

`sidecars` maps a name to a project-relative path or an object with `macos`, `linux` and `windows` paths. A string is used for every target. An omitted platform entry excludes the sidecar from that platform's bundle. There is no per-architecture selection: supply a binary matching the chosen target, or a universal binary for a universal macOS app.

Names used by `host.sidecar` may contain letters, numbers, dots, underscores and hyphens. Prefer a name without an extension, such as `ffmpeg`; the Windows bundle adds `.exe`.

| Location and preparation | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Development | Configured source path | Configured source path | Configured source path |
| Bundle | `Contents/MacOS/<name>` | Beside the app executable as `<name>` | Beside the app executable as `<name>.exe` |
| Executable mode | Bundle copy gets `chmod +x` | Bundle copy gets mode `0755` | Copied as an executable; warns if it lacks a PE header |

The Vite plugin resolves dev paths from the project root and exposes them through `KITOP_SIDECAR_<NAME>` environment variables, with punctuation in the uppercase name replaced by underscores. In dev, source files on macOS and Linux must already be executable (`chmod +x`); otherwise `host.sidecar` rejects with a spawn error. A bundle build fails if a selected source file is missing. Dependent libraries or companion resource files are not collected automatically.

Restart Vite after changing the mapping. The framework does not build or hot-reload the sidecar. Replacing an executable does not replace an already running process; stop it and spawn a new one.

## Spawning and communication

`await host.sidecar(name, args?, options?)` resolves a `Bun.spawn` subprocess, not its exit result. `args` defaults to `[]` and `options` to `{}`. Options pass through unchanged. Use `pid`, `stdin`, `stdout`, `stderr`, `kill()` and `exited` as with `Bun.spawn`. Invalid names, missing bundled executables and spawn failures reject. See the [server API reference](/host/data/server).

There is no sidecar-specific environment or working directory. Bun defaults `cwd` to `process.cwd()`; it does not change to the executable's directory. Its default environment is the environment captured when Bun launched. Pass `env: { ...process.env, KEY: 'value' }` to include current environment changes and your own values. Set `cwd` explicitly when the tool needs one, for example `host.paths.data` for writable app data after `host.ready`.

Choose the protocol your executable already supports:

- For a CLI, pass arguments and read stdout/stderr. Set `stdin: 'pipe'` for a writable input stream, or pass input supported by `Bun.spawn`, such as a `Blob`. The framework adds no framing or JSON protocol.
- For a local HTTP server, start it on a loopback port, wait for its readiness signal, then make requests with server-side `fetch`. You own port selection and startup timeouts.
- For a WebSocket server, server code or a page can open a standard `WebSocket` to its loopback address. Return the selected address to the page through an endpoint. Bind to loopback and validate/authenticate clients in the sidecar; the app server's session gate does not protect a separate listener. See [WebSockets](/features/websockets).

## Threads and processes

The executable runs in its own OS process, started by server code. Pages cannot call `host.sidecar`; they use your endpoints or remote functions, or a protocol the sidecar exposes. See [Threads and processes](/native/threads).

The child receives no `host` global, service port or automatic connection to the native UI thread. A sidecar crash ends that child; it is not restarted automatically. Inspect `exited` and handle failures in the owning server code.

## Lifetime and quit

The shell does not register sidecars in its job or service registry. App quit has no explicit sidecar stop/reap step, and `host.sidecar` does not install a parent-death handler. Do not rely on quitting the app to stop a sidecar: it may outlive the app, depending on its own behavior and the OS.

Keep the subprocess handle and register a server `host.onBeforeQuit` callback, as above. Hooks are awaited in registration order; they run before automatic job and service cleanup. If a tool supports graceful shutdown, send its shutdown command first, then force-kill after a bounded wait. Quit cleanup itself has a limited window, and forced termination cannot guarantee it runs. Killing the direct subprocess does not provide process-tree supervision.
