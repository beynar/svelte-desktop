---
title: Limitations
description: What isn't done, verified or possible yet, by platform.
---

Desktop only: macOS, Windows, Linux. iOS can't run Bun, so mobile isn't a target; for mobile, deploy the SvelteKit app and ship it as a PWA or wrap it (e.g. Capacitor).

## Everywhere

- **Smaller builds need a canary Bun.** `build.trim` and `build.aot` are unavailable on stable Bun. See [Distribution](/shipping/distribution#macos).
- **Ops vary by platform.** Many window and app ops are macOS-only and answer `unsupported` elsewhere. `host.capabilities.describe()` lists the operations registered in the running build; a registered operation can still reject because the OS, permission or runtime is unavailable.
- **No screen reader has been run.** axe-core and real key presses check what the framework draws, on Linux only. See [Accessibility](/ui/accessibility).
- **Self-update has platform and recovery gaps**: no delta patches on Windows or for AppImages, no recovery from an executable the OS can't launch at all. See [Self-update](/shipping/self-update#platform-support).

| Feature | macOS | Linux | Windows |
| --- | --- | --- | --- |
| [Custom resource protocols](/features/protocols) | Supported | Unsupported | Unsupported |
| Website sessions, cookie management and per-session proxies | Supported | Unsupported | Unsupported |
| Server-owned web permission and authentication handlers | Supported | Unsupported | Unsupported |
| Registered web scripts, content rules and navigation policy | Supported | Unsupported | Unsupported |
| Native download management and file bookmarks | Supported | Unsupported | Unsupported |
| Native input policy | Supported | Unsupported | Unsupported |
| Web-view printing and PDF export | Supported | Unsupported | Supported with a recent WebView2 runtime |

These are shell API limits. The page still has the web APIs its installed web engine provides.

## macOS

- **Notarization needs credentials.** The pipeline implements pre-flight, `notarytool` submission and stapling; it runs only with a signing identity and a notary profile.
- **Permission names exceed runtime support.** Usage strings can be declared for every documented name, but `host.permissions.status()` checks only `camera`, `microphone`, `notifications`, `screenRecording`, `accessibility`, `inputMonitoring` and `fullDiskAccess`. Other declared names reject with `invalid_args`; WebKit page consent is separate. Full Disk Access reports `unknown` when its probe cannot establish a grant. See [Permissions](/features/permissions).
- **Screen capture** needs macOS 12.3 for source discovery, Screen Recording permission and macOS 14 for stills.
- **Notifications need a bundled app.** Under `vite dev`, notification calls return `unavailable`; location and speech consent also need testing in a built bundle.
- **Some WebKit delegates use private SPI.** Location, speech and display-capture consent can vary with the installed macOS/WebKit version.
- **The macOS 26 icon** (`Assets.car`) needs Xcode 26. See [App icon](/shipping/app-icon).

## Windows

- **Only partly tested on real Windows:** CI runs the app and its notifications on a Windows runner. Title-bar dragging, background jobs, views, printing and high-DPI setups aren't covered, so test your app on a real PC.
- The WebView2 runtime must be installed. The shell offers an Evergreen download link when it is missing; it does not bundle the runtime.
- Rust and Go plugins need a Windows host. See [Distribution](/shipping/distribution#windows).
- Windows repeating notifications queue at most 128 occurrences over the next 30 days, topped up while the app runs. They do not repeat indefinitely while closed.

## Linux

- Tray hosts don't report icon positions, so tray-anchored popovers open at the pointer.
- Global shortcuts and screen capture need X11; on Wayland they answer `unsupported`.
- C/C++ plugins, source addons, Rust and Go plugins need a Linux host. See [Distribution](/shipping/distribution#linux).
- Native inline notification replies are unavailable; reply buttons become plain actions. Scheduling catches up when the app restarts rather than delivering while it is closed.
- The build makes an app folder and an AppImage, not deb, rpm or Flatpak packages. Self-update covers those two; an install this user can't write to, in `/opt` for instance, answers `not_writable`. See [Self-update](/shipping/self-update#linux).
- Self-update has been run through real updates and rollbacks on Ubuntu 24.04 only, under Xvfb. Other distributions and real desktop sessions haven't been covered.

## Tooling

- `kitop doctor` checks each OS's tools, and signing on macOS only. It is not a complete cross-platform readiness check.
- SVG icon sources require macOS (`sips`); use a PNG source when building the same app in Linux or Windows CI.
- Swift and Objective-C plugins are macOS-only. Only one Go plugin runtime is allowed per app process; consolidate Go code into one module. See [Native code](/native).
