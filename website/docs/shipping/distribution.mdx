---
title: Distribution
description: Build, sign and package for macOS, Windows and Linux.
---

`bunx --bun vite build` compiles the server into one executable and packages it for the target. Output goes to `.desktop/dist` (`build.outDir`). The target is the host OS unless `build.target` or `SVELTE_DESKTOP_TARGET` says otherwise; Linux and Windows can be built from macOS. The environment variables override the config. Building macOS requires macOS and its Apple toolchain.

```sh
bunx --bun vite build                               # macOS, the host
SVELTE_DESKTOP_TARGET=linux bunx --bun vite build   # cross-build
SVELTE_DESKTOP_TARGET=windows SVELTE_DESKTOP_TARGET_ARCH=arm64 bunx --bun vite build
```

## macOS

```sh
CODESIGN_IDENTITY="Developer ID Application: You (TEAMID)" NOTARY_PROFILE=notary bunx --bun vite build
```

| Output | |
| --- | --- |
| `<App>.app` | One executable, `libshell.dylib`, C/C++/Swift/Objective-C and Rust/Go plugins, addons and sidecars; `Info.plist` from the config |
| `<Exe>-<version>-darwin-<arch>.zip` | `build.zip: false` to skip |
| `<Exe>-<version>-darwin-<arch>.dmg` | With an Applications link; `build.dmg: false` to skip |
| `release/` | Update archives and a manifest when [`update`](/shipping/self-update) is set; unsigned without a private key |

The pipeline:

1. **Info.plist** from the config: `identifier`, `version`, URL `schemes`, document types (`fileTypes`), usage strings (`permissions`), `LSUIElement` (`trayOnly`), `build.minimumSystemVersion` (default `12.0`) and any extra `plist` keys.
2. **Signing.** Nested code first, then the bundle, with the hardened runtime and the entitlements Bun's JIT needs, plus device entitlements derived from `permissions`. `sign.entitlements` adds more; `sign.provisioningProfile` embeds a profile (needed for APNs).
3. **Notarization.** When an identity and a notary profile are set, a local pre-flight runs, then the app and the DMG are submitted with `notarytool` and stapled.

Without an identity, builds are ad-hoc signed: they run on your machine, but Gatekeeper blocks them once downloaded.

<Steps>
  <Step title="Get a Developer ID certificate">
    A **Developer ID Application** certificate in your keychain. `bunx svelte-desktop doctor` lists the identities it finds.
  </Step>
  <Step title="Store notary credentials">
    Create a keychain profile with Apple's `xcrun notarytool store-credentials notary`, then pass its name as `NOTARY_PROFILE` (or `sign.notaryProfile`).
  </Step>
  <Step title="Build">
    Set `CODESIGN_IDENTITY` (or `sign.identity`) and build. `bunx svelte-desktop preflight .desktop/dist/<App>.app` runs the same pre-flight on any bundle.
  </Step>
</Steps>

**Universal builds.** `build: { universal: true }` builds both arm64 and x64 slices (Bun cross-compiles the other executable slice) and lipos the executable, `libshell`, the plugins and compiled addons into one app. Prebuilt addons must already contain the slices you need; sidecars are copied without merging architectures.

**Smaller builds.** The packager checks `bun build --help` for `--trim` and `--aot`. When available, `trim` is on by default; `trim: false` opts out. Set `build: { aot: true }` to opt into AOT on a supported host build. `build.bun` or `SVELTE_DESKTOP_BUN` chooses the compiler. If a target runtime rejects trimming, the packager retries without it. AOT is skipped for the other architecture in a universal build and for Windows builds.

## Windows

```sh
SVELTE_DESKTOP_TARGET=windows bunx --bun vite build
```

| Output | |
| --- | --- |
| `<appName>-windows-<arch>/` | `<Exe>.exe` (icon and version resources), `shell.dll`, optional `app-native.dll`, language plugins under `plugins/`, addons, sidecars |
| `.zip` | The folder |
| NSIS installer | Per-user, with URL schemes and file associations |
| `release/` | Update archives, when `update` is set |

Cross-builds run the native toolchain (llvm-mingw, the WebView2 SDK, NSIS, osslsigncode) in Docker. Authenticode signing is on when a certificate is given:

```ts desktop.config.ts
sign: { windows: { certificateFile: 'cert.pfx', password: process.env.CERT_PASSWORD } }, // or $WINDOWS_CERT_PFX + $WINDOWS_CERT_PASSWORD
```

Rust and Go plugins are skipped when cross-building Windows from another OS; build on Windows if your app needs them. C/C++ plugins and source addons use the Docker toolchain.

`timestampUrl` defaults to `http://timestamp.digicert.com`. Data lives in `%APPDATA%\<identifier>`, caches and logs in `%LOCALAPPDATA%`. `build.targetArch` is `x64` (default) or `arm64`.

:::warning
The Windows native layer and installer have Wine smoke tests, but those do not validate Bun and WebView2 together. Validate the installer and app on a real Windows desktop. See [Limitations](/shipping/limitations).
:::

## Linux

```sh
SVELTE_DESKTOP_TARGET=linux bunx --bun vite build
```

| Output | |
| --- | --- |
| `<appName>/` | Relocatable app directory: the executable, `lib/` (`libshell.so`, plugin, addons), sidecars, `<identifier>.png`, `<identifier>.desktop` |
| `<exe>-<version>-linux-<arch>.tar.gz` | The directory |
| `<exe>-<version>-linux-<arch>.AppImage` | When `appimagetool` is on the PATH |

GTK 3 and WebKitGTK 4.1 come from the system, like the system WebKit on macOS; libnotify, appindicator and libsecret are optional. `fileTypes` become the `.desktop` MimeType entry (plus a shared-mime-info package for custom types). C/C++ plugins and source addons need a Linux host of the target architecture; run the build there or in a matching Linux container. The packager skips those source builds when cross-building from macOS, even when Docker builds `libshell.so`. Prebuilt `addons` are copied. Rust and Go plugins also build on a host of the target OS. See [plugin platforms](/native/plugins/platforms).

The generated Linux updater archive currently has a layout mismatch with the installer. Distribute the `.tar.gz` or `.AppImage` for manual installation; see [Self-update](/shipping/self-update#platform-support).
