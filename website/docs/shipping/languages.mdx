---
title: Languages
description: The app's name, permission prompts and standard menus in the user's language.
---

Your pages handle their own translations. What the system shows needs translating too: the app's name in the Finder and the Dock, the permission prompts, and the standard menus (Edit, Window…). List the app's languages in `locales`:

```ts desktop.config.ts
export default defineConfig({
  appName: 'Notes',
  language: 'en',                                   // the language of the texts below (default)
  permissions: { camera: 'Scan documents into your notes.' },
  locales: {
    fr: { permissions: { camera: 'Scanner des documents dans vos notes.' } },
    de: { name: 'Notizen', permissions: { camera: 'Dokumente in Ihre Notizen scannen.' } },
  },
});
```

macOS then shows the app in the user's language among these. That's the first of their preferred languages (System Settings › General › Language & Region) that the app has, or `language` when it has none of them. An app with no `locales` stays in `language` everywhere, as AppKit's own menus do.

| What | Translated by |
| --- | --- |
| The app's name (Finder, Dock, menu bar) | `name`. Without it, `appName`. |
| Permission prompts | `permissions`. A reason left out keeps the one in `permissions` at the top level. |
| The shell's standard menus and roles: About, Hide, Quit, Edit, Undo, Copy, Paste, View, Window, Minimize, Zoom, Help… and `<WindowTabs>`' Tab menu | The shell, in French, German, Spanish, Italian, Portuguese, Dutch, Japanese, Simplified Chinese, Korean and Russian. The wording follows macOS's own menus. |
| Items macOS adds itself (Start Dictation, Emoji & Symbols, AutoFill) | macOS |
| Menu items your app writes | You: they're your labels. Only the shell's exact English labels are translated. |

The build writes `CFBundleLocalizations` and a `<language>.lproj/InfoPlist.strings` per language. In `vite dev`, the shell gets the list instead (there's no bundle), and `SVELTE_DESKTOP_LANGUAGE=fr` forces a language for a run.

Linux and Windows menus stay in the config's language for now.
