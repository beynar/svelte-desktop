Two files make a SvelteKit project a desktop app: the Vite plugin and `desktop.config.ts`.

## The Vite plugin

```ts vite.config.ts
import { desktop } from '@svelte-desktop/shell/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [desktop({ experimental: { remoteFunctions: true } })],
});
```

`desktop(kitOptions, options)` is SvelteKit's own plugin with the desktop adapter set (don't pass `adapter`). Svelte compiler options go in `kitOptions.compilerOptions`; for example, the `create` template turns on `experimental.async` to use `await` in markup. The first argument takes SvelteKit's plugin options; the second takes:

The plugin also installs the [`host` global](/host) in page and server code and writes `src/host.d.ts` once.

## desktop.config.ts

```ts desktop.config.ts
import { defineConfig } from '@svelte-desktop/shell/config';

export default defineConfig({
  appName: 'Svelte Notes',
  identifier: 'dev.svelte-desktop.notes',
  window: { width: 960, height: 680, minWidth: 520, minHeight: 400, autosaveName: 'main', titleBarStyle: 'hiddenInset' },
  schemes: ['svelte-notes'],
  quitOnLastWindowClosed: false,
  fileTypes: [{ name: 'Markdown', extensions: ['md'], role: 'Viewer' }],
  permissions: {
    camera: 'Notes can attach photos from your camera.',
    screenRecording: 'Notes can attach a screenshot of your screen.',
  },
  notifications: { foreground: true },
  push: { server: 'https://push.example.com' },
});
```

Set `appName` and `identifier`: `defineConfig` requires them. If you omit them (a plain object, or a `.js` file), the loader falls back: `appName` falls back to `productName` or `name` in `package.json`, `identifier` to `dev.svelte-desktop.` followed by the lowercased app name with non-alphanumeric characters removed, and `version` to the `package.json` version or `0.0.0`. `identifier` must be reverse-DNS (`com.example.app`): it names the bundle and the data directories.

The plugin loads the first file it finds (`desktop.config.ts`, `.js`, then `.mjs`) for both `vite dev` (window, native plugins) and `vite build` (bundle, signing, release). Editing it during windowed `vite dev` restarts the dev server and the shell. Browser-only mode skips this watcher.

`singleInstance` and `quitOnLastWindowClosed` apply to built apps. The dev shell currently receives neither setting: it allows multiple instances and quits when its last window closes. `exitOnClose` controls whether Vite also stops.

## Environment overrides

Some settings can come from the environment, which keeps secrets and per-build switches out of the file. The target variables override config values; the other variables are fallbacks when their config field is absent:

| Variable | Overrides |
| --- | --- |
| `SVELTE_DESKTOP_TARGET` | `build.target` (`macos`, `linux`, `windows`) |
| `SVELTE_DESKTOP_TARGET_ARCH` | `build.targetArch` |
| `SVELTE_DESKTOP_BUN` | `build.bun` (the Bun binary used to compile) |
| `CODESIGN_IDENTITY` | `sign.identity` |
| `NOTARY_PROFILE` | `sign.notaryProfile` |
| `SVELTE_DESKTOP_UPDATE_KEY` | `update.privateKey` |
| `WINDOWS_CERT_PFX`, `WINDOWS_CERT_PASSWORD` | `sign.windows` |
