---
title: Background jobs
description: Long or CPU-heavy work in its own process, with progress, cancellation and history, started from server code and watched from pages.
---

A job runs in its own process, so the app stays responsive and a crashing job can't take it down. One file per job in `src/jobs/`:

```ts src/jobs/thumbnails.ts
// No import: HostJob is a global type.
const thumbnails: HostJob<{ files: string[] }, { made: number }> = async ({ files }, ctx) => {
  for (const [i, file] of files.entries()) {
    if (ctx.signal.aborted) throw new Error('canceled');
    await makeThumbnail(file);
    ctx.progress((i + 1) / files.length, file);
  }
  return { made: files.length };
};
export default thumbnails;
```

Start it from server code (a remote function, an endpoint, a hook):

```ts
const job = host.jobs.start('thumbnails', { files }, { concurrency: 2 }); // { id, state: 'queued', ... }
const done = await host.jobs.wait(job.id);                                 // done, failed or canceled
```

Watch it from a page:

```svelte
<script>
  host.jobs.on('done', (job) => toast(`${job.name} finished`));
</script>

{#each host.jobs.active() as job (job.id)}
  <progress value={job.progress}></progress> {job.message}
  <button onclick={() => host.jobs.cancel(job.id)}>Cancel</button>
{/each}
```

## API

`host.jobs` is the same in pages and server code; server code also has `start` and `wait`.

| | |
| --- | --- |
| `start(name, args, { concurrency, env })` | Server only. Queue `src/jobs/<name>.ts` with JSON-serializable `args`. `concurrency` caps how many jobs of that name run at once. |
| `wait(id)` | Server only. Resolves when the job ends. |
| `list()`, `active()`, `running()`, `get(id)` | Snapshots (reactive in pages) |
| `cancel(id)` | Fires the job's `ctx.signal`; the process is killed if it hasn't ended 2 s later |
| `on(state, fn)` | State transitions: `queued`, `running`, `done`, `failed`, `canceled`, or `'*'` |
| `onEvent(fn)` | Custom events from `ctx.emit(data)` |

A job's info: `id`, `name`, `state`, `progress` (0 to 1), `message`, `args`, `result`, `error`, `log` (last lines), `createdAt`, `startedAt`, `endedAt`, and `restored` for jobs from a previous launch.

## The job context

| | |
| --- | --- |
| `ctx.progress(fraction, message?)` | Progress and a status line, throttled to the pages |
| `ctx.log(...parts)` | A line in the job's log |
| `ctx.emit(data)` | A custom event for listeners |
| `ctx.signal` | Aborted on cancel and when the app quits |
| `ctx.id` | The job id |

## How it runs

In the built app, each job is the app's own executable acting as Bun, running the job's bundle embedded at build time. Under `vite dev` the `.ts` file runs directly. Jobs are killed when the app quits; ended jobs (state, result, error, last log lines) are kept in `<data>/jobs.json` and come back after a restart with `restored: true`.

Verified on macOS (built and dev) and Linux.
