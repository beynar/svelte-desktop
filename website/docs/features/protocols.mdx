---
title: Custom resource protocols
description: Serve app-owned resources to a page from a custom URL scheme, answered by a handler in your server code.
---

:::note
API reference: [`host.protocol`](/host/web/protocol).
:::

A custom protocol lets a page load app-owned resources from a URL such as `<img src="asset://archive/cover.svg">`, answered by a handler in your server code. It works on macOS, Linux and Windows.

Declare the scheme (lowercase) in the config. Adding one needs a restart.

```ts desktop.config.ts
import { defineConfig } from '@kitop/shell/config';
export default defineConfig({
  appName: 'Archive',
  identifier: 'com.example.archive',
  protocols: ['asset']
});
```

Register the handler in **server code**, for example in `src/hooks.server.ts`. It receives a standard `Request` and returns a standard `Response`; a `Bun.file` or `ReadableStream` body is streamed to the page, except on Windows, where WebView2 takes a response whole once it ends. See [platform support](/host/web/protocol#platform-support).

```ts src/hooks.server.ts
// Under `vite dev` this module can load again: drop the previous handler first.
host.protocol.unhandle('asset');
host.protocol.handle('asset', async (request) => {
  const url = new URL(request.url);
  if (url.hostname !== 'archive') return new Response('Not found', { status: 404 });
  if (url.pathname === '/cover.svg') {
    return new Response(Bun.file('/path/to/cover.svg'), {
      headers: { 'content-type': 'image/svg+xml' }
    });
  }
  return Response.json({ title: 'Archive', path: url.pathname });
});
```

The page can then load `asset://archive/cover.svg` in an image, a frame or another resource element. In a packaged app the handler runs in the Bun Worker; during `vite dev`, the Vite server owns it.

Things to know:

- Handlers are registered again on every launch. Registering a scheme twice throws until `host.protocol.unhandle('asset')` removes the first handler.
- A declared scheme with no handler answers 404. A handler that throws fails the resource load.
- Validate the URL in your handler: don't return private files for arbitrary paths.
- Custom schemes keep WebKit's origin restrictions, and `fetch()` on one is not guaranteed to work. For ordinary app resources and web-origin behavior, use authenticated SvelteKit HTTP routes.
- `http`, `https`, `file` and other reserved schemes can't be taken over, and a resource request doesn't get the host bridge.

`protocols` is separate from [`schemes` for OS deep links](/host/app/deep-link): deep links launch or activate the app, while a protocol answers resource requests inside its web views. See the [`host.protocol` reference](/host/web/protocol) for the handler contract, streaming, cancellation and timeouts.
