## A terminal in a page

Bun runs a program in a pseudo-terminal (`Bun.spawn` with `terminal`), so it behaves as in a real terminal: colors, prompts, full-screen programs like `vim` or `htop`. Run the user's shell on the app's server, and draw it in the page with [xterm.js](https://xtermjs.org). A [WebSocket](/features/websockets) carries the bytes both ways:

```ts src/websocket.ts
import { defineWebSocket } from '@svelte-desktop/shell/websocket';

const shells = new Map<number, ReturnType<typeof Bun.spawn>>();
let next = 1;

export default defineWebSocket<{ id: number }>({
  path: '/terminal',
  upgrade: () => ({ id: next++ }),
  open(ws) {
    // A login shell reads the user's profile: their PATH, aliases and prompt are there.
    const proc = Bun.spawn([process.env.SHELL || '/bin/zsh', '-l'], {
      cwd: process.env.HOME,
      env: { ...process.env, TERM: 'xterm-256color' },
      terminal: { cols: Number(ws.data.query.cols) || 80, rows: Number(ws.data.query.rows) || 24, data: (_t, bytes) => ws.send(bytes) },
    });
    shells.set(ws.data.data.id, proc);
    void proc.exited.then(() => ws.close());
  },
  message(ws, message) {
    const { input, cols, rows } = JSON.parse(String(message));
    const terminal = shells.get(ws.data.data.id)?.terminal;
    if (input) terminal?.write(input);
    if (cols && rows) terminal?.resize(cols, rows);
  },
  close(ws) {
    shells.get(ws.data.data.id)?.kill();
    shells.delete(ws.data.data.id);
  },
});
```

```svelte src/lib/Terminal.svelte
<script lang="ts">
  import { onMount } from 'svelte';
  import { Terminal } from '@xterm/xterm';
  import { FitAddon } from '@xterm/addon-fit';
  import '@xterm/xterm/css/xterm.css';

  let el: HTMLDivElement;
  onMount(() => {
    const term = new Terminal({ fontFamily: 'ui-monospace, Menlo, monospace', fontSize: 12 });
    const fit = new FitAddon();
    term.loadAddon(fit);
    term.open(el);
    fit.fit();
    const ws = new WebSocket(`${location.origin.replace('http', 'ws')}/terminal?cols=${term.cols}&rows=${term.rows}`);
    ws.binaryType = 'arraybuffer';
    ws.onmessage = (e) => term.write(new Uint8Array(e.data));
    term.onData((input) => ws.send(JSON.stringify({ input })));
    const resize = new ResizeObserver(() => (fit.fit(), ws.send(JSON.stringify({ cols: term.cols, rows: term.rows }))));
    resize.observe(el);
    return () => (resize.disconnect(), ws.close(), term.dispose());
  });
</script>

<div bind:this={el} style="height: 300px"></div>
```

Only the app's pages reach its sockets, since they carry its session cookie, so only they get a shell. The shell has the user's rights. To run a [coding agent](/features/ai#the-users-coding-agents) or another tool in it instead, find it with `host.which` and spawn that. Pseudo-terminals are POSIX: macOS and Linux. The dashboard example has this terminal on its Modules page.

## The app's command

`command` in the config gives the app a command for the user's terminal, like VS Code's `code`. `notes report.md ~/Projects` opens those in the app, in the running one if it is (`host.webview.onOpenFiles`).

```ts desktop.config.ts
command: 'notes',
```

Server code installs it, typically from a menu item or a settings page:

```ts src/routes/settings/command/+server.ts
import { json } from '@sveltejs/kit';

export const GET = async () => json(await host.command.status());       // { name, available, path, onPath }
export const POST = async () => json(await host.command.install());     // { path, onPath }
export const DELETE = async () => (await host.command.uninstall(), json(null));
```

The command goes in a folder of the user's shell `PATH` they can write to (`~/.local/bin`, `~/bin`, `/opt/homebrew/bin`). When there's none, it goes in `/usr/local/bin` after the system's administrator prompt. `onPath` says whether a new terminal finds it.

| | How it works |
| --- | --- |
| macOS | A launcher in the bundle (`Contents/Resources/bin/<command>`) runs `open -a` with the files and folders. Other arguments reach a new launch only. |
| Linux | A link to the app's executable (the AppImage) in `~/.local/bin`. The single instance hands the arguments to the running app. |
| Windows | Not yet. |

It installs from the built app; in `vite dev`, `status()` says `available: false` and `install()` does nothing.
