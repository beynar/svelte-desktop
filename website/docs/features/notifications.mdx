One API, `host.notifications`, on macOS, Linux, Windows, Android, iOS and in a plain browser tab.

```ts
await host.notifications.show({
  id: 'msg-42',                 // dedupe: the same id replaces, never duplicates
  title: 'Alice', subtitle: '#general', body: 'Lunch?',
  url: '/chat/42',              // a click opens it in the window that showed it
  data: { chat: 42 },           // handed back in events and lists
  group: 'chat', image: '/avatars/alice.png', urgency: 'critical',
  actions: [
    { id: 'reply', title: 'Reply', input: { placeholder: 'Message' } },
    { id: 'mute', title: 'Mute', foreground: false, destructive: true },
  ],
});

host.notifications.on('click', (e) => { /* e.id, e.data, e.url; e.preventDefault() skips the navigation */ });
host.notifications.on('reply', (e) => send(e.data.chat, e.input));
```

`show` resolves `{ id, scheduled }` and rejects when the OS refuses.

## Behavior

- **Dedupe.** An `id` replaces a delivered or pending notification on every platform (`replace: false` keeps the existing one; `renotify: false` replaces silently). Pushes use the same ids, so a push and a local notification for the same message show once.
- **Deep links.** `url` (or an action's `url`) navigates with the SvelteKit router; the app's own scheme goes through `host.deepLink`; http(s) opens in the browser.
- **Cold start.** A click that launched the app is kept until the page starts, then navigates; listeners added later still receive it. Server code gets every response too (`host.notifications.on('response', fn)` in a `+server.ts` or hook), replayed at start.
- **Several windows.** Listeners and navigation run in one page: the window that showed it, else the focused one, which comes to the front.
- **Foreground.** Banners show while the app is frontmost (config `notifications.foreground`, default `true`; per notification `foreground`).

## Scheduling

```ts
await host.notifications.show({ id: 'standup', title: 'Stand-up', at: tomorrow9am, repeat: 'day' });
await host.notifications.show({ title: 'Tea is ready', delay: 4 * 60_000 });
```

`at` (a `Date`, epoch ms or string) or `delay` (ms), with `repeat`: `minute`, `hour`, `day`, `week`, `month`, `year`. Schedules survive the app quitting on macOS, iOS, Android and Windows; Linux keeps the queue on disk and catches up at the next start.

## Events and lists

| | |
| --- | --- |
| `on('click' \| 'action' \| 'reply' \| 'dismiss' \| 'response', fn)` | `{ id, kind, actionId, input, url, data, target, preventDefault() }`; `response` receives every kind |
| `on('shown', fn)` | Delivered while the app runs (a scheduled one firing, a push in the foreground) |
| `delivered()`, `pending()` | What's in the notification center, and what's scheduled |
| `dismiss(id)`, `dismissAll()` | Remove delivered and cancel pending |
| `setBadge(count)` | App icon badge (Dock, iOS, Unity launchers on Linux, Windows overlay); `null` or `0` clears it |
| `permission`, `requestPermission()` | Reactive `granted`, `denied`, `notDetermined` or `unavailable` |

## Android channels

```ts desktop.config.ts
notifications: {
  channels: [
    { id: 'messages', name: 'Messages', importance: 'high' },
    { id: 'reminders', name: 'Reminders' },
  ],
},
```

Channels are created at startup; the first one is the default. Fields: `id`, `name`, `description`, `importance` (`min`, `low`, `default`, `high`, `max`), `sound`, `vibrate`, `lights`, `badge`, `visibility`.

## Remote push

`host.push.register()` returns the target your server sends to:

| Platform | Provider | Config |
| --- | --- | --- |
| macOS, iOS | APNs | `push: { apns: true }` and a provisioning profile with Push Notifications (`sign.provisioningProfile` on macOS, `sign.ios.provisioningProfile` on iOS). The iOS simulator registers without one. |
| Android | FCM, or UnifiedPush when a distributor app (such as ntfy) is installed | `push: { fcm: { googleServices: './google-services.json' } }` |
| macOS, Windows, Linux | Your own push server (Web Push) | `push: { server: 'https://push.example.com' }`. Takes precedence over APNs on macOS. |
| Browser tab | Web Push | `host.push.register({ vapidPublicKey })` |

```ts
const target = await host.push.register();
await saveTarget(target); // send it to your server
host.push.on('message', (m) => { /* a push received while the app runs */ });
host.push.on('token', (t) => saveTarget(t)); // rotations
```

Taps on pushes are ordinary notification clicks, with the same `url` and `data`.

### Sending from Bun

No dependencies; one sender for all three providers:

```ts server.ts
import { createPush } from '@svelte-desktop/shell/push';

const push = createPush({
  apns: { teamId, keyId, key: await Bun.file('AuthKey.p8').text() },
  fcm: { serviceAccount: await Bun.file('firebase-service-account.json').json() },
  webpush: { publicKey, privateKey, subject: 'mailto:ops@example.com' },
});

const results = await push.sendMany(targets, { id: 'msg-42', title: 'Alice', body: 'Lunch?', url: '/chat/42' });
// results[i].expired: the target is gone (uninstalled, unsubscribed), delete it
```

`push.send(target, notification)` sends one. `generateVapidKeys()` from the same module creates the Web Push keys. A notification also takes `subtitle`, `data`, `badge`, `sound`, `silent`, `group`, `image`, `channel`, `ttl`, `priority` and `background` (data-only, delivered to `host.push.on('message')`).

### Self-hosted push

On desktop you don't need an Apple or Google account. Set `push.server` to a Web Push compatible service you run; the app holds one connection while it runs (window closed included, with `quitOnLastWindowClosed: false`). `register()` then returns a Web Push target and the same `push.send()` delivers to it, end-to-end encrypted.

Run the server anywhere with Bun:

```ts push-server.ts
import { servePush } from '@svelte-desktop/shell/push-server';

servePush({ port: 47123, db: 'push.sqlite' }); // db defaults to ':memory:'
```

Or deploy `packages/push-worker` from the repository on Cloudflare (`bunx wrangler deploy`): one Durable Object per device with hibernatable WebSockets. Android can use UnifiedPush the same way; iOS has no alternative to APNs.

In a plain browser tab, notifications use the Notification API and a small service worker served at `/__desktop/push-sw.js`, in its own scope.
