**svelte-desktop** explores a single question: *can a Svelte app render to real native UI — GPUI, the Rust engine behind the Zed editor — while keeping Svelte's authoring model intact?*

The answer so far is **yes, for the Svelte language** — verified by a 45-case conformance suite driven through real GPUI hit-testing, not synthetic DOM events.

```txt
.svelte file → svelte/compiler → compiled client JS
                                    │
                                    ▼
                        fake DOM (gdom.ts)
                                    │  createElement / setStyle /
                                    ▼  setText / insertBefore / …
                        gpuix applyBatch protocol
                                    │
                                    ▼
                    GPUI (Rust) → Metal → native window
```

## Status at a glance

| | |
|---|---|
| Svelte runtime | **45/45 conformance cases pass** headless on `TestGpuixRenderer` |
| Remote functions | `query` / `command` / `refreshAll` in-process, backed by `bun:sqlite` |
| Live window | Works (`bun src/main.ts`), ~150 MB RSS |
| Headless testing | Deterministic: real hit-testing, keystrokes, painted-text asserts |
| Packaging | Not yet proven — see [Roadmap](/roadmap) |

:::warning
This is a research POC, not a library. The code lives in
[`gpuix-poc/`](https://github.com/) inside this repo and is documented here as a
spec for what a real `svelte-gpuix` package would need.
:::
