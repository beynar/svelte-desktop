nkit styling is **StyleX-shaped, Rust-executed**. Your components never compute
a resolved style — they ship *symbolic payloads* (vocabulary names like
`p: 'lg'`, `bg: 'primary'`, variant tuples like `size: 'small'`) and the
native engine does the rest: vocabulary mapping, conflict resolution, token
and palette resolution, theme re-resolution. The JavaScript side holds no
style logic worth the name.

```
component                    gdom bridge                 Rust engine
─────────────────────────────────────────────────────────────────────────
style({ p: 'lg' })        →   setStyleProps [raw frags]  →   style_props.rs
recipe({...})         →   registerRecipe {config}        (vocab→fields,
r({ size: 'sm' })     →   setRecipe "name"+variants      ordered expansion)
class="…"             →   setStyle {desc fields}         recipe.rs (merge)
                                                        tokens.rs (palette)
                                                     →  StyleDesc → paint
```

Three layers compose per element, in order — legacy `setStyle` desc, then the
recipe layer selected by variant props, then your `StyleProps` fragments on
top. All three merge *symbolically* (still token names) and resolve once.
