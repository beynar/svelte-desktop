The honest map of what the style engine accepts, per lane. **Expressible**
means the value reaches the GPU through real native styling — not a
workaround. **Refused** means the key is either dropped with a diagnostic
(`definitionIssues` / the `dropped` audit) or parses but maps to no native
capability. Refused keys never silently no-op a whole style — a bad value
drops *itself*, not the fragment around it.

Three lanes feed the same `StyleDesc` wire format:

- **`style()` / StyleProps** — the closed vocabulary (`checkStyleProps`)
- **class tokens** — `class="p-4 tracking-tight"` (`resolveTokens`)
- **stylesheets** — `stylesheet.register` CSS text (`stylesheet.rs`)

## Layout

| Property | Lane | Status |
|---|---|---|
| `display` (`flex`, `grid`, `none`) | all | ✅ |
| `flexDirection` (`row`/`col`/`column`) | all | ✅ |
| `flexWrap`, `flexGrow`, `flexShrink`, `flexBasis` | all | ✅ |
| `alignItems`/`Self`/`Content`, `justifyContent` | all | ✅ |
| `gap`, `rowGap`, `columnGap` | all | ✅ spacing tokens resolve |
| `gridTemplateColumns`/`Rows` (count, `grid-cols-N`) | all | ✅ count only — no track sizing |
| `gridColumnMin`/`gridRowMin` | sheet | ✅ (`grid-cols-[…]` counts columns) |
| `position` (`absolute`/`fixed`) | all | ✅ `sticky` maps to `absolute`; `relative`/`static` drop |
| `top`/`right`/`bottom`/`left`, `inset` | all | ✅ |
| `zIndex` | — | ❌ no gpui `Style` field — paint order is DOM order; overlays use `<anchored>` `priority` (deferred paint lane) or a real OS window |
| `order`, `placeItems`, `placeSelf`, `float`, `clear` | — | ❌ no native concept |
| `gridColumn`/`gridRow` spans, `auto-rows-*`, `row-*`, `col-*` | class | ❌ intentionally dropped |
| `aspectRatio` | all | ✅ number or `W/H` |

## Values — what the grammar refuses everywhere

`var(`, `url(`, `clamp(`, `attr(`, `env(`, `color-mix(`, `gradient(`,
`conic(`, `min(`, `max(`, `mix(`, `oklch from`, `inherit`/`initial`/`unset`
(no cascade — `revert`/`revert-layer` are skipped the same way).

`calc(` is the exception: it **evaluates** for numeric/dimension fields
(`width: calc(100% - 8px)` works — same-unit arithmetic, `%` survives
against a px base). On non-numeric fields it's refused.

## ARIA / accessibility props

These are element props (`aria-*` attributes), not style fields — they land
on `custom_props` and materialize into AccessKit nodes:

| Prop | Status |
|---|---|
| `role` (full token map → `Role`) | ✅ |
| `aria-label`/`aria-description`/`aria-valuetext`/`aria-keyshortcuts`/`aria-placeholder`/`aria-roledescription` | ✅ |
| `aria-expanded`/`selected`/`pressed`/`checked` (tristates)/`disabled`/`busy`/`hidden`/`modal`/`readonly`/`required` | ✅ |
| `aria-level`/`posinset`/`setsize`/`rowindex`/`colindex`/`rowcount`/`colcount`/`valuenow`/`valuemin`/`valuemax` | ✅ |
| `aria-orientation`, `aria-live`, `aria-invalid`, `aria-haspopup` | ✅ enum-mapped |
| `aria-activedescendant` | ✅ (set on the descendant, gpui-style) |
| `aria-controls`/`owns`/`describedby`/`details` | ❌ reference attrs — accesskit takes `NodeId`s, no author-id resolution at build time |
