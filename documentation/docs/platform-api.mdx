# Platform API — brokered native services over the GPUI renderer

Status: **V1 slice implemented and live-probed on macOS** (2026-09-16).
Evidence: `results/run-2026-09-16-platform/platform.jsonl` — 55/56 probes ok,
0 unexpected failures, 1 skipped (modal dialogs, by design).
The public surface is **`svelte-desktop/stores`** — reactive namespaces,
one object per domain; the wire-level service ops sit beneath it.

## Architecture

```
JS typed facade (gpuix-poc/src/native-api/)
        │  {id, service, op, args} JSON
        ▼
GpuixRenderer.platformCall(request: string) -> string        [napi]
        │
        ├── macOS (embedded):  update_window(|view, window, cx| …)
        │                      or GPUI_APP.update when no window
        └── win/linux (gpuix-ui thread):
                             UiCommand::PlatformCall → SyncSender reply (2s)
        ▼
native/src/platform.rs dispatcher
        ├── now   → {"ok":true,"value"} | {"ok":false,"error":{code,message}}
        └── async → {"pending":true,"id"} now; result later as a
                    `platformResult` event on the existing EventPayload TSFN
```

Replies and events reuse the **existing** channels — `platform_call` is one new
napi method, `EventPayload.data` one new optional field, `PLATFORM_EVENT_ID`
(`0x7fffff02`) one new sentinel routed by `dispatchPayload` in `gdom.ts` to the
`native-api` bus. No second dispatch system.

On macOS the GPUI app runs embedded on the JS thread, so dispatch is a direct
`update_window`/`App::update`. On Windows/Linux/FreeBSD the call travels as a
`UiCommand` to the `gpuix-ui` thread and waits on the same bounded
`SyncSender` channel every other command uses.

## Error model

All service failures are values, never exceptions across napi:

```json
{"ok":false,"error":{"code":"invalid_args|unknown|unsupported|unavailable|denied|internal","message":"…"}}
```

`unsupported` = not implementable on this OS through this backend (contract
stable — callers may feature-detect). `unavailable` = implementable but
refused right now (unbundled URL-scheme registration, missing gpui feature
flag, missing file). `denied` = policy/user refusal. `invalid_args` = caller
error. `unknown` = no such service/op. Transport failures (no app, dead UI
thread) are the only napi `Err`s.

## Public API — `svelte-desktop/stores`

`src/native-api/stores.svelte.ts` is a rune module — `compileModule`'d into
`src/gen/native-api/stores.js` and exposed as **`svelte-desktop/stores`**
(tsconfig `paths` + the `#stores` package alias both resolve it). This is
the public surface: one specifier, one object per domain.

```ts
import { app, theme, window, secureStorage } from 'svelte-desktop/stores';

// {theme.dark ? '🌙' : '☀️'}            — reactive in markup
// {app.version}                         — reactive in markup
// secureStorage.setPassword(…)          — methods live on the same object
```

**No init call needed** — importing the module is enough. The moment
`initPlatform(renderer)` binds a backend, every namespace self-initializes
in parallel and its fields populate reactively. `initStores()` stays
exported as a manual refresh-all / test seam (concurrent calls share the
in-flight boot).

**The normalization rule**: each namespace object carries *both* — every
nullary value-getter is a `$state` field, and parameterized queries /
side-effecting actions are methods on the same object (`app.getPath`,
`window.setSize`, `theme.set`, `update.check`). `shell`, `dialog` and
`secureStorage` are re-exported verbatim — pure action namespaces, no
`$state` — and `secureStorage` is the deliberate exception: secrets never
enter reactive memory. Namespaces with real platform events expose a
typed `on(event, cb)` — autocomplete narrows the event names, the payload
is checked, and it returns an unsubscribe fn.

Every reactive namespace shares the shape: `ready` + `error` `$state`
fields and an `init()`. Namespaces that fail capture the error on
`ns.error` rather than poisoning the rest.

## Multi-window

`windows.create(opts)` opens a real second NSWindow on a fresh `GpuixView`
sharing the one retained element tree. The primary window is `windowId 0`;
secondary ids are monotonic `u32`s, never reused, allocated only after all
options validate (a rejected create burns no id). `label` is the JS lookup
key for `get(label)`/`emitTo` — unique per live window, duplicates reject
`invalid_args`.

Each window mounts its own gdom root: `createWindowRoot(windowId)` returns a
mount target whose subtree binds to that window via `['setRoot', id, w]`;
closing the window destroys the subtree through the normal
`closed → destroyWindowRoot` path (primary roots are tracked the same way).

`windowId` routing rules, everywhere:

- An **explicit** `windowId` targets that window — unknown → `unavailable`,
  fractional/negative/non-finite → `invalid_args`.
- **Absent** on a window op → the *key* window (where real input would
  land), falling back to the lowest live id.
- **App-scoped** ops (`windows.create`/`list`/`get`) ignore `windowId`
  entirely and work with zero windows open.
- **Element-scoped** napi ops (`focusElement`, `scrollTo`, bounds,
  `setWindowKeyEvents`) resolve the element's owning window through the
  tree — they act on the right view regardless of which is key.
- `simulate_*` (`simulateClick`, `simulateMouse*`, `simulateScrollWheel`,
  `simulateKeystrokes`, `simulateKeyDown`/`Up`) take an optional trailing
  `windowId` with the same semantics (default: key window).

Isolation: every window gets its own selection state, focus handles,
scroll/virtual-list mirrors, and automation bounds (all tagged by the
painting window id). The automation clock is app-global — `clockPause`
freezes every window at once. `windows.close` bypasses `close_veto`
deliberately (veto = "ask JS"; a JS close call *is* the decision); the
OS red button honors it and emits `willClose`. Closing the last window
exits the process (`LastWindowClosed`).

Events: `emitTo(windowId, event, payload)` + `onWindow(windowId, event, cb)`
scope the local bus by `data.windowId` (window `0` included); `created`/
`closed` fire through `onPlatform`.

Also exported: `initPlatform`, `onPlatform`, `onAnyPlatform`,
`emitTo`, `onWindow`, `platformReady`, `NativeApiError`, and all service
types. gdom exports `createWindowRoot(windowId)` / `destroyWindowRoot` /
`windowRoots` for the multi-window mount surface.

Honest limits:

- `boundsChanged` events emitted *during* a synchronous platform op (e.g.
  a programmatic `setPosition` inside `platformCall`) can be dropped — the
  gpui `on_moved` handler's re-entrant `handle.update` fails while the
  window borrow is held. Own writes refresh `live` anyway via `#syncLater`.
- `theme.preference` tracks what `set()` applied; the OS-level preference
  isn't readable.
- Clipboard has no OS change-event — `clipboard.text` is the last
  read/written value, refreshed via `refresh()`. Rich formats (`html`,
  `rtf`) live in `$state` via own writes/reads but `formats`/`has` only
  see gpui-modeled types (text/image/paths), not custom UTIs.
- `willClose` veto is pre-armed (`setCloseVeto`) rather than a per-close
  callback — the gpui should-close callback returns bool synchronously and
  can't await a JS round-trip.
- `menu.popup` and dialogs use real OS tracking loops — they block
  automation the same way modals do.
- `dialog` `filters` are wired (`PathPromptOptions.filters` in the gpui
  fork — union of extensions → `setAllowedFileTypes:`); per-filter UTI
  pickers aren't modeled (raw extensions only).
- `app.setActivationPolicy` may return `internal` on unbundled binaries —
  NSApplication refuses policy changes without a bundle.
- `system.checkPermission('notifications')`/`requestPermission` and
  `notifications.getPermissionStatus`/`requestPermission` return
  `unavailable` on unbundled binaries — `UNUserNotificationCenter` raises
  an uncatchable ObjC exception without a bundle identity, so the call is
  gated on `bundleIdentifier` presence.
- `capture.getSources`/`captureSource` return `unavailable` while the
  screen-recording TCC grant is denied — check
  `system.checkPermission('screenRecording')` first.
- `system.requestPermission('camera'|'microphone')` requires the matching
  `NS*UsageDescription` key in Info.plist — declare it at package time with
  `package-app.ts --usage camera="…"`. The key is read before the
  AVFoundation call because TCC aborts the process when it's missing; the
  op returns `unavailable` with the missing-key message instead.
- `system.requestPermission('fullDiskAccess')` is `unsupported` by design —
  macOS offers no programmatic request; `checkPermission` is a heuristic
  (readable TCC.db → `granted`, else `unknown`) and the request error
  points at `system.openSettings({pane:'privacy-fullDiskAccess'})`.
- `menu.update`/`get` find items by `representedObject` id or by
  spec-correlated position in `NSApp.mainMenu`/dock menu — items created
  through `role` with app-level action types (quit/hide/…) aren't
  id-addressable; `os_action` roles (copy/paste/…) are.
- `{icon}` on menu items applies to NSMenuItem-built menus (tray, popup);
  `setAppMenu`/`setDockMenu` go through `gpui::MenuItem` which has no image
  field — the icon is silently ignored there.
- `app.setLoginItem` returns `unavailable` on unbundled binaries
  (SMAppService needs a bundle id, macOS 13+).

## Events

`onPlatform(name, cb)` / `onAnyPlatform(cb)` subscribe on the bus; payloads
arrive in `EventPayload.data`. Names: `openUrls`, `reopened`, `systemWake`,
`thermalStateChanged`, `keyboardLayoutChanged`, `appearanceChanged`,
`notificationResponse`, `willQuit`, `willRestart`, `menuAction`,
`boundsChanged`, `willClose`, `displaysChanged`, `systemSleep`,
`screenLocked`, `screenUnlocked`, `trayClick`, `shortcutPressed`,
`shortcutReleased`, `secondInstance` (reserved, not yet emitted),
`platformResult` (internal — resolves pending calls). App-level callbacks are
registered once at `renderer.init` in both the embedded and threaded paths;
OS-level observers (workspace/distributed notifications, Carbon handler,
display reconfiguration) install at `register_app_callbacks`.

## Caveats

- Async ops need the executor pumped — `renderer.tick()` must keep running
  (the frame loop already does; the probe learned this the hard way).
- `deepLink.register` and notification delivery require a bundled `.app`.
- `capture.*` reports honest `unavailable` until gpui's screen-capture feature
  is enabled in the native crate's build.
- `setSize`/fullscreen apply on the next frame — reads are stale until then;
  fullscreen transitions are animated (~1s) so rapid toggle→read can lag.
- The pinned gpui checkout carries a local patch (to upstream into the
  `remorses/zed` fork): `PlatformWindow::set_position` +
  `Window::set_position`/`observe_window_bounds` (gpui platform.rs,
  window.rs; impl in `gpui_macos/src/window.rs`). Editing vendored checkouts
  needs `cargo clean -p gpui -p gpui_macos -p gpui_platform` — cargo doesn't
  track their mtimes.
- `window.set_position` must NOT hold `MacWindowState` across
  `setFrameTopLeftPoint` — `windowDidMove` fires synchronously and its
  delegate re-locks the same mutex (same-thread deadlock observed).
- Deploying the `.node` into `node_modules` must use copy-to-temp + `mv`
  (new inode): `cp` truncates in place and the kernel rejects the stale
  signature → `SIGKILL (Code Signature Invalid)` on load.
- No panics cross the napi boundary; the dispatcher returns error envelopes.
