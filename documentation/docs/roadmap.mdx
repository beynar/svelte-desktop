## The queue (dependency-ordered)

1. **Worker-exit segfault** — the one true blocker. Repro:
   `bun src/mission-qg-multiwin-main.ts` → PASS then host null-deref. Likely
   an FFI notifier callback outliving the worker. Cheapest probe: host-side
   `app.destroy()` before exit, or a dispatch guard after worker death.
2. **gpuix AX materialization** — consume `role`/`aria-*` custom props into
   `accessibilityElement` children. Transport is done; this is renderer work.
   Biggest product gap.
3. **Notifications/permissions bindings** — wrong kind strings today
   (`unsupported` / unknown-kind); binding fix, not just testing.
4. **Window-scoped services with a live window** — Appearance, parented
   dialogs, menu/tray — extend the `mission-qg-app` pattern.
5. ~~**Target-filtered event registration**~~ — DONE: one
   `setDelegatedEvents` op carries the delegated set; the renderer attaches
   listeners at build (`element.events ∪ delegated`). Focus/key stays
   focusable-scoped; `text` elements are exempt (never DOM targets).
6. ~~**Move semantics**~~ — DONE: `moveBefore` reparents natively without
   destroy/recreate (same-parent reorder, anchored insert, cross-parent).
7. ~~**Transition params**~~ — DONE for the transform emitters: native
   `transform`/`transform-origin` through a GPUI `element_transform_stack`
   (translate/scale/rotate/skew/matrix, `%` + keyword origins, nested
   composition, transformed hitboxes/masks/AABB bounds). `fly`/`scale`/
   `slide` verified end-to-end. `blur` still drops `filter`; `draw` needs
   `getTotalLength`.
8. **Cross-platform evidence** — linux-x64/win-x64 NAPI targets exist but are
   NOT_RUN; CI cross-build + manual checklist.
9. **Signing/notarization/updater** — needs credentials; spec'd only.

## The package that falls out of this

```
svelte-gpuix/
├── gdom.ts        fake DOM (as today)
├── bridge.ts      gpuix ops + event dispatch
├── render.ts      render(App, windowOpts) — mirrors @gpuix/react
├── remote.js      query / command / refreshAll
├── plugin.ts      bundler plugin (below)
└── deps: svelte (peer, version-pinned), @gpuix/native
```

Deliberately **not vendored**: Svelte itself. The whole trick depends on the
unmodified runtime traversing the fake tree — a fork would own unstable
internals while gaining nothing. `svelte` stays a version-pinned peer dep, and
the conformance suite is the insurance policy across minors.

## The bundler plugin — three jobs

<Steps>
  <Step title="Compile .svelte / .svelte.js">
    What `build.ts` does by hand today, as a real Vite/Bun plugin.
  </Step>
  <Step title="Alias svelte → client entry">
    Under Bun, `import 'svelte'` resolves the server entry. The plugin aliases
    it — replaces the `svelte-client.js` shim + post-compile rewrite.
  </Step>
  <Step title="Transform *.remote.ts">
    Rewrite SvelteKit-style remote imports to in-process calls (or stand up an
    embedded adapter-bun server and let real stubs hit loopback — the
    Electrobun experiment proved that path).
  </Step>
</Steps>

## Remaining surface area

- **DOM depth**: selection, clipboard, IME, focus management, portals,
  `document.activeElement`, observers on the live renderer's bounds source.
- **Styling**: scoped blocks + the nkit recipe system cover the authored-app
  case; arbitrary web CSS stays a non-goal ([renderer verdict](/renderer-verdict)).
- **Media elements** — play/pause/`TimeRanges` or a documented stub.
- **Live-renderer verification** — sync native reads inside event handlers
  (`getElementBounds`) need a live-mode deadlock probe.
